YooAsset Collector（资源收集器）完整详解

打开窗口：Window → YooAsset → AssetBundle Collector Collector（收集器）是YooAsset编辑器里最小配置单元，只存在编辑器阶段，运行时不存在。 它的职责：指定扫描哪个目录、筛选哪些资源、资源如何寻址、如何打成AssetBundle。 一个Group下可以有多个Collector；每个Collector代表一套独立扫描+过滤+打包规则。 层级回顾：Package → Group → Collector Package、Group、Collector都是编辑器配置；打包后全部转化为Manifest清单与物理AB文件。

Collector全部属性列表

属性说明
CollectPath收集路径，可以填文件夹路径，也可以填单个资源完整路径（Assets/xxx/xxx.prefab），必须以Assets开头
CollectorType收集器类型（3种，核心），决定资源是否写入Manifest清单，运行时能否直接LoadAsset加载
AddressRuleName寻址规则：生成运行时代码加载资源的key（逻辑地址），EnableAddressable开启后生效
PackRuleName打包规则：决定收集到的资源如何合并、拆分生成AssetBundle物理文件
FilterRuleName过滤规则：在CollectPath范围内再筛选文件类型，过滤掉不需要的资源
UserData自定义字符串，用于自定义PackRule/AddressRule/FilterRule，业务扩展用，内置规则不会读取此字段
AssetTags资源标签，分号分隔；用于打包时筛选拷贝到StreamingAssets首包、清单标签过滤等功能

1. CollectorType 收集器类型（最重要）

① MainAssetCollector【90%业务使用】

  • ✅资源写入Manifest资源清单

  • ✅运行时代码可以直接LoadAssetAsync<T>("逻辑地址")加载

  • ✅依赖分析正常生效，被引用的贴图材质会做共享包拆分

  • 适用：预制体、UI、场景、音频、Sprite图集，所有需要业务代码主动加载的资源。

    ② StaticAssetCollector

  • ❌不会写入Manifest，代码不能直接加载

  • ✅参与打包；无视共享依赖规则，不会被框架剥离为共享Bundle。

    无论多少主资源引用它，都会严格按照本Collector的PackRule打包，不会被拆分出去。

  • 适用场景：强制把一组贴图/材质固定打在同一个AB，不希望框架自动拆共享包。

    ③ DependAssetCollector

  • ❌不会写入Manifest，代码不能直接加载

  • ✅参与打包；没有任何主资源引用这些资源时，打包会自动剔除该资源，减小包体。

  • 适用场景：特效贴图、粒子纹理等只被别的资源间接依赖，业务不会直接加载的资源。可以做细粒度分包，修改一张纹理只更新小包。

    简单对比表

    类型写入清单可直接加载共享包机制特点
    MainAssetCollector✅✅正常生效业务主资源，绝大多数场景
    StaticAssetCollector❌❌关闭强制打包，不做共享剥离
    DependAssetCollector❌❌正常生效无引用自动剔除，用于依赖资源

2. AddressRuleName 寻址规则（逻辑加载地址）

需要Package设置勾选EnableAddressable才生效；寻址地址不能重复，大小写敏感。 内置规则：

  1. AddressByFileName（最常用） 只用文件名（不带后缀）作为逻辑地址。 Assets/Res/UI/Button.prefab → 寻址名：Button

    package.LoadAssetAsync<GameObject>("Button");

    注意：同Collector内不能有同名不同后缀资源，会冲突报错。

  2. AddressByGroupAndFileName Group名_文件名，避免跨Collector重名冲突。UI_Button

  3. AddressByFolderAndFileName 父目录_文件名，多级目录防重名。

  4. AddressByFullPath 使用完整Assets路径作为加载key：Assets/Res/UI/Button.prefab；不会重名，但写起来长。

    也可以实现IAddressRule接口写自定义寻址规则，UserData字段可传入自定义参数。

3. PackRuleName 打包规则：决定生成多少个AB物理文件

PackRule决定收集出来的主资源如何合并成AssetBundle；注意：共享依赖包是框架额外生成，不受PackRule控制。

PackRule行为适用场景
PackSeparately每个资源单独生成1个AB大独立资源、极少改动资源；更新粒度最小，但文件数量爆炸
PackDirectory每个子文件夹生成1个AB层级目录，每个子目录一个包
PackTopDirectory收集路径下第一层子文件夹各自生成1个AB；深层子目录归属于一级父目录AB项目最常用，按一级模块分包
PackCollector当前Collector全部资源合并成1个AB希望这一条收集器下所有资源进同一个bundle；改动任意文件，整个包都要热更下载
PackGroup整个Group下面所有Collector全部资源合并为同一个AB一个Group下可以有多条Collector，全部合并输出1个主AB；适合整体更新模块。
PackRawFile原生文本资源打包(json/csv/txt)，不做Unity资源解析配置表文本资源，必须搭配MainAssetCollector
⚠️PackGroup关键点：PackGroup作用域是整个Group，Group内所有Collector，不管多少条，全部合并为一个主AB。
注意：就算PackCollector/PackGroup打成1个主AB，开启EnableSharePackRule，仍然会额外产生若干共享依赖AB包。

4. FilterRuleName 过滤规则

在CollectPath扫描到一堆资源后，再按规则过滤，只保留符合条件的资源。 内置规则：

  • CollectAll：收集路径下全部资源（默认）

  • CollectPrefab：只收集prefab预制体

  • CollectScene：只收集unity场景文件

  • CollectSprite：只收集精灵资源

  • CollectShader：只收集shader

    可自定义实现IFilterRule接口做自定义过滤；UserData可以传参数给自定义规则。

    5. UserData

    纯自定义字符串，内置规则完全忽略。当你写自定义IPackRule / IAddressRule / IFilterRule时，可以读取这个字段做配置。 示例：填prefix:role，自定义规则解析字符串实现特殊分包逻辑。

    6. AssetTags 标签

    分号分隔，例如ui;common。 用途：

  1. 打包时，Copy Buildin File Option可以按标签拷贝资源到StreamingAssets作为首包内置资源；
  2. 清单里会记录标签，运行时可以查询资源标签。

Collector使用实操、最佳实践与坑点

典型配置示例

Package: GamePackage
└─ Group: UI
 ├─ Collector1
 CollectPath: Assets/Res/UI/Prefabs
 CollectorType: MainAssetCollector
 AddressRule: AddressByFileName
 PackRule: PackTopDirectory
 FilterRule: CollectPrefab
 AssetTags: ui
 └─ Collector2
 CollectPath: Assets/Res/UI/Atlas
 CollectorType: DependAssetCollector
 PackRule: PackSeparately
 FilterRule: CollectSprite
 AssetTags: ui

含义：UI预制体作为主资源；图集精灵作为依赖资源，每个图集单独AB，修改一个图集只更新对应小包。

重要避坑点

  1. 同一个资源不能被多条Collector收集，打包报“资源重复收集”。

  2. CollectPath必须以Assets/开头，不能填相对外部路径。

  3. PackGroup是Group级别规则：同一个Group下所有Collector都会合并，不管每条Collector自己的PackRule设置。

  4. MainAssetCollector才可以被代码直接加载；Static/Depend只能被依赖引用，直接Load会报找不到资源。

  5. AddressRule产生的寻址key不能重复，否则打包报错。

  6. PackCollector / PackGroup大包模式：包内任意一个资源改动，整个AB包都要重新下载，热更流量会变大，适合更新频率很低的模块。

    编辑器代码创建Collector示例

    using YooAsset.Editor;
//获取或创建Package
var package = AssetBundleCollectorSettingData.Setting.GetPackage("GamePackage");
var uiGroup = AssetBundleCollectorSettingData.CreateGroup(package, "UIGroup");
//新建Collector
var collector = new AssetBundleCollector();
collector.CollectPath = "Assets/Res/UI/Prefabs";
collector.CollectorType = ECollectorType.MainAssetCollector;
collector.AddressRuleName = nameof(AddressByFileName);
collector.PackRuleName = nameof(PackTopDirectory);
collector.FilterRuleName = nameof(CollectPrefab);
collector.AssetTags = "ui";
uiGroup.Collectors.Add(collector);
AssetBundleCollectorSettingData.SaveSetting();

    运行时视角

    Collector全部信息只存在编辑器配置文件；打包完成后Collector、Group信息全部丢弃，不会打进Manifest清单。 Manifest只记录：逻辑寻址地址、归属哪个AB包、MD5、依赖列表、标签。运行时YooAsset.GetPackage()完全不知道Collector、Group的存在。 如果你需要，我可以给一个自定义PackRule的最简示例代码，方便你理解UserData如何使用。
