YooAsset Package（逻辑资源包）与物理AB文件关系

Package是纯逻辑概念，它和AssetBundle文件没有固定一一对应关系。一个 Package（逻辑包）可以对应N个物理AssetBundle文件，数量完全由打包规则PackRule + 共享依赖拆分规则共同决定。

层级梳理：

Package(逻辑包，运行时代码拿到的对象)
├─ Group（分组）
│  ├─ Collector收集器（配置路径、PackRule分包规则）
│  │    → 根据PackRule生成若干个AssetBundle物理文件
└─【自动生成】共享依赖Bundle、Shader专用Bundle（不在Collector里配置）


1. PackRule 直接决定Collector产出多少AB文件


PackRule行为产出AB数量
PackSeparately每个资源文件单独1个AB收集多少主资源，就生成多少AB
PackDirectory每个子文件夹1个AB收集路径下子文件夹数量
PackTopDirectory收集路径下第一层文件夹各自一个AB一级子目录数量
PackCollector当前Collector全部资源合并为1个AB固定1个
PackGroup当前Group下所有Collector全部合并成1个AB固定1个

注意：以上只是主资源生成的AB数量，还会额外产生共享依赖Bundle，这部分是YooAsset自动生成，你在Collector界面看不到配置。



2. 额外自动生成的AB包（很关键，容易被忽略）

开启 EnableSharePackRule（默认开启，零冗余模式）时：

  • 如果一个贴图/材质被≥2个不同AB包引用，这个依赖资源会被剥离出来，生成独立的共享AssetBundle，避免多份拷贝冗余。
  • 开启自动收集Shader：所有shader会统一打入一个专门的Shader‑Bundle文件。

👉 所以：哪怕你把Group设置为PackGroup（全部主资源打为1个AB），最终Package下面也可能不止1个AB，还附带若干共享依赖Bundle、Shader Bundle。

举个直观例子

  • 1个Package，1个Group，PackGroup规则：所有主资源合并成1个主AB。
  • 但是里面10张贴图被多处预制体共用。
  • 打包结果：
    • 1个主资源AB（所有prefab场景）
    • N个自动生成的共享依赖AB（被多个地方引用的贴图材质）
    • 1个Shader Bundle

最终这个逻辑Package，实际对应物理磁盘上：1+N+1个.bundle文件。


3. 运行时视角

代码中你操作的是：


var package = YooAsset.GetPackage("DefaultPackage"); //逻辑包对象

package内部持有一份Manifest清单文件。清单记录了这个逻辑包管辖的全部AssetBundle列表、每个资源属于哪个AB、AB之间依赖关系、MD5、大小等信息。Manifest是逻辑包和物理AB文件的桥梁；多个物理AB全部归属同一个Package管理，统一更新、统一缓存。


4. 容易混淆概念总结

  1. Package：逻辑业务单元，可以独立更新，一个Package对应一份manifest清单，不限制底层AB数量。
  2. Group：编辑器配置分组，仅编辑器用，运行时不存在Group对象。
  3. Collector：定义哪些资源被收集，以及分包策略PackRule。
  4. AssetBundle：磁盘真实物理文件，一个Package下面可以几十/几百个AB文件。

❌错误理解：一个Package等于一个AssetBundle文件 ✅正确理解：一个Package = 一份Manifest + 一批属于此Package的物理AB文件集合。AB数量取决于你的PackRule，以及共享依赖拆分。


5. 如果想要一个Package对应尽量少的AB文件

  • 主资源使用 PackGroup / PackCollector；
  • 关闭 EnableSharePackRule，关闭零冗余模式，依赖资源跟随主包打进同一个AB（代价：会存在资源冗余，同一张贴图多份拷贝）。

补充：多Package

  • 多个Package，会生成多套完全隔离的Manifest，AB文件归属各自Package；Package之间资源不能互相引用。


YooAsset编辑器配置层级（仅编辑器存在，运行时没有Group、Collector对象）

Package（逻辑包裹）
├─ Group（分组，一个Package可以1个或多个Group）
│  ├─ Collector（收集器，**一个Group里面可以有若干个Collector**）
│  ├─ Collector
│  └─ Collector ……
└─ Group
   ├─ Collector
   └─ Collector ……

数据结构源码：AssetBundleCollectorPackage.Groups 是List；每个AssetBundleCollectorGroup内部持有List<AssetBundleCollector>收集器集合。


关键点

  1. 1个Package → 0/1/多个Group Package下可以新建很多Group，每个Group可以独立启用/禁用（ActiveRule），禁用后该Group下全部Collector都不参与打包。

  2. 1个Group → 0/1/多个Collector 一个Group下面可以创建多个收集器，每个Collector可以配置：不同的收集路径、不同PackRule分包规则、不同过滤规则、不同可寻址规则。

示例：同一个UI Group下：

  • Collector1：收集 Assets/Res/UI/Prefabs，PackRule=PackDirectory
  • Collector2：收集 Assets/Res/UI/Atlas，PackRule=PackCollector 同一个Group内多个Collector，配合PackGroup规则时：该Group下所有Collector收集到的全部主资源合并打成同一个AB。
  1. 运行时代码层面：
  • 只有YooAsset.GetPackage("xxx")得到Package对象；
  • 运行时完全没有Group、Collector的概念。Group/Collector只是编辑器用来描述“收集哪些资源、怎么分包”的配置数据；打包完成后全部编译进Manifest清单文件里。

容易混淆的对比

概念作用存在时机
Package独立热更单元，对应一份manifest清单编辑器 + 运行时
Group编辑器分组，批量开关一组收集器，配合PackGroup分包规则仅编辑器
Collector最小配置单元：收集路径、过滤、分包PackRule、寻址规则仅编辑器
AssetBundle磁盘真实物理文件，由Collector+PackRule+共享依赖生成打包输出产物

实操常见用法

  1. 按模块划分Group：UI、Role、Scene、Audio；每个Group下建多个Collector分别收集预制体、贴图、音效。
  2. 如果想整个模块合并成一个AB：Group设置PackGroup，Group下可以放任意数量Collector，全部合并输出同一个主AB。
  3. 想同一个Group内不同目录分开打多个AB：每个Collector各自用PackDirectory / PackTopDirectory。

重要提醒：同一个资源不能被多个Collector收集，打包会报资源重复收集异常。


举一个极简配置示例

Package: GamePackage
├─ Group: UI
│   ├─ Collector：Assets/Res/UI/Prefabs（PackDirectory）
│   └─ Collector：Assets/Res/UI/Atlas（PackCollector）
└─ Group: Role
    ├─ Collector：Assets/Res/Role/Model
    └─ Collector：Assets/Res/Role/Animation
