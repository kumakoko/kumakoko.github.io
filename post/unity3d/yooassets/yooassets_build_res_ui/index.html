YooAsset AssetBundleBuilder 构建界面选项详解（3.0.x官方文档）

打开路径：Window → YooAsset → AssetBundle Builder


1. Build Package（资源包裹）

  • 作用：下拉选择要构建的资源包裹(Package)，一个工程可以配置多个Package，相互完全独立。
  • 场景：项目多分包、多资源包隔离，只构建选中的包裹，不会影响其它包裹。 注意：打包前需要在AssetBundleCollector窗口配置好对应Package的收集规则。

2. Build Pipeline（构建管线）

决定打包执行逻辑，不同管线用途完全不同，管线种类如下表所示

管线详细说明使用场景
EditorSimulateBuildPipeline编辑器模拟构建，只生成资源清单，不生成真实AB包。模拟真实打包环境，跳过耗时的AB生成。开发调试，EditorSimulateMode模式，快速验证收集逻辑，不用真正打包。
LegacyBuildPipelineUnity传统内置打包管线，旧版本遗留。Unity2020及更早版本项目。
ScriptableBuildPipeline(SBP)Unity可编程构建管线，可自定义打包流程，打包速度、稳定性优于旧管线。Unity2021.3+强烈推荐生产环境使用
RawFileBuildPipeline原生文件管线，不经过UnityAB系统，直接复制原始文件。处理Unity不识别的文件：FMOD bank、自定义二进制文件等。
ArchiveFileBuildPipeline归档管线，把多个原始文件合并成单个归档文件。大量小原生文件，减少文件数量，方便管理加密。

3. Build Output（构建输出目录）

  • 作用：设置打包产物根目录。
  • 重要特性：工具会自动根据Unity编辑器当前选中的平台，在该目录下创建平台子目录（Android/iOS/StandaloneWindows等），不同平台产物互不干扰。
  • 产物目录结构示例：BuildOutput/Android/DefaultPackage/v1.0，里面存放AB包、清单、构建报告。

4. Build Version（构建版本）

  • 作用：本次资源包的版本号，补丁包文件夹名称就等于该版本。必须大于0，每次热更打包必须修改。
  • 运行时意义：客户端比对该版本号判断是否需要更新资源。

提示：版本号可以是数字字符串，例如1001、20260822。


5. Clear Build Cache（清理构建缓存）

  • 勾选：删除全部构建缓存，全量重新构建所有资源包，打包慢；修改打包规则、资源分组后建议勾选。
  • 不勾选：开启增量打包，对比上一次缓存，只重新打包发生变更的资源，打包速度大幅提升。

⚠️注意：修改收集规则、分组规则、管线参数时，增量缓存可能产生错误产物，需要勾选清理缓存。


6. Use Asset Depend DB（资源依赖数据库）

  • 开启：资源收集阶段读取缓存的依赖关系数据库，不用每次重新完整解析所有资源依赖，大幅提升收集阶段速度。
  • 关闭：每次打包完整扫描所有资源依赖，适合资源大量改动的调试阶段。

生产打包建议勾选，配合增量打包使用。


7. Bundle Encryptor（资源包加密器）

  • 作用：选择实现IBundleEncryptor接口的加密类，对输出的AssetBundle/Raw/Archive文件做加密处理。
  • 默认内置：YooAssetEditorEncryptionNone=不加密。
  • 自定义：自己写加密类，放到Editor目录，下拉框自动识别。

运行时必须配置对应的解密器，否则无法加载资源。


8. Manifest Encryptor（清单加密/压缩器）

  • 作用：针对PackageManifest资源清单文件做加密或者压缩。清单记录全部资源包信息、哈希、大小、依赖关系。
  • 打包阶段执行加密/压缩。

9. Manifest Decryptor（清单解密/解压器）

⚠️构建阶段填写，供运行时读取，打包本身不会执行解密。

  • 作用：告诉YooAsset，运行时使用哪个类来解密解压清单文件。必须和上面ManifestEncryptor配对。
  • 如果清单加密，运行时不配置对应解密器，游戏启动解析清单直接报错。

10. Compression（资源包压缩方式）

控制AssetBundle的压缩算法（RawFile管线不受该选项影响）

压缩方法特性和适用范围
Uncompressed不压缩，包体积大，加载最快
LZMA高压缩率，包体最小，解压慢；适合网络下载
LZ4压缩率中等，解压速度极快；移动端项目最常用推荐

11. File Name Style（输出资源包文件命名样式）

控制磁盘上Bundle文件的文件名，影响热更新哈希校验：

命名方式特性适用范围
HashName只用哈希值命名，abc123.bundle文件名称与bundle名字无关，修改资源内容哈希就变。
BundleName直接使用bundle分组名字不推荐，资源变更文件名称不变，CDN缓存会导致更新异常。
BundleName_HashNamebundle名_哈希.bundle兼顾可读性+哈希校验，生产项目最推荐。

12. Copy Bundled File Option（首包内置文件拷贝策略）

构建完成后，自动把部分/全部资源拷贝到StreamingAssets，作为安装包内置资源（首包资源）。

选项行为适用场景
None不拷贝任何文件；所有资源全部走热更新下载。纯热更新，首包不带任何资源。
ClearAndCopyAll清空StreamingAssets原有YooAsset目录，拷贝全部资源。完整内置首包，初次启动不用下载。
ClearAndCopyByTags清空旧文件，只拷贝带指定标签的资源。部分资源内置，剩余走热更新。
OnlyCopyAll不清空旧文件，直接拷贝全部；旧文件不会删除，容易残留垃圾。极少用
OnlyCopyByTags不清空旧文件，按标签拷贝，残留旧文件。极少用

重要：打包Unity安装包的时候，StreamingAssets内的文件会打进APK/IPA。


13. Click Build（构建按钮）

点击后执行完整构建流程：资源收集→依赖解析→生成Bundle→加密处理→生成清单→拷贝内置资源。

  • 任意步骤报错，构建终止，错误信息查看Unity Console控制台。
  • 构建成功后输出构建报告，可以查看资源大小、冗余、依赖统计。

生产环境常用配置参考

  1. 管线：ScriptableBuildPipeline（Unity2021.3+）
  2. Clear Build Cache：日常迭代不勾选；修改分组/打包规则时勾选
  3. Use Asset Depend DB：勾选
  4. Compression：LZ4
  5. File Name Style：BundleName_HashName
  6. Copy Bundled File Option：ClearAndCopyAll（需要内置首包）/None（全热更）


YooAsset AssetBundleBuilder 构建界面踩坑清单

聚焦构建面板各个选项引发的坑，区分现象、根因、解决方案，生产环境高频踩坑。


一、Clear Build Cache（清理构建缓存）相关坑

  1. 坑：不勾选清理缓存，修改收集规则/分组/PackRule之后，打包产物异常、资源缺失、依赖错乱
  • 现象：打包成功，但运行时报Bundle找不到、依赖丢失；新增/删除分组后旧产物残留。
  • 根因：增量缓存只检测资源文件变更，不检测收集器规则变更，规则改动不会自动触发全量重打。
  • 解决：修改收集规则、分组、打包规则、管线参数时，务必勾选Clear Build Cache做全量构建；日常迭代资源内容可以不勾选。

  1. 坑：每次都勾选清理缓存，打包速度极慢
  • 解决：区分场景，资源内容改动用增量；规则改动才全量。

二、Use Asset Depend DB（依赖数据库）坑

  1. 坑：开启依赖数据库，资源大量删除/移动后，依赖解析错误
  • 现象：打包警告依赖异常，运行时丢贴图、丢材质。
  • 根因：缓存的依赖数据库没有跟随资源大规模变更刷新。
  • 解决：大规模调整资源时关闭该选项，或者勾选清理构建缓存。

三、Build Pipeline（构建管线）高频坑

  1. 坑：EditorSimulateBuildPipeline用于真机打包
  • 现象：真机运行报找不到bundle文件。
  • 根因：模拟管线只生成清单，不输出真实AB包，只能用于编辑器调试，不能用于出包。
  • 解决：真机打包必须切换 SBP / Legacy / RawFile 等真实管线。
  1. 坑：SBP管线忘记安装SBP包，打包直接报错
  • 现象：构建报错，提示找不到UnityEditor.Build.Pipeline命名空间。
  • 解决：PackageManager安装Scriptable Build Pipeline包。
  1. 坑：RawFileBuildPipeline把多个文件打到同一个Bundle
  • 现象：构建报错bundle does not support multiple raw asset。
  • 根因：RawFile管线每个bundle仅允许一个原生文件，不能多个文件打包到同一个Raw包。
  • 解决：调整收集器PackRule，每个Raw包只放一个文件。
  1. 坑：一套Package混用普通AB资源和RawFile资源
  • 现象：构建或者运行时报错，资源加载API调用异常。
  • 根因：一个Package只能用一种管线；RawFile管线只能处理原生文件，不能处理Unity普通资源。
  • 解决：原生文件单独新建Package，使用RawFileBuildPipeline。

ArchiveFileBuildPipeline适合多个原生文件合并，不要和RawFile搞混。


四、Build Version（构建版本）坑

  1. 坑：热更打包版本号不修改，直接复用旧版本号
  • 现象：热更新逻辑不触发更新，客户端认为已经是最新版本。
  • 根因：版本号作为补丁文件夹名称，YooAsset靠版本号区分补丁包。
  • 解决：每一次热更打包，BuildVersion必须修改。

  1. 坑：版本号使用中文、特殊符号
  • 现象：部分Windows/Android平台文件系统异常，文件创建失败。
  • 解决：版本号只用数字、英文。

五、Copy Bundled File Option（拷贝内置资源）坑

  1. 坑：使用OnlyCopyAll / OnlyCopyByTags，不清空旧文件
  • 现象：StreamingAssets里面残留旧版本bundle和清单；旧清单和新清单混杂，Offline模式加载错乱，报找不到manifest文件。
  • 根因：Only开头选项不会删除原有文件，只会追加拷贝，旧垃圾文件不会清理。
  • 解决：需要内置首包优先选ClearAndCopyAll / ClearAndCopyByTags；Only系列仅特殊场景使用。
  1. 坑：构建完之后手动修改StreamingAssets目录，再打Unity安装包
  • 现象：APK/IPA内置资源和打包面板输出不一致。
  • 根因：YooAsset构建的拷贝逻辑，只在点击Build按钮执行；手动修改后再次Unity Build会被覆盖。
  • 解决：先YooAsset构建，再执行Unity Build；不要手动修改StreamingAssets/yoo目录。
  1. 坑：Copy选项选None，但是运行时配置OfflinePlayMode
  • 现象：直接报错找不到版本文件、清单文件。
  • 根因：Offline模式完全依赖StreamingAssets内置资源，None模式不会拷贝任何资源进去。
  • 解决：Offline模式必须配置拷贝策略；Host模式才可以None。

六、加密相关（BundleEncryptor / ManifestEncryptor / ManifestDecryptor）

  1. 坑：构建配置了加密器，运行时忘记注册对应解密器
  • 现象：热更下载成功，加载bundle报解压失败、解密失败；清单解析直接报错闪退。
  • 根因：ManifestDecryptor只是构建阶段记录类型名字，打包不会执行解密；运行时必须手动注册解密实例。
  • 解决：
    • BundleEncryptor → 运行时注册IBundleDecryptor
    • ManifestEncryptor → 运行时注册IManifestDecryptor
    • 不加密全部留空，不要乱填。
  1. 坑：ManifestEncryptor和ManifestDecryptor配对错误
  • 现象：清单文件解析失败。
  • 解决：加密和解密类必须一一对应。

⚠️WebGL旧版本对加密支持有限，容易解压失败。


七、FileNameStyle（文件名样式）坑

  1. 坑：热更新项目选用 BundleName（不带哈希）
  • 现象：资源更新后CDN缓存旧文件，客户端依然加载旧资源，资源不生效。
  • 根因：文件名称不变，CDN长缓存不会刷新；YooAsset内部哈希校验虽然检测出文件不对，但CDN返回旧数据会导致异常。
  • 解决：热更新项目禁止使用BundleName；优先BundleName_HashName，其次HashName。

八、Compression（压缩方式）坑

  1. 坑：移动端大量使用LZMA
  • 现象：下载很快，但游戏内加载卡顿，CPU解压耗时高。
  • 根因：LZMA压缩率高，但解压开销大；移动端不适合。
  • 解决：移动端优先 LZ4；LZMA适合仅下载几乎不加载的资源。
  1. 坑：RawFile管线下修改Compression参数
  • 现象：配置了LZ4/LZMA，但原生文件完全没有被压缩。
  • 根因：Compression只对AssetBundle生效；RawFile管线直接复制原始文件，压缩参数无效。

九、Build Output（输出目录）坑

  1. 坑：切换Unity平台之后忘记重新打包
  • 现象：Android打包，读取Windows平台的bundle，运行全部加载失败。
  • 根因：YooAsset会在BuildOutput下自动创建平台子目录，不同平台产物隔离。切换平台后，必须重新构建资源包。
  1. 坑：构建输出路径设置到StreamingAssets根目录
  • 现象：目录嵌套混乱，拷贝内置资源逻辑异常。
  • 解决：BuildOutput设置到项目外目录，不要直接指向StreamingAssets；由Copy Bundled File Option自动拷贝到StreamingAssets。

十、其它高频隐性坑

  1. 坑：Build Package选错，打包A包，运行时初始化B包
  • 现象：运行时报Package不存在，清单找不到。
  • 根因：Package名字打包和运行时初始化必须完全一致，大小写敏感。
  1. 坑：构建成功，但输出目录为空（The pack asset info is empty）
  • 排查：检查AssetBundleCollector收集器规则，是否没有收集到任何资源，路径是否写错，资源是否被删除。

✅ 生产打包前自检清单（快速核对）

  • 确认BuildPackage是目标包裹
  • 确认BuildPipeline和平台匹配，真机不用EditorSimulate
  • 修改收集规则后勾选Clear Build Cache；普通迭代不勾选
  • BuildVersion每次热更必须变更
  • FileNameStyle：热更项目用BundleName_HashName，禁止BundleName
  • Compression移动端选LZ4
  • Copy策略优先ClearAndCopyXXX，避免OnlyXXX
  • 如果开启加密，确认运行时已经注册对应解密器
  • Unity编辑器平台和目标发布平台一致，打完YooAsset包再打Unity安装包
