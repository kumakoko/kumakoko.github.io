Shift + 点击添加道路标记不起作用，反而选中了地形

免费版发生这种情况时，是因为免费版不支持场景中的多个地形瓦片。在这种情况下，在当前未被 Terrain.activeTerrain 引用的地形上添加标记会失败。

Shift + 点击不起作用也可能发生在较新的 Unity 版本中，通常是自定义的 Unity 编辑器布局导致 OnSceneView() 不再捕获键盘或鼠标按钮事件，而是选中了被点击的对象（此处为地形）。

一个已知的原因是"Gizmos"选项卡（场景视图窗口右上方）未启用。无论如何，启用 Gizmos 是显示各种道路网络相关手柄所必需的，默认 Unity 设置中是启用的。

验证 Unity 编辑器状态的一种方法是复制项目，并通过主菜单 > Window > Layouts 将 Unity 编辑器布局重置为预设之一，之后可以再次自定义到偏好的布局。如果问题复现，请联系我们。我们已与 Unity QA 团队讨论过此事，他们见过这种情况，很希望了解如何复现此问题。

导入演示包后没有道路类型和侧边对象

演示包本身没有将道路类型和侧边对象数据存储在项目文件夹中。原因是稍后导入包更新时会覆盖这些数据，包括可能已更改的道路类型、侧边对象和新添加的道路类型、侧边对象。

要使道路类型和侧边对象在其他场景中可用，请打开演示场景，在层级中选择道路网络对象然后取消选择。此时项目道路类型、侧边对象数据将更新。道路类型和侧边对象现在将在其他场景中可用。

从 v3.1.9f0 开始，应该会有通知提示有新的道路类型和侧边对象预设可用，并提供将这些预设导入项目的选项。之后这些预设将在"常规设置 > 道路类型 > Add Project Road Types"和"侧边对象管理器 > Add Project Side Objects"中可用。

环岛未正确实例化和连接到道路的首/末标记

目前避免将环岛直接实例化到所选道路的第一个或最后一个标记。改用另一种方式在场景中实例化交叉口：选择交叉口预制体选项卡 。从可用交叉口预制体列表中选择环岛，按住 SHIFT 键并在场景中点击要放置环岛的位置。现在可以将道路连接到预制体，或通过拖动红色环岛连接手柄开始新道路。[完整信息见交叉口章节]。

更改半径、分辨率或添加/更改连接后环岛几何不更新

在创建/添加环岛连接之前，建议先正确设置半径和分辨率。可能的连接数量取决于分辨率、半径和连接宽度。当连接已存在时更改半径或分辨率，可能导致连接无法重建。发生时控制台会显示警告信息。可以尝试从连接 1 开始重新定位连接，仔细检查白色中间手柄和外侧绿色手柄的位置。当连接无法创建时（因为太靠近环岛起点或终点（固定位置的白色外侧手柄），或与另一个连接重叠），绿色手柄会变红。但最简单的解决方法是先移除所有连接，然后重新开始添加新连接，环岛几何将重建。

这将进一步优化。目前建议通过先正确设置半径和分辨率来避免这种情况。在这种情况下，只有当当前所选连接与另一个连接重叠时环岛几何才不重建。可以通过位置滑块更改其位置或更改连接宽度来修复。

激活/停用连接预制体上的人行道后，已连接道路的人行道不更新

当道路两端都连接到连接预制体时会发生。此问题将修复。目前请检查相应道路一侧的另一个连接人行道设置，确保它们匹配。

地形边界外的道路标记无法选择

当标记因某种原因位于地形边界外时，可以通过沿道路网格小心地向标记移动来选择它。

道路无法附加到交叉口连接，道路几何与交叉口连接几何匹配但中心连接手柄显示为红色

当人行道激活但外侧人行道手柄被禁用（意味着附加道路的人行道将不激活）时会发生。[选择特定交叉口]，确保该侧道路包含人行道时外侧拐角手柄为绿色（激活）。

当道路几何结构与自定义交叉口连接不匹配时，自定义交叉口也会发生这种情况。

地形穿透道路，或道路悬浮在地形上方 / z-fighting

可能由多种情况引起：

  1. Unity 地形高度限制：Unity 地形对象以 0 到 1 之间的小数存储高度值，意味着无法应用负高度值。道路对象必须在地形游戏对象 Y 位置或以上。同时考虑样条形状的特性：将两个标记（A 和 B）正好放在地形对象 Y 位置，第三个标记（C）升高一点时，A 和 B 之间的道路形状（样条曲线）会略微低于地形对象 Y 位置，地形在此区域会渲染在道路上方，因为它无法被推得更低。这些区域用红点高亮，表示道路在此区域可能需要注意。当道路位于地形 y=0 时，也应避免 Random Tilting & Bumpiness 值低于 0。

    解决方法：将道路标记稍微向上移动，或先将地形对象在更高水平平整后再雕刻：选择地形对象 > Terrain Tools > Set Height > 设置值 > 按"Flatten Tile"或"Flatten All"。这样始终有向下调整地形的空间。

  2. 地形网格分辨率：Unity 地形对象基于网格，无法向此网格添加地形细节点。因此 heightmapscale 越大（地形尺寸与高度图分辨率之比），道路形状在带有高度差的急转弯方面越不灵活。必须有足够的地形点来适应道路形状在该区域的变化。这在带有显著高度变化的急弯中会明显可见。可能同一个地形点既用于适应位置 A 的道路高度，又用于适应位置 B 的道路高度，结果地形形状不准确。将场景视图着色模式切换为 Shaded Wireframe 并放大时，地形网格（地形点）清晰可见。道路形状内和周围的地形点密度越低，地形调整到道路形状的精度越低。

    相关地，当使用不应更新到道路网络的较低分辨率地形对象时，可以忽略这些地形对象——它们在计算所需最小缩进值时不被包含。选择地形对象，在 Inspector 中找到"ER Terrain"组件，激活"Exclude this terrain object"。之后所需的最小缩进值（常规设置 > 场景设置 > 地形控制中的"Default Indent"）将更低，从而使地形更新更精确。

  3. 道路间距过近：道路或路段彼此过近时也会发生同样情况。两条道路之间必须至少有两个地形点，一个平整到道路 A，另一个平整到道路 B。当同一点用于两条道路时，地形很可能要么从较低道路中弹出，要么较高道路在该位置悬浮在地形上方。

  4. 缩进对齐设置：请检查道路标记部分中 Left 和 Right Indent Alignment 下拉菜单的状态。默认值为"Align with the road"。其他选项之一会导致道路和地形之间出现或大或小的间隙。这些选项的目的是在涉及道路边缘附近的墙或地形网格覆盖层时，提供对地形变形的额外控制。侧边对象管理器中标记为 Terrain Surface Object 的侧边对象会自动影响此设置——假设该侧边对象形状将覆盖该区域以获得更多地形细节，它会保持地形本身更接近原始高度。

  5. 自定义变形设置与倾斜：使用自定义地形变形设置、道路倾斜和该区域合理的道路高度差时，地形更可能穿透道路。这将进一步优化。目前尝试降低道路倾斜和/或高度差。

  6. Layer 31：EasyRoads3D 使用 Layer 31，您在此图层上有其他对象吗？

  7. Z-fighting：道路铺设在地形上方。确保在构建模式下的 Inspector 中设置"Raise"值，特别是使用没有 z-fighting Offset 选项的着色器时。

  8. 地形高度值精度：高度值以 0..1 之间的浮点数存储，最终高度乘以地形高度值计算得出。高度值 600（默认地形高度）比高度 8000 的地形产生更平滑的地形。4000 以上的高值可能导致小的高度误差，需要更高的 Raise 级别使道路在地形上方。

  9. “Draw Instanced”：地形设置中的"Draw Instanced"默认禁用。启用此项可能影响地形形状，使其不再精确跟随道路。Unity 编辑器中看起来一切正常，但最终构建中可能看到误差。

  10. 缩进区域重叠：每个道路对象在侧向上影响地形的距离取决于地形规格、高度图分辨率和地形尺寸。此距离由缩进值定义。缩进区域可在常规设置 > 场景设置中可视化。其他道路对象的缩进和环绕区域不应在此区域内，否则无法为两条道路准确更新地形。

如果以上都不适用于您的情况，请联系我们。

道路网络无法移动或旋转

道路网络对象的 transform 确实被锁定了。原因是：想象在平坦区域工作时不小心移动了道路网络，之后才发现。几乎不可能将现有道路网络与地形精确匹配，尤其是在丘陵地形中。

但道路网络对象是可以移动的。方法是：选择主道路网络对象下的两个子对象"Connection Objects"和"Road Objects"，将这两个对象移动到新位置。Inspector 中将显示这些更改的通知，按"Apply Transform Changes"确认更改，道路网络对象将相应更新。

更改地形高度图分辨率后地形不能准确恢复到原始地形

对地形对象设置的更改（如高度图分辨率或细节贴图大小更改）应在道路网络处于编辑模式时进行。如果在地形已调整到道路网络时进行这些更改，最初存储的地形单元索引位置将不再对应地形上的相同位置，地形将无法准确恢复到原始地形。

某些道路对象不影响地形高度图

当"道路设置 > 对象设置"中的"Terrain Deformation"未激活时会发生。地形变形状态可以按道路类型设置，对于特定道路类型（如立交桥），地形不应更新。相同设置也可按标记段设置，例如用于按道路标记段手动激活的桥梁侧边对象段。

道路边缘高亮但道路本身透明

使用支持透明度的道路着色器时会发生。可以为道路标记分配顶点颜色，这在用户端可用于各种目的。工具本身使用顶点颜色实现泥土路起点和终点的混合功能，这使用顶点颜色的 alpha 通道。当所有标记上的顶点颜色 alpha 通道为 0 时，道路对象将完全透明。

键盘快捷键不起作用

对于 Shift + R（移除所选标记）等操作，请确保场景视图窗口具有焦点。

道路标记手柄和其他手柄不可见

场景视图窗口右上方的 Gizmos 选项卡必须激活。

道路与自定义连接预制体连接点之间的法线不平滑

这很可能是由于连接两端的道路几何结构不同。虽然道路连接良好，但两个连接之间可能存在法线组差异，因此无法正确平滑法线。

可以在建模应用程序中复查平滑组。另一个原因是在模型的导入设置中使用"Calculate"。可以在点击"Apply"后检查特定网格资源的顶点数来验证——Unity 将根据所选平滑角度重建网格，导致不同的顶点数。检查法线组的另一种方法是在自定义预制体编辑器窗口中打开自定义预制体，从下拉菜单选择特定连接，统计窗口中将列出法线组数量。要获得确切的法线组信息，可以打开 UV 编辑器窗口并逐个选择每个节点。当"Hard Edge"复选框开启时，新的法线组将从该节点开始。这一切都取决于源网格的几何结构。

缩进值不能设置低于某个值

最小缩进值基于地形的 heightmapscale（尺寸与高度图分辨率之比）。这是为了根据道路形状确保最佳地形变形所必需的，因为 Unity 地形对象不接受在特定区域添加额外细节点。使用更低值时，地形会穿透道路或道路悬浮在地形上方。heightmapscale 越大，最小缩进值越高。

每个标记的默认值与常规设置 > 场景设置中全局存储的最小缩进值匹配。因此如果项目中的最小缩进值很高，可能是因为您的地形设置。

新标记不吸附到地形

这在相机缩放距离点击点超过 5000 单位时可能发生。不太可能发生，但如果发生会导致标记悬浮在地形上方远处。这种情况下请向地形再放大一点。

Inspector 工具栏不显示

这很可能是因为 Inspector 处于调试模式。点击 Inspector 右上角的下拉箭头（锁图标旁边），确保选中"Normal"。此外，有用户报告使用两个 Inspector 面板（其中一个在调试模式）会影响场景视图功能。如果遇到类似行为，请避免这样做，仅使用一个 Inspector 面板，这也是 Unity 默认设置。

Unity 编辑器在道路更改后无响应或缓慢

这可能是因为 Unity Lighting 窗口中选择了"Auto"。光照会在后台持续重新计算，在较慢的计算机上可能导致延迟。在处理道路网络时暂时关闭"Auto"即可解决。

Unity 编辑器变慢也可能在没有交叉口的超长路段上明显。请尝试间隔插入 I 连接器，这对运行时性能也更好。

构建地形进度条不更新

Unity 进度条只能通过编辑器脚本使用和更新。由于构建功能也为脚本 API 所需，此代码目前不在编辑器脚本中运行，因此进度条仅按地形更新，不显示已处理道路的进度。这将改进，在此期间请耐心等待，后台正在处理。

双面侧边对象显示翻转

“Combine"选项开启时发生。目前请避免使用。

隧道地形洞问题

为隧道在地形中挖洞因各种原因很复杂，特别是所有可能的地形规格（特别是高度图分辨率相关）。一个已知问题是桥梁到隧道段之间的过渡，特别是在较低高度图分辨率下。这可能导致错误的地形单元被移除，以及在道路高度附近的起点处仍可见地形单元。

在地形中挖洞处于预览状态，欢迎反馈。

自定义连接模型在运行时生成的道路网络中不可见

当用于自定义连接的原始模型在导入设置中未启用"Read/Write Enabled"时发生。在运行时（而非 Unity 编辑器中）构建道路网络时，请确保在创建自定义连接预制体之前启用此项。

所选标记的变换 Gizmo 难以控制

变换 Gizmo 有两种对齐选项：水平和沿道路方向。水平是常用的，沿道路方向在丘陵地区很有用。W 键在两者间切换。

特别是当道路标记靠近其他有相当高度差的标记时，由于 Gizmo 尝试与道路方向对齐，标记可能较难控制。这种情况下可按 W 键切换到水平对齐。

更改地形高度图分辨率

请在道路网络处于编辑模式时更改地形高度图分辨率。在构建模式下进行此操作时，存储的原始地形数据将不再匹配相应区域，之后切换回编辑模式会产生意外结果。

WebGL 构建中道路材质呈粉色

当前 Unity WebGL 构建不支持 Shader Model 4.5，导致材质呈粉色。解决方法：打开使用的着色器，搜索 #pragma target 4.5 并替换为 #pragma target 3.5。

着色器位于 /Assets/EasyRoads3D/Shaders/。

包导入后的错误/警告

Timeout while updating assemblies: Assets/EasyRoads3D/Editor/EasyRoads3Dv3Editor.dll … Assets/EasyRoads3D/lib/EasyRoads3Dv3.dll … Assets/EasyRoads3D/lib/DelaunayER.dll …

这可能发生，与包导入相关，通常无害。要检查包是否导入成功，请打开演示场景，在层级中选择道路网络对象。Inspector 中是否可见 EasyRoads3D 工具栏？道路网络是否响应？如果不是，请重启 Unity。包应该已正确导入，如果仍出现此错误请联系我们。
