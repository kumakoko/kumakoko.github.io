在某些情况下，不同图形 API 之间的图形渲染行为存在差异。大多数情况下，Unity 编辑器会隐藏这些差异，但在某些情况下，编辑器无法为您隐藏这些差异。下面列出了这些情况以及发生这些情况时您需要采取的措施。

1. Render Texture coordinates

垂直方向（V坐标）上的纹理坐标约定，在类 Direct3D 和类 OpenGL这两种类型的平台之间有所不同：

API V坐标朝向 适用平台
Direct3D 坐标从顶部开始为 0，向下增加 Direct3D、Metal
OpenGL 坐标从底部为 0，向上增加 OpenGL、OpenGL ES

除非将场景内容渲染到Render Texture，否则这种差异一般不会有什么影响产生任何影响。

因为对上层逻辑而言，Unity统一使用类OpenGL的render texture纹理坐标，故而在 Direct3D 类平台上渲染内容到render texture时，Unity会在内部将渲染颠倒过来。

Image Effects

当您使用后处理效果时和抗锯齿时，图像效果的源纹理不会翻转以匹配类似 OpenGL 的平台约定。在这种情况下，Unity 会渲染到屏幕上以获得抗锯齿，然后将渲染解析为渲染纹理，以便使用图像效果进行进一步处理。

如果您的图像效果是一次处理一个渲染纹理的简单效果，则Graphics.Blit会处理不一致的坐标。但是，如果您在图像效果中同时处理多个渲染纹理，则在 Direct3D 类平台中以及使用抗锯齿时，渲染纹理可能会以不同的垂直方向出现。要标准化坐标，您需要手动将屏幕纹理“翻转”到您的顶点着色器 使其符合类似OpenGL的坐标标准。

以下代码示例演示了如何执行此操作：

// Flip sampling of the Texture: 
// The main Texture
// texel size will have negative Y).
#if UNITY_UV_STARTS_AT_TOP
if (_MainTex_TexelSize.y < 0)
	uv.y = 1-uv.y;
#endif

GrabPass也会出现类似的情况。在 Direct3D 类（非 OpenGL 类）平台上，生成的渲染纹理可能实际上不会被颠倒。如果您的 Shader 代码对 GrabPass 纹理进行采样，请使用UnityCG 包含ComputeGrabScreenPos文件中的函数。

Rendering in UV space

纹理坐标 (UV) 空间中渲染特殊效果或工具时，您可能需要调整着色器，以使 Direct3D 类系统和 OpenGL 类系统之间的渲染保持一致。您可能还需要调整渲染到屏幕和渲染到纹理之间的渲染。通过将 Direct3D 类投影上下翻转以使其坐标与 OpenGL 类投影坐标相匹配来调整这些。

内置变量包含ProjectionParams.x一个+1或–1值。-1表示投影已被上下翻转以匹配类似 OpenGL 的投影坐标，而+1表示投影尚未翻转。您可以在着色器中检查此值，然后执行不同的操作。下面的示例检查投影是否已翻转，如果是，则翻转并返回 UV 坐标以进行匹配。

float4 vert(float2 uv : TEXCOORD0) : SV_POSITION
{
    float4 pos;
    pos.xy = uv;
    // This example is rendering with upside-down flipped projection,
    // so flip the vertical UV coordinate too
    if (_ProjectionParams.x < 0)
        pos.y = 1 - pos.y;
    pos.z = 0;
    pos.w = 1;
    return pos;
}

Clip space coordinates

与纹理坐标类似，剪辑空间坐标（也称为后投影空间坐标）在 Direct3D 类平台和 OpenGL 类平台之间有所不同：

Direct3D 类：剪辑空间深度从近平面的 +1.0 到远平面的 0.0。这适用于 Direct3D、Metal 和控制台。

类似 OpenGL：裁剪空间深度从近平面的 -1.0 到远平面的 +1.0。这适用于 OpenGL 和 OpenGL ES。

在Shader代码中，可以使用UNITY_NEAR_CLIP_VALUE 内置宏根据平台获取近平面值。

在脚本代码中，如果平台需要，则使用GL.GetGPUProjectionMatrix将 Unity 的坐标系（遵循类似 OpenGL 的约定）转换为类似 Direct3D 的坐标。

Precision of Shader computations

为避免精度问题，请确保在目标平台上测试着色器。移动设备和 PC 中的 GPU 在处理浮点类型方面有所不同。PC GPU 将所有浮点类型（浮点、半精度和固定）视为相同 - 它们使用完整的 32 位精度进行所有计算，而许多移动设备 GPU 不这样做。

有关详细信息，请参阅数据类型和精度的文档。

Const declarations in Shaders

constMicrosoft HSL（参见msdn.microsoft.com）和 OpenGL 的 GLSL（参见Wikipedia ）着色器语言的使用有所不同。

微软的 HLSLconst与 C# 和 C++ 中的含义大致相同，即声明的变量在其范围内是只读的，但可以以任何方式初始化。

OpenGL 的 GLSLconst意味着变量实际上是一个编译时常数，因此必须使用编译时约束（文字值或其他计算const）进行初始化。

最好遵循 OpenGL 的 GLSL 语义，并且只在变量const真正不变时声明为。避免const使用其他方式初始化变量可变的 值（例如，作为函数中的局部变量）。这在 Microsoft 的 HLSL 中也有效，因此const以这种方式使用可以避免在某些平台上出现令人困惑的错误。

Semantics used by Shaders

为了使着色器在所有平台上都能正常工作，一些着色器值应该使用以下语义：

顶点着色器输出（剪辑空间）位置：SV_POSITION。有时着色器使用 POSITION 语义来使着色器在所有平台上工作。请注意，这在 Sony PS4 或曲面细分上不起作用。

片段着色器输出颜色：SV_Target。有时着色器使用COLOR或COLOR0使着色器在所有平台上都能正常工作。请注意，这在 Sony PS4 上不起作用。

将网格渲染为点时，PSIZE从顶点着色器输出语义（例如，将其设置为 1）。某些平台（例如 OpenGL ES 或 Metal）在未从着色器写入点大小时将其视为“未定义”。

有关更多详细信息，请参阅Shader 语义的文档。

Direct3D Shader compiler syntax

Direct3D 平台使用 Microsoft 的HLSL Shader 编译器。HLSL 编译器对各种细微的 Shader 错误的处理比其他编译器更严格。例如，它不接受未正确初始化的函数输出值。

使用此功能时可能遇到的最常见情况是：

一个表面着色器 具有参数的顶点修改器out。像这样初始化输出：

void vert (inout appdata_full v, out Input o) 
{
      **UNITY_INITIALIZE_OUTPUT(Input,o);**
      // ...
}

在顶点着色器中使用tex2D。这是无效的，因为顶点着色器中不存在 UV 导数。您需要改为采样显式 mip 级别；例如，使用tex2Dlod( tex, float4(uv,0,0))。您还需要#pragma target 3.0按tex2Dlod原样添加 Shader model 3.0 功能。

DirectX 11 (DX11) HLSL syntax in Shaders

表面着色器编译管道的某些部分不理解 DirectX 11 特定的 HLSL（微软的着色器语言）语法。

如果您使用 HLSL 功能（如StructuredBuffers）RWTextures和其他非 DirectX 9 语法，请将它们包装在仅限 DirectX X11 的预处理器宏中，如下例所示。

#ifdef SHADER_API_D3D11
// DirectX11-specific code, for example
StructuredBuffer<float4> myColors;
RWTexture2D<float4> myRandomWriteTexture;
#endif

Using Shader framebuffer fetch

一些 GPU（最著名的是 iOS 上基于 PowerVR 的 GPU）允许您通过将当前片段颜色作为片段着色器的输入来实现某种形式的可编程混合（请参阅EXT_shader_framebuffer_fetchkhronos.org ）。

可以在 Unity 中编写使用帧缓冲区提取功能的着色器。为此，在 HLSL（Microsoft 的着色语言 - 请参阅msdn.microsoft.com）或 Cg（Nvidia 的着色语言 - 请参阅nvidia.co.ukinout ）中编写片段着色器时使用颜色参数。

下面的例子是 Cg 中的。

CGPROGRAM
// only compile Shader for platforms that can potentially
// do it (currently gles,gles3,metal)
#pragma only_renderers framebufferfetch

void frag (v2f i, inout half4 ocol : SV_Target)
{
    // ocol can be read (current framebuffer color)
    // and written into (will change color to that one)
    // ...
}   
ENDCG

The Depth (Z) direction in Shaders

深度（Z）方向在不同的Shader平台上有所不同。

DirectX 11、DirectX 12、PS4、Xbox One、Metal：反转方向

深度（Z）缓冲区在近平面为 1.0，在远平面减小到 0.0。

剪辑空间范围是 [near,0]（表示在近平面处的近平面距离，在远平面处减小到 0.0）。

其他平台：传统方向

深度（Z）缓冲区值在近平面为 0.0，在远平面为 1.0。

剪辑空间取决于具体平台： 在类似 Direct3D 的平台上，范围是 [0,far]（表示近平面处为 0.0，在远平面处增加到远平面距离）。 在类似 OpenGL 的平台上，范围是 [-near,far]（意味着在近平面处减去近平面距离，在远平面处增加到远平面距离）。 注意反转方向深度（Z），结合浮点深度缓冲区 ，相对于传统方向，深度缓冲精度显著提升。这样做的好处是 Z 坐标冲突更少，阴影效果更好，尤其是在使用小近平面和大远平面时。

因此，当您使用深度（Z）反转的平台的着色器时：

UNITY_REVERSED_Z 已定义。 _CameraDepthTexture 纹理范围是 1（近）至 0（远）。 剪辑空间范围在“近”（近）到0（远）之间。 但是，以下宏和函数会自动计算深度（Z）方向的任何差异：

Linear01Depth(float z) LinearEyeDepth(float z) UNITY_CALC_FOG_FACTOR（坐标）

Fetching the depth Buffer

如果您手动获取深度（Z）缓冲区值，则可能需要检查缓冲区方向。以下是此示例：

float z = tex2D(_CameraDepthTexture, uv);
#if defined(UNITY_REVERSED_Z)
    z = 1.0f - z;
#endif

Using clip space

如果您手动使用剪辑空间（Z）深度，您可能还需要使用以下宏来抽象平台差异：

float clipSpaceRange01 = UNITY_Z_0_FAR_FROM_CLIPSPACE(rawClipSpace);

注意：此宏不会改变 OpenGL 或 OpenGL ES 平台上的剪辑空间，因此它在这些平台上返回“-near”1（近）到 far（远）的范围。

Projection matrices

如果您所在的平台深度 (Z) 反转， GL.GetGPUProjectionMatrix()将返回 z 反转矩阵。但是，如果您手动从投影矩阵组合（例如，用于自定义阴影或深度渲染），则需要通过脚本自行反转深度 (Z) 方向。

下面是一个示例：

var shadowProjection = Matrix4x4.Ortho(...); //shadow camera projection matrix
var shadowViewMat = ...     //shadow camera view matrix
var shadowSpaceMatrix = ... //from clip to shadowMap texture space
    
//'m_shadowCamera.projectionMatrix' is implicitly reversed 
//when the engine calculates device projection matrix from the camera projection
m_shadowCamera.projectionMatrix = shadowProjection; 

//'shadowProjection' is manually flipped before being concatenated to 'm_shadowMatrix'
//because it is seen as any other matrix to a Shader.
if(SystemInfo.usesReversedZBuffer) 
{
    shadowProjection[2, 0] = -shadowProjection[2, 0];
    shadowProjection[2, 1] = -shadowProjection[2, 1];
    shadowProjection[2, 2] = -shadowProjection[2, 2];
    shadowProjection[2, 3] = -shadowProjection[2, 3];
}
    m_shadowMatrix = shadowSpaceMatrix * shadowProjection * shadowViewMat;

Depth (Z) bias

检查深度（Z）方向的工具 使用SystemInfo.usesReversedZBuffer来查明您是否处于使用反向深度（Z）的平台上。
