系统要求

使用 Bakery 你需要：

  • Windows（7 或更高版本）PC。
  • Nvidia GPU。最低支持型号为 Kepler（GeForce 650 或更新。Quadro 显卡请查阅规格）。
  • 64 位 Unity 编辑器。Bakery 已在 5.6 至 2020 的所有版本上测试。

系统要求是针对开发机，而非目标平台。你可以在任何平台上使用 Bakery 烘焙出的光照贴图。

前提条件

  • 确保你的项目没有任何脚本编译错误，否则也会阻止 Bakery 脚本编译。
  • 确保你安装了最新的 GPU 驱动。如有需要请更新。

请使用 Game-Ready（标准）驱动，而不是 “Studio”（工作室）驱动。

  1. 添加一些模型或基本体（primitive），并将其标记为 Static（静态）。

第 4 页：快速入门（续）

网格必须具有不重叠的 UV 才能进行光照贴图烘焙。如果存在 UV2 则使用 UV2（否则使用 UV1）。如果你没有为光照贴图展开模型，请务必在资源上勾选 Generate Lightmap UVs（生成光照贴图 UV）。Unity 基本体已经具有正确的 UV2。

  1. 选择 Directional Light（Unity 为你创建的那个），并向其添加 Bakery Direct Light 组件。

Bakery 和 Unity 使用各自独立的光源组件。

  1. Bakery Direct Light 有很多可调选项，但你可以轻松地将其与 Unity 光源匹配。点击 Match lightmapped to real-time（将烘焙光匹配到实时光）。现在 Bakery 光源应该具有与 Unity 默认 Directional 相同的淡黄色。

Direct Light 组件可能会提示项目未使用线性光强度。问题在于，默认情况下 Unity 对光源颜色应用伽马校正的方式不正确，这正是 “Fix”（修复）按钮所做的。如果你已经有很多以非线性强度模式设置的光源，并且不想再次更改它们，可以跳过修复。即使按了 “Fix”，你也可以随时还原更改。

  1. 要获得带阴影的环境光照，创建 Skylight（天空光）（Bakery->Create->Skylight）。

  1. 选择 Skylight，给它一些偏蓝的颜色，然后点击 Match scene skybox to this light（将场景天空盒匹配到此光源）。这将使场景天空盒与光照完全匹配。

将 Unity 天空盒与 Bakery 天空光匹配是可选的，但对正确性很有用，以确保可见环境和引擎内的反射探针与烘焙光照匹配。目前此选项仅适用于标准渲染管线（Standard render pipeline）。

第 5 页：快速入门（续）

  1. 点击 Bakery->Render Lightmap。默认情况下激活的是 Full Lighting（完整光照）模式。它将烘焙所有光源的直接和间接贡献。如果你想将实时阴影与烘焙 GI 结合，请将其改为 Indirect（间接光照）。

下图是Render Lightmap 窗口

Bakery 可能会提示你正在使用旧的伽马模式并建议更改。如果你在意光照质量，强烈推荐使用 Linear（线性）模式。如果你已经有一个以错误伽马设置的大型项目且不想更改，或者针对不支持线性模式的移动设备发布，可以忽略此提示。

  1. 点击 Render（渲染）。

  2. 完成！你现在应该有了烘焙好的 GI： 图：烘焙完成效果

第 6 页：渲染设置、渲染模式

渲染设置

所有渲染设置都可以通过 Bakery->Render Lightmap 访问。设置会为每个场景保存。Bakery 窗口顶部的选项允许你在 Simple（简单）、Advanced（高级）和 Experimental（实验性）设置之间切换，每种模式都会显示更多可调整选项。Simple 模式对大多数场景来说已经足够，也是入门的好方法。

渲染模式

定义要烘焙的光照贴图类型。下图显示不同渲染模式对比

完整光照（Full Lighting）

烘焙所有 Bakery 光源的完整直接与间接光照。

在 2017.3 之前的 Unity 版本上，如果你在同一对象上同时有 Unity 和 Bakery 组件，则需要手动禁用 Unity 组件以避免双重亮度。在较新版本中，与内置光照贴图器一样，烘焙光源的实时效果会自动禁用。

间接光照（Indirect）

基本混合模式。它会查看每个光源上的 Baked Contribution（烘焙贡献）选择器：如果设置为 Direct And Indirect（直接与间接），则该光源按 Full Lighting 模式烘焙。如果设置为 Indirect Only（仅间接），则只烘焙此光源的间接贡献（GI）。在后一种情况下，你应该在对象上同时保留 Unity 和 Bakery 光源，一个提供实时直接贡献，另一个用于预计算 GI。

阴影遮罩（Shadowmask）

一种更高级的混合模式。它的工作原理是生成两种类型的光照贴图——一种带有烘焙颜色（与 Indirect 模式相同），另一种带有来自静态对象的阴影。它有若干好处：

  • 实时阴影只需要渲染少量动态对象，而不是整个场景。
  • 实时和烘焙阴影可以正确地融合在一起。
  • 实时光源可以渲染凹凸、高光和其他表面效果，同时仍被高质量烘焙阴影遮挡。

此复选框仅在选择了阴影遮罩时可见，它只是切换项目 Quality Settings（质量设置）中同名设置。更多细节。

  • 由于缺少相应脚本 API，此复选框在 Unity 5.6.x 上不可见。相反，你可以在 Window->Lighting->Mixed Lighting->Lighting Mode 中切换。
  • 在 Unity < 2017.3 版本上，由于 API 限制，渲染 Shadowmask 光照贴图会清除光照探针。烘焙后需要重新渲染它们。在较新版本上不应该发生这种情况。

相减模式（Subtractive）

启用相减光照模式。此选项对光照贴图本身不做任何特殊处理，实际上它的工作方式与 Full Lighting 相同。唯一的区别是它还会设置实时 Unity 光源以配合相减模式工作（因为这无法通过 UI 完成）。你还需要在 Unity 光照窗口中额外设置全局相减参数（如全局阴影颜色）。

仅环境光遮蔽（Ambient Occlusion Only）

仅烘焙 AO。如果你知道自己在做什么，这可能会很有用。确保设置好 AO 选项。

方向模式（Directional mode）

定义方向信息的烘焙方式。标准光照贴图每个纹素只存储单一颜色，而方向性光照贴图会给着色器提供关于纹素周围半球上光照如何变化的提示。这些数据是结合完全光照贴图区域与法线贴图所必需的。将其接入内置的 Bakery 着色器也可以产生近似的镜面反射响应。

无（None）

无方向数据，每个纹素单一颜色。

烘焙法线贴图（Baked Normal Maps）

仍然没有方向数据，但在渲染光照贴图时会考虑法线贴图。没有额外的运行时开销。由于光照贴图的分辨率通常低于法线贴图，结果可能看起来模糊。其他问题包括由于缺乏 mipmapping 导致的远处锯齿，以及降噪步骤可能抹掉细节。要了解如何在此模式下使用带程序化法线的自定义着色器，请阅读 Normal Mapping 部分。

主方向（Dominant Direction）

此模式类似于 Unity 中的 Enlighten 和 Progressive（渐进式）烘焙。它兼容大多数着色器，只生成一张附加贴图，运行时开销最小。缺点是凹凸贴图看起来相当暗淡和发灰，并且与同一对象在实时光照下的效果可能有很大差异。

RNM

基于最初为 HL2 发明的 Radiosity Normal Mapping（辐射度法线贴图）技术，后来被许多游戏使用（例如《镜之边缘》）。它总共生成 3 张 HDR 贴图，是所有模式中最耗内存的。运行时开销仍然相对较低。此模式比 Dominant Direction 更精确。它更擅长再现表面对比度，以及处理从不同角度影响法线贴图的有色光源。

SH

基于 Precomputed Global Illumination in Frostbite（寒霜引擎中的预计算全局光照论文）。这是最高质量的模式，能给出更好的表面对比度，并能表现来自不同方向的不同颜色光照。总共生成 4 张贴图，其中只有一张是 HDR，因此比 RNM 占用更少内存。运行时开销略高于 RNM。

MonoSH

与 SH 相同，但使用单色 L1 方向系数。表面对比度同样好，虽然不能精确表示同一纹素上来自不同方向的不同颜色；但对许多场景来说已经足够。只生成一张附加贴图，因此 VRAM 占用/带宽与 Dominant Direction 相似；实际上甚至更小，因为 Dominant Direction 使用 RGBA 贴图，而 MonoSH 只需要 RGB。该贴图通过内置的方向性光照贴图系统提供，但使用标准着色器时看起来不正确。请确保使用兼容的着色器。

局限性（Limitations）

  • RNM 和 SH/MonoSH 只能与 Bakery 着色器一起使用，或者需要对你的着色器进行调整。
  • 在 RNM 和 SH 模式下，不会创建标准颜色光照贴图。你需要让场景中所有材质都使用 Bakery 着色器，或者使用 Lightmap Groups（光照贴图组）将 RNM/SH 对象与其余对象分开。
  • RNM 和 SH 贴图通过 MaterialPropertyBlock应用到对象上，因此可能不会完整显示在 Unity 的 Lighting 窗口中。
  • Dominant Direction、RNM 和 SH/MonoSH 模式可能需要稍多一些的 GI 和 Light Mesh 采样，才能获得同等级别的质量。

每单位纹素（Texels per unit）

每世界单位大约的光照贴图纹素数。影响生成的光照贴图数量与分辨率。

帮助你入门的示例值：

  • 大型室外区域（一座城市）：1 - 5
  • 中等室外区域（几条小巷）：10-20
  • 高质量室内：100

上图是每单位 1 纹素 与 10 纹素的对比

假设场景比例大约为 1 单位 = 1 米。在 Unity 中工作时通常建议采用这种比例，以便更好地导航和进行物理模拟。如果你的比例不同，请相应地乘以 Texels 值。

请记住，Texels Per Unit 是基础分辨率，但每个对象还可以通过 Mesh Renderer 上的 Scale in Lightmap（https://docs.unity3d.com/Manual/class-MeshRenderer.html）选项以及 Bakery 窗口中的 Scale per map type 进行额外调整。

将 Scale in Lightmap 设置为 0 的对象不会被烘焙，但仍会投射阴影并影响 GI。

最大分辨率（Max resolution）

最大光照贴图尺寸限制。如果对象无法放入单个光照贴图（给定当前 Texels Per Unit 值），将分配额外的光照贴图。同样的 4 个方形对象可以占用四张 512x512 贴图或一张 1024x1024。

反弹次数（Bounces）

定义光线应在表面间反弹多少次。通常室外场景（如城市）用较低值就足够，而更封闭的场景（室内、洞穴）需要更高值。

虽然滑块限制为 5 次反弹，但可以在数字字段中输入任意数量的反弹次数。

影响 GI 的质量。典型值为 16 到 32。

可以输入任何数字，超过滑块的最大值也可以，但请注意这个数字代表最终光线数的平方根，即 32 是 1024 条光线，64 是 4096 条光线，依此类推。

GPU 优先级（GPU Priority）

当 GPU 在处理光照贴图时，操作系统和其他软件可能会变得不太响应。此选项允许你在烘焙速度和系统响应性之间取得平衡。

渲染（Render）

为所有已打开的场景烘焙光照贴图。如果 Light Probe Mode 设置为 L1 或 L2，也会烘焙光照探针。

渲染光照探针（Render Light Probes）

为所有已打开的场景烘焙光照探针。

注意，要在 Shadowmask 模式下让动态对象获得正确的混合光照阴影，你还需要启用遮蔽探针（occlusion probes）

渲染反射探针（Render Reflection Probes）

为所有已打开的场景烘焙反射探针（https://docs.unity3d.com/Manual/class-ReflectionProbe.html）。此按钮只是为方便起见，它将调用内置引擎的反射探针更新。

更新天空盒探针（Update Skybox Probe）

为当前天空盒烘焙全局漫反射和反射探针。与 “Render Reflection Probes” 一样，它只是调用内置引擎函数。

遮蔽探针（Occlusion probes）

渲染光照探针时，让 Unity 使用当前选择的内置光照贴图器烘焙遮蔽探针。遮蔽探针是存储在常规光照探针内部的附加数据，它可以防止动态对象在阴影区域被照亮。目前 Unity 中无法使用自定义遮蔽探针，必须调用其自己的光照贴图器来完成这项工作。

警告（Warnings）

这些选项会在按下某个 Render 按钮后验证场景，并显示警告对话框，询问继续还是停止烘焙过程。

  • Suppress all popups（抑制所有弹窗）：按下 Render 后不显示任何对话框。
  • UV validation（UV 验证）：将检查所有模型是否具有完全正确的光照贴图 UV——具体来说是检查它们是否位于 0-1 范围内且不重叠。
  • Overwrite check（覆盖检查）：将告知哪些光照贴图文件将被覆盖。
  • Memory check（内存检查）：将给出所需显存的一个非常粗略的估算。
  • Sample count check（采样数检查）：将检查是否有任何光源、GI 或 AO 具有不合理的采样数，可能导致 GPU 超出可用资源。
  • Lightmapped prefab validation（光照贴图预制体验证）：验证光照贴图预制体，并通知是否有某些预制体将被覆盖。

高级渲染设置（Advanced render settings）

光照探针模式（Light probe mode）

更改光照探针的烘焙方式。

Legacy（旧版）：使用 Render Light Probes 按钮生成探针。点光源和方向光在光照贴图器内计算，而区域光/天空/间接光照通过在每个探针位置渲染立方体贴图来收集。结果存储为 L2 球谐。缺点是立方体贴图渲染性能较慢，并且当你的游戏着色器不能物理地表现被照亮表面，或者你的项目是为移动端设置时（Unity 会裁剪掉高强度值），光照贴图与探针之间可能出现不匹配。

第 10 页：光照探针模式、资源 UV 处理、降噪器

L1：点击 Render 时，光照探针将与光照贴图一起渲染。此选项提供卓越的烘焙性能，并保证探针光照与光照贴图匹配。结果存储为 L1 球谐（常规着色器仍可使用）。使用 Bakery 着色器中的 Non-Linear Light Probe SH 选项可以进一步改善结果。

L2：卓越质量（完整 L2 球谐）。与 L1 一样，会与光照贴图一起自动渲染。与 L1 相比性能影响可忽略。在所有着色器下看起来都应该正常。探针对比度/方向性/振铃移除可以通过 Project Settings -> Bakery -> “Ringing removal for L2 light probes” 调整。

Unity 2019.3 中似乎有一个 bug：如果启用了遮蔽探针选项，Legacy 光照探针颜色将无法正确保存。L2 模式现在是默认模式，在使用遮蔽探针时推荐使用。

资源 UV 处理（Asset UV Processing）

配置资源的 UV 填充（padding）调整。可能的值：

  • Don’t change（不更改）：不触碰资源。
  • Adjust UV padding（调整 UV 填充）：将查找具有自动生成 UV（资源上的 “Generate Lightmap UVs”）的模型，并进一步调整它们，使每个网格的 UV 岛之间有适当的填充。导入器设置中整个模型的 Pack Margin 将被忽略。取而代之的是根据每个网格的面积和光照贴图分辨率计算最优值。
  • Adjust UV padding for new meshes only（仅调整新网格的 UV 填充）：相同，但跳过任何先前至少调整过一次的模型。
  • Remove UV adjustments（移除 UV 调整）：还原所有先前的 UV 调整，使自动展开的模型看起来与 Unity 原本展开的方式一致。

降噪器（Denoiser）

设置所需的降噪器。可能的值：

  • Optix 5：使用 OptiX 5.1 AI 降噪器（以前称为 “Legacy denoiser”）。在 GPU 上运行。支持从 Kepler（通常是 GeForce 6xx）到 Turing（通常是 GeForce 20xx）的所有产品。不支持 Ampere。OptiX 5.1 使用嵌入其中的静态训练数据集，这意味着它不受驱动实现的影响。
  • Optix 6：使用 OptiX 6.0 AI 降噪器（以前是默认选项）。在 GPU 上运行。似乎在 Kepler（6xx）GPU 上会失败，但在所有更新型号上都能运行，包括 Ampere（30xx）。从 6.0 开始，OptiX 降噪器的训练数据集位于驱动中。在驱动 v442.50 之前，其行为类似于 OptiX 5.1；但在那之后 NVIDIA 更改了数据集，结果可能不同。更新的数据集有时会产生网格状图案和更多亮边（仍然可以用 “Denoise: fix bright edges” 修复），但运行更快。
  • Optix 7：使用 OptiX 7.2 AI 降噪器。行为与 OptiX 6.0 类似，但在 Ampere（30xx）上可能支持更好。
  • OpenImageDenoise：使用 Intel Open Image Denoise 库。在 CPU 上运行（任何支持 SSE 4.1 的 CPU）。可能比 OptiX 稍慢，但质量相当。
  • OpenImageDenoise2：使用 Intel Open Image Denoise 2，CUDA 模式。在 GPU 上运行，性能与 OptiX 6/7 相当，质量与 CPU 版本相同。

调整采样位置（Adjust sample positions）

寻找最佳采样位置以防止漏光。算法细节在此概述。在某些情况下（通常是大而低多边形且带平滑法线的几何体），它可能产生错误结果，这时你可以禁用它。

渲染前卸载场景（Unload scenes before render）

在烘焙前卸载 Unity 场景以释放显存。复杂场景仅因在编辑器中显示就可能占用数 GB 的 VRAM。

降噪（Denoise）

如果启用，将应用降噪算法。Bakery 使用 Nvidia 的 AI 降噪器。

修复接缝（Fix Seams）

如果启用，将尝试混合由 UV 不连续产生的接缝。对平滑几何体很有用，包括 Unity 的默认球体。

按场景拆分（Split by scene）

如果同时加载多个场景，并且此选项启用，则每个场景将拥有自己的一组光照贴图，不与其他场景共享。当场景在运行时流式加载时，这对于限制加载的纹理数量很有用。

孔洞填充（Hole filling）

如果 Atlas Packer 设置为 xatlas，将尝试填充每个孔洞，从而产生更高效的图集。对于非常复杂的几何体场景，它可能增加场景导出时间，但除此之外推荐启用。

最小分辨率（Min resolution）

最小光照贴图尺寸限制。可用于在"许多小而完全占满的光照贴图"与"少量未完全填充的光照贴图"之间取得平衡。

按贴图类型缩放（Scale per map type）

允许你以不同方式缩放颜色/阴影遮罩/方向贴图的分辨率。例如，一个常见情况是间接光照颜色使用低分辨率，但阴影遮罩使用高细节。注意缩放是在光照贴图渲染后应用的，所以不会节省烘焙时间。如果 “Adjust UV padding” 开启，填充将基于最低分辨率的贴图，以防止纹素泄漏。

棋盘格预览（Checker preview）

如果 Show checker 复选框开启，Scene View 将在可见对象之上渲染棋盘格图案，以演示光照贴图纹素大小。这有助于确保在烘焙前为 Texels Per Unit 和其他影响分辨率的设置使用合适的值。

启用棋盘格预览将强制 Bakery 执行图集打包。这可能需要一些时间，但不应超过几秒。在你更改某些内容后，按 Refresh checker 可重新对场景进行图集打包以查看更改。

棋盘格预览还使用随机颜色来显示场景将如何被分割到不同的光照贴图中。

棋盘格预览目前不会为地形显示正确的纹素大小。

图集预览（Atlas preview）

当棋盘格预览开启时，Atlas preview 按钮可见。点击它将打开一个新窗口，显示未来光照贴图的 UV 布局。点击 “<” “>” 按钮浏览各光照贴图。这在烘焙前检查打包质量和光照贴图数量时很有用。

自发光增强（Emissive boost）

将任何表面自发光乘以这个数字。

间接光增强（Indirect boost）

将所有反弹光照乘以这个数字。与光源组件上的 Indirect Intensity 相同，但它是全局的。

背面全局光照（Backface GI）

决定有多少光从正面穿过到背面，然后被 GI 反弹。这对薄而半透明的表面（如树叶）特别有用。值在 0-1 范围内。

环境光遮蔽（Ambient occlusion）

简单的非物理环境光遮蔽，你可以将其叠加在最终场景光照之上以达到美学目的。

  • Intensity（强度）：控制 AO 效果的可见度。值为 0 时禁用效果。
  • Radius（半径）：决定 AO 效果中使用的光线距离。较小的值给出局部遮蔽（角落、褶皱），而较大的值使其更像 Skylight，产生来自远处对象的阴影。
  • Samples（采样）：影响环境光遮蔽的质量。典型值为 4 到 32。

第 12 页：抖动透明度、RTX 模式、地形、批处理、压缩体积、采样倍增、瓦片尺寸、临时路径

抖动透明度（Dither transparency）

通过自动抖动 alpha 纹理来启用半透明阴影。参见 Bakery 如何解释不透明度贴图。

RTX 模式（RTX Mode）

启用 RTX 硬件加速。只有 RTX GPU 能从该选项受益。最低支持驱动版本为 418。

  • 驱动可以在大多数非 RTX Nvidia 显卡上模拟 RTX 模式，但结果通常更慢。
  • RTX 模式必须在 Ampere（3xxx）显卡上启用。

导出地形树木（Export terrain trees）

如果启用，绘制的地形树木将影响光照。树木本身不会被烘焙。注意烘焙时每棵树都使用尽可能最高的 LOD 级别。不建议将此选项用于渲染具有高细节模型的多公里森林。

地形优化（Terrain optimization）

如果启用（默认），地形使用独立的射线追踪技术以利用其高度场几何体。否则它们被当作任何其他网格处理。地形优化显著降低了高分辨率地形所需的显存占用。在某些情况下它还可以使地形烘焙更快，在其他情况下（尤其是简单的低分辨率地形）禁用它可能更合理。

Terrain Optimization 目前与绘制的地形洞不兼容。禁用它才能让它们工作。

光照网格批处理上限（Light Mesh batch limit）

如果此值大于 0，会将许多 Light Mesh 合并为一个，前提是它们具有相同的设置并影响相同的光照贴图组，但将它们的总采样数限制为该值（即如果上限为 64，它可以合并 2 个 samples=32 的光或 4 个 samples=16 的光，等等）。这将在有许多 Light Mesh 的场景中提高性能。小心不要将此值设置得太高，因为 GPU 一次处理太多采样时可能触发操作系统驱动超时。

压缩体积（Compress volumes）

如果启用，对体积 3D 纹理应用纹理压缩，并将 Bakery 着色器切换到相应的采样模式。不建议用于非常低分辨率的体积。体积大小可能被增加到 4 的倍数。

注意事项：

  • 目前它只能压缩为 BC6H/BC7 纹理格式（桌面/主机）。
  • 体积压缩仅在 Unity 2020.1 或更新版本上受支持。
  • 目前只有标准渲染管线的 Bakery 着色器支持使用压缩体积。

采样倍增器（Samples multiplier）

将所有阴影和 GI 采样乘以指定系数。使用它可以在草稿质量和最终质量之间快速切换。

瓦片尺寸（Tile size）

与 GPU Priority 相同，但不用抽象优先级，而是设置瓦片尺寸。Bakery 将光照贴图拆分为较小的瓦片并一次更新一个。更小的尺寸意味着更多的 GPU 工作中断，可以使系统更响应。

临时路径（Temp path）

临时文件文件夹。Bakery 在渲染期间可能需要数 GB 的可用空间。将此文件夹放在 SSD 上可以使渲染比 HDD 稍快。目前此文件夹不会自动清理。你可以随时删除其内容（渲染期间除外）。

第 13 页：输出路径、实验性渲染设置

输出路径（Output path）

光照贴图文件夹。所有光照贴图以及光照探针和顶点颜色资源都将保存在这里。此路径相对于你的 Assets 文件夹。

如果启用此选项，输出路径将自动设置为与当前活动场景同名的文件夹（Assets/CurrentSceneName/）。这与内置 Unity 光照贴图器的行为类似。

仅烘焙包含所选对象的光照贴图组。不仅所选对象会被重绘，它们所属的所有光照贴图组也会被重绘。其他光照贴图将不会被更新。如果对象不属于某个手动分配的组，那么使用同一光照贴图的场景部分将被重新烘焙。

完成时提示音（Beep on finish）

如果启用，烘焙完成时 Bakery 将播放声音。

第 14 页：实验性渲染设置（续）、组件（光照贴图组选择器）

UV 填充：仅增加（UV padding: increase only）

仅在 Adjust UV padding 开启时可见。默认情况下，模型资源的最优 UV 填充仅基于当前加载的场景计算。如果同一模型有多个使用不同光照贴图分辨率的实例，最小的那个将决定填充，因此 UV 块之间的间距足够大以防止它们相互泄漏。但是，在两个不同的隔离场景中烘焙同一模型，可能在为新场景优化的同时破坏先前场景中的 UV。此复选框允许通过永不减少填充值来防止这种行为，因此它将始终针对曾经烘焙过的最低分辨率实例进行优化。

降噪：修复亮边（Denoise: fix bright edges）

仅在 Denoise 开启时可见。有时用于降噪的神经网络会在阴影周围产生亮边，就像应用了锐化效果一样。如果启用此选项，Bakery 将尝试过滤掉它们。启用后降噪阶段可能会稍慢。

Bakery 光照贴图组选择器（Bakery Lightmap Group Selector）

指定对象及其所有子对象使用哪个光照贴图组。光照贴图组（Lightmap Group）是 Bakery 用来表示共享一张光照贴图的对象集合的术语。组具有一些属性，告诉 Bakery 如何打包对象、哪些光源应影响它们、结果应烘焙到纹理还是顶点。默认情况下所有静态对象都会自动打包到多个光照贴图组（图集）中，所以你不必担心。手动定义组只应用于特殊目的，例如：

  • 标记某些对象使用逐顶点光照贴图而不是纹理。
  • 使用建模软件中精确的未缩放 UV 烘焙光照贴图。
  • 将关卡的某些区域分组以使用单个光照贴图，便于资源流式加载或在运行时通过脚本切换不同的烘焙光照。
  • 使用 Render Selected Groups 按钮只更新分组对象。

要手动定义组，你可以创建 Lightmap Group 资源（Assets），通过 Assets->Create 菜单，或使用组件中的 Create New 按钮。使用 Create New 按钮时，将根据以下表单创建新资源：

  • Name（名称）：要创建的光照贴图组资源的名称。

    • Original UV（原始 UV）：对象及其子对象将使用未修改的 UV 烘焙。不执行打包。这对于多个网格共享同一个已打包 UV 布局的模型很有用。
    • Pack Atlas（打包图集）：对象及其子对象被打包到专用纹理图集中。在 v1.3 之前，每个可打包的子对象都需要有这个组件，但现在不再需要。每个子对象将作为自己的矩形打包，除非 Bakery 自动检测到子对象具有不重叠的子对象，在这种情况下

Bakery 光照贴图预制体（Bakery Lightmapped Prefab）

此组件允许预制体存储光照贴图元数据。这样的预制体之后可以在任何场景中实例化，无论是在编辑器还是运行时。该组件应直接添加到预制体的根对象上。不支持嵌套预制体。由于烘焙后预制体将被覆盖（与按下 “Apply” 按钮的方式相同），因此要求预制体没有任何未应用的更改（子对象不应被移动、材质和脚本参数不应被更改等）。如果检测到此类更改，组件 UI 中将打印错误，并且烘焙后不会保存元数据。如果启用了 Lightmapped prefab validation 警告，所有预制体错误也会在烘焙前显示在对话框中。

光照贴图预制体支持所有 Bakery 功能，如 LOD、地形、方向性光照贴图、RNM、SH、逐顶点模式和阴影遮罩。要使阴影遮罩工作，你需要让光源也属于同一个预制体。

注意，由于 API 限制，预制体阴影遮罩仅在 Unity 2017.4 或更新版本上工作。

烘焙后，一个名为 “BakeryPrefabLightmapData” 的对象将被添加到预制体中。此对象持有一个脚本，包含应用光照贴图所需的所有数据。

此外，Lightmapped Prefab 允许你使用两个按钮保存当前渲染设置并将其加载回任何当前打开的场景：

  • Save current render settings to prefab（将当前渲染设置保存到预制体）：在此预制体上存储当前 Render Settings 的副本。
  • Load render settings from prefab（从预制体加载渲染设置）：将当前 Render Settings 设置为存储在预制体上的设置。

烘焙光照贴图预制体时，建议检查：

  • 预制体已 “Applied”（应用）。在较旧的 Unity 版本上，点击 Inspector 右上角的 “Apply” 按钮。在较新版本上点击 “Overrides” 列表，然后 “Apply all”。
  • 预制体组件 UI 不显示任何错误。
  • （推荐）主窗口中启用 “Lightmapped prefab validation” 复选框。点击 Render 时你不会看到关于预制体的任何警告对话框。

  • 光照贴图以烘焙它们的场景或它们使用的光照贴图组（如果有）命名。在同一场景中烘焙不同预制体时，请确保使用不同名称的光照贴图组或更改 Output Path。
  • 当使用相同模型逐个烘焙多个预制体时，建议将 Asset UV Processing 设置为 Don’t Change，以防止共享模型 UV 被更改。
  • Bakery 的预制体工作流是在 Unity 具有"双击进入预制体"视图功能之前实现的。因此，在隔离的预制体视图中光照贴图可能无法正确应用，组件可能显示 “This GameObject is not a prefab” 消息。在正常场景中工作时应该按预期工作。
  • 解包以前烘焙的预制体并将其与现有光照贴图解除链接时，请确保移除持有预制体级光照贴图/渲染器连接的 BakeryPrefabLightmapData 对象。

第 16 页：Bakery 平行光、天空光、光照网格

Bakery 平行光（Bakery Direct Light）

无限远的平行光（例如太阳）。

  • Color（颜色）：颜色。
  • Intensity（强度）：线性颜色倍增器。
  • Shadow spread（阴影扩散）：光源的大小，或简单地说，阴影模糊程度。0 = 最大锐利阴影，1 = 最大模糊阴影。技术上它从单条光线插值到更宽的光线锥。
  • Shadow samples（阴影采样）：影响阴影质量。Shadow Spread 值越小，干净图像所需的采样越少。太阳阴影的典型值为 1 到 16。将采样设置为 0 将使此光源的阴影消失。
  • Bitmask（位掩码）：用于排除此光源影响特定光照贴图组的开关列表。
  • Baked contribution（烘焙贡献）：决定应烘焙何种光照数据。仅在 Indirect 或 Shadowmask 模式下可见。可能的值：
    • Direct and Indirect（直接与间接）：直接和间接贡献都将被完全烘焙。
    • Indirect only（仅间接）：实时光源应提供直接贡献；仅烘焙间接光照。
    • Shadowmask and indirect（阴影遮罩与间接）：实时光源应提供直接贡献，但来自静态几何体的阴影将被烘焙到单独的贴图。动态和静态阴影将混合在一起。间接光照将照常烘焙。
    • Direct, Indirect, Shadowmask (custom lighting only)（直接、间接、阴影遮罩（仅自定义光照））：与 Direct and Indirect 相同，但也会生成 Shadowmask 并分配用于自定义着色器。
  • Denoise shadowmask（降噪阴影遮罩）：决定是否应对此光源的阴影遮罩应用降噪。通常没有必要，因为阴影不会表现出太多噪点，但对非常宽的模糊阴影（大的阴影扩散）可能有用。
  • Indirect intensity（间接强度）：此光源的非物理 GI 倍增器。自然光照应为 1，但可以修改以获得更风格化的场景。
  • Anti-alias（抗锯齿）：对阴影执行超采样。
  • Texture projection（纹理投影）：在光照上投影一个可平铺的乘法纹理。可用于模拟远处的云影。

Bakery 天空光（Bakery Sky Light）

无限远的带阴影环境光（天空）。

  • Color（颜色）：颜色。
  • Intensity（强度）：线性颜色倍增器。
  • Sky texture（天空纹理）：可选的立方体贴图资源，例如 HDRI 全景，用于影响来自不同方向的光照颜色。

旋转天空光 GameObject 将相应地旋转来自立方体贴图的光照。

  • Samples（采样）：影响阴影质量。典型值为 8 到 32。
  • Hemispherical（半球）：如果启用，光照只来自上方（上半球）。否则来自所有方向。
  • Bitmask（位掩码）：用于排除此光源影响特定光照贴图组的开关列表。
  • Baked contribution（烘焙贡献）：决定应烘焙何种光照数据。仅在 Indirect 或 Shadowmask 模式下可见。可能的值：
    • Direct and Indirect（直接与间接）：直接和间接贡献都将被完全烘焙。这是所有天空光的默认且推荐行为，因为 Unity 中没有实时版本可以模拟它们。
    • Indirect only（仅间接）：实时光源应提供直接贡献；仅烘焙间接光照。

Bakery 根据自发光表面的接近程度混合两种用于区域光的算法。靠近光源时其工作方式类似于 GI 算法，而在远处，光源被近似为一团虚拟点光源。

  • 光照网格自身不接收光照，也不会被光照贴图烘焙。
  • 一个多边形的 Light Mesh 比许多简单的 Light Mesh 烘焙更快。
  • 如果你不断得到脏/噪的结果，尝试将 Samples Near 设置为 0。然后只使用 VPL 算法。它对于精度不重要的非常简单光源也很有用（例如建筑物上的窗户灯）。
  • Bitmask（位掩码）：用于排除此光源影响特定光照贴图组的开关列表。
  • Baked contribution（烘焙贡献）：决定应烘焙何种光照数据。仅在 Indirect 或 Shadowmask 模式下可见。可能的值：
    • Direct and Indirect（直接与间接）：直接和间接贡献都将被完全烘焙。这是所有光照网格的默认且推荐行为，因为 Unity 中没有实时版本可以模拟它们。
    • Indirect only（仅间接）：实时光源应提供直接贡献；仅烘焙间接光照。
    • Shadowmask and Indirect（阴影遮罩与间接）：实时光源应提供直接贡献，但来自静态几何体的阴影将被烘焙到单独的贴图。动态和静态阴影将混合在一起。间接光照将照常烘焙。目前只有 HDRP（和自定义渲染器）支持混合区域光。
    • Direct, Indirect, Shadowmask (custom lighting only)（直接、间接、阴影遮罩（仅自定义光照））：与 Direct and Indirect 相同，但也会生成 Shadowmask 并分配用于自定义着色器。
  • Indirect intensity（间接强度）：此光源的非物理 GI 倍增器。自然光照应为 1，但可以修改以获得更风格化的场景。
  • Shadowmask with falloff（带衰减的阴影遮罩）：将完整的灯光衰减烘焙进阴影遮罩（仅对自定义着色器有用）。

如果网格材质和光照设置不匹配，将出现两个按钮：

  • Match light to material（将光源匹配到材质）：将公共设置从无光照网格材质或区域光复制到 Bakery 光源。
  • Match material to light（将材质匹配到光源）：将公共设置从 Bakery 光源复制到无光照网格材质或区域光。

光照网格与自发光材质的区别（Differences between Light Mesh and emissive materials）

自发光材质（Emissive material）：

  • 在 GI 计算期间传播光线，因此无论多少网格是自发光的都是 “免费” 的。
  • 小而亮的光源可能根据 GI 采样数给出不准确的噪点结果。
  • 由于 Bakery 中 GI 的工作方式，它必须占据光照贴图空间，因此可能浪费空间。这也意味着自发光对象需要有效的 UV 并启用 “Cast shadows”。

光照网格（Light Mesh）：

  • 每个光源单独计算光照，因此比自发光材质慢。
  • 专为小而亮的光源设计，即使离它们很远也能给出干净的结果。
  • 不占据光照贴图空间。

Bakery 点光源（Bakery Point Light）

点光源，没有面积。尽管物理上不可能，但它对游戏很有用，而且是匹配 Unity 点光源和聚光灯的唯一方式。

聚光灯只是带额外投影遮罩的点光源。

  • Color（颜色）：颜色。
  • Intensity（强度）：线性颜色倍增器。
  • Shadow spread（阴影扩散）：阴影模糊程度。虽然点光源没有面积，但通常仍然希望它们产生模糊阴影。为此，阴影被模拟为从一个球形区域光投射。此参数定义这个虚拟球体的半径，直接影响模糊程度。

Bakery Volume 是一个与一组 3D 纹理（3 个 SH 纹理和一个阴影遮罩，如果需要）链接的边界框，使其非常易于使用和脚本化。体积可以在运行时轻松地交换、移动、加载或卸载，或链接到预制体。它们也不需要任何 Light Probe Group 和手动探针放置；整个体积被填充为均匀的探针体素网格。光照/阴影泄漏会自动修复，方式与光照贴图相同（虽然薄的双面墙可能在大体素尺寸下成为问题，但可以通过在不同侧面使用不同体积来避免）。由于体素网格的均匀性，还可以对其应用类似光照贴图的降噪，这是常规光照探针无法做到的。此外，Bakery 着色器使用 Geomerics 采样技巧来完全消除球谐在高对比度 HDR 光照下有时会产生的 “振铃” 伪影。

因此，体积可以为动态对象产生干净、细致、高质量的烘焙光照（也就是说，来自静态对象并影响动态对象的光照，而不是反过来）。

体积方法的唯一缺点是更高的每像素着色成本。成本与 LPPV 类似（随屏幕上受体积影响的着色像素数量缩放），但与 LPPV 不同，体积一旦烘焙就永远不会更新。可以通过轻微重叠体积来避免多个体积混合。

设置体积变换（Setting volume transform）

当 BakeryVolume 添加到 GameObject 时，场景视图中会出现一个边界框 gizmo。通过小方块拖动它可以缩放。还有其它更改体积大小和位置的方法：

  • 将任何可渲染的 GameObject 拖入 “Wrap to object” 字段。体积将环绕此对象（及其子对象）以将其封装。
  • 如果同一对象上添加了 Box Collider，将出现 “Set from box collider” 和 “Set to box collider” 按钮。这些可用于在体积/碰撞器之间快速复制值。

分辨率（Resolution）

当启用 “Adaptive resolution”（自适应分辨率）时，体素数量由 “Voxels per unit”（每单位体素）控制。禁用它则允许手动输入分辨率。对于大多数 1 单位 = 1 米的游戏，合理的 “Voxels per unit” 值是 2，但有些情况（例如动态门）使用更小但分辨率更高的体积是有益的。

其他设置（Other settings）
  • Enable baking（启用烘焙）：体积应该被（重新）计算吗？禁用可防止覆盖现有数据。
  • Denoise（降噪）：烘焙体积后应用降噪。推荐用于高分辨率体积。避免用于覆盖许多光源的极低分辨率体积，因为降噪器将难以区分实际内容与噪点。
  • Global（全局）：自动将此体积分配给所有兼容体积的着色器，除非它们有覆盖。内部它将调用 Shader.SetGlobalTexture()/SetGlobalVector()。
用法（Usage）

可以使用体积感知着色器将体积分配给对象。Bakery 附带实现此功能的 “Bakery Standard” 着色器，以及 HDRP 和 URP 图。参见 example_volumes 场景了解应用体积的各种方式。

提示（Hints）
  • 确保查看示例。
  • 如果两个体积连接，让它们重叠一点。重叠的大小应等于最大动态对象的大小。这样在运行中简单地在体积之间切换就可以工作。
  • 只在动态对象实际可以到达的区域周围放置体积。例如使用玩家高度来限制体积高度。
旋转体积（Rotating volumes）

如果启用 “Rotate around Y” 选项，体积可以围绕 Y 轴旋转。旋转非常便宜，只使用 2 个额外的浮点数据（预计算的角度的 sin/cos）。

还有一个额外的选项可以在运行时旋转体积（Experimental -> “Support rotation after bake” 以及 Bakery Shader 中的类似选项），在这种情况下它们需要以零初始旋转烘焙。

技术信息（Technical information）

体积可以自动工作（查看示例场景），但也可以编写脚本控制它们的使用方式。

可以通过以下公共属性从组件检索体积数据：

  • bakedTexture0：存储 L0 RGB 系数和 alpha 中的 L1 Z 红色通道。
  • bakedTexture1：存储 L1 X RGB 系数和 alpha 中的 L1 Z 绿色通道。

因此体积字节大小 = widthheightdepth38 +（仅在使用了阴影遮罩时）widthheightdepth4（或使用 R8 遮罩时为 widthheight*depth）。

可以对体积启用纹理压缩以使其小得多。

要采样体积，需要特殊着色器，Bakery 已包含这些。要将体积添加到自定义着色器，请查看 HDRP/URP 包中包含的 BakeryDecodeLightmap.hlsl 中的 BakeryVolume_float() 函数。

Bakery 光照滤镜（Bakery Light Filter）

在上图中，将一个渲染器标记为光照滤镜。滤镜用其颜色着色所有直接/间接光线，类似于现实中的光学滤镜，允许彩色透明效果（例如彩色玻璃）。唯一参数是用于着色的纹理。

反照率与自发光（Albedo and emission）

Bakery 通过利用 Meta Pass（https://docs.unity3d.com/Manual/MetaPass.html）系统支持大多数 Unity 材质。所有内置、surface、URP 和 HDRP 着色器都已经定义了正确的元通道。

如果你有无光照（Unlit）着色器，请按 Unity 文档中的描述手动添加元通道。

如果不存在该通道，Bakery 将假定 _MainTex、_BaseColorMap 或 _Color（如果未设置纹理）属性为材质反照率，_EmissionMap 和 _EmissionColor 为自发光颜色。

为使自发光工作，Material.globalIlluminationFlags（https://docs.unity3d.com/ScriptReference/Material-globalIlluminationFlags.html）必须设置为 MaterialGlobalIlluminationFlags.BakedEmissive（https://docs.unity3d.com/ScriptReference/MaterialGlobalIlluminationFlags.BakedEmissive.html）。Standard 着色器会自动设置此值。

不透明度（Opacity）

默认情况下，Bakery 总是从 _MainTex、_BaseColorMap 或 _BaseMap 的 alpha 值获取全分辨率不透明度，并将其视为 cutout（1 位透明度）。

当启用 Dither Transparency（抖动透明度）选项时，半透明值会自动转换为可变的蓝色噪点，然后被过滤/模糊，产生部分透明度（以前可以使用手动抖动贴图实现，但从 v1.97 起是自动的）。

为使不透明度工作，着色器的 RenderType 标签（https://docs.unity3d.com/Manual/SL-SubShaderTags.html）必须是以下值之一：

  • Transparent
  • TransparentCutout
  • TreeLeaf

如果存在名为 _Cutoff 的属性，它将影响 cutout（因此 Standard 着色器的 cutoff 滑块会自动工作）。

在不使用 Dither Transparency 的情况下，如果材质 RenderType 是 Transparent 或 TreeLeaf，则 _Color 的 alpha 值将额外修改 cutoff：finalCutoff = 1 - (1 - cutoff) * alpha

对于彩色透明度，使用 Light Filter 组件。

对于漫反射半透明效果，阅读关于 Backface GI 和次表面散射的内容。

Alpha 元通道（Alpha Meta Pass）

自 v1.9 起，Bakery 也支持指定基于着色器的自定义透明度，但这需要兼容的着色器。要利用 Alpha Meta Pass，必须采取以下步骤：

  • 向着色器添加名为 BAKERY_META_ALPHA_ENABLE 的属性。例如： [HideInInspector] BAKERY_META_ALPHA_ENABLE ("Enable Bakery alpha meta pass", Float) = 1.0
  • 确保 RenderType 标签设置为上述值之一。
  • 声明一个名为 META_BAKERY 的通道。
  • 在该通道中检查 unity_MetaFragmentControl.w 是否为非零，如果是，则返回计算的透明度值。

参见包中包含的 Baked_Alpha_meta.shader 作为示例。

注意：目前 Alpha Meta Pass 要求将 Light Probe Mode 设置为 L1 或 L2。

自定义表面法线可以与 Baked Normal Maps 模式结合使用。不幸的是，Unity 的 Meta Pass 不输出法线信息，因此默认情况下法线取自名为 _BumpMap 的纹理，并额外由 _MainTex_ST 变换。

然而，完全自定义的、带有高级法线贴图功能（例如混合多个图层）的着色器也可以与烘焙兼容。为此你需要：

正/背面（Front/back faces）

无论着色器使用什么剔除模式，Bakery 都将所有背面视为不透明，这意味着任何直接光线都不会穿过背面，就像不会穿过正面一样。但是，如果你使用 Backface GI，背面可以部分发射正面接收到的光照。

类似于 Bakery 的光照贴图组，Unity 有 Lightmap Parameters，可以作为资源创建并分配给 Mesh Renderer。它们的逻辑有异同：

  • 光照贴图组的主要用途是将多个对象分组到一个图集。此外它允许覆盖此图集的烘焙设置。
  • Lightmap Parameters 主要用于覆盖对象的烘焙设置。但此外它们可以通过 “Baked Tag” 选项影响打包：具有不同 Baked Tag 的对象永远不会共享同一图集。

由于一些用户更习惯 Lightmap Parameters 工作流，Bakery 现在支持并扩展了它们：

  • Bakery 尊重 Baked Tag。
  • Lightmap Parameters UI 中将显示附加的 Bakery 特定选项。它们的含义参见 Lightmap Group 部分。

项目设置（Project Settings）

一些全局设置可以在 Project Settings -> Bakery GPU Lightmapper 中调整（此选项仅在 Unity 2018.3 或更新版本中可见；对于旧版本，改为编辑 BakeryProjectSettings.asset）：

  • Mipmap lightmaps（光照贴图 mipmap）：在光照贴图资源上启用 mipmapping。随着图集变小，可能跨 UV 块产生泄漏；另一方面，它减少了远处高分辨率光照贴图的锯齿。总体而言，建议为非常远的对象使用单独烘焙的较低分辨率光照贴图 LOD，而不是这个。
  • Color file format（颜色文件格式）：常规 HDR 颜色光照贴图的格式。可能的值：
    • HDR：Radiance HDR 格式（默认）。可以在许多图像编辑器中打开。
    • Asset：Unity 原生格式。可以有自定义 mipmap 数量。
  • Mask/Direction file format（遮罩/方向文件格式）：附加 LDR 贴图（如阴影遮罩或方向数据）的格式。可能的值：
    • TGA：8 位 Targa（默认）。
    • PNG：8 位 PNG。与 TGA 相比通常在磁盘上占用更少空间。
    • Asset：Unity 原生格式。可以有自定义 mipmap 数量。
  • Compress lightmaps（压缩光照贴图）：定义光照贴图资源压缩行为。压缩的光照贴图占用更少 VRAM，但根据压缩类型可能表现出一些视觉伪影（如条带或彩色斑点）（移动端压缩问题见此）。可能的值：
    • Compress but allow overriding asset（压缩但允许覆盖资源）：新光照贴图将以启用压缩的方式创建。创建后，可以在 Inspector 中更改它们的压缩设置。重新烘焙后这些修改值将被保留（默认）。
    • Force compress（强制压缩）：始终压缩所有光照贴图。
    • Force no compress（强制不压缩）：始终产生未压缩的光照贴图。
  • High quality direction（高质量方向）：为方向贴图启用 “high” 质量压缩。实际格式取决于平台。例如在 PC 上，它会从 DXT1 改为 BC7，质量更高，但 VRAM 占用加倍。
  • Texel padding (default atlas packer)（纹素填充（默认图集打包器））：使用默认图集打包器时，定义在光照贴图图集中对象 UV 布局之间添加多少空纹素。
  • Texel padding (xatlas packer)（纹素填充（xatlas 打包器））：相同，但使用 xatlas 时。

  • Alpha Meta Pass resolution multiplier（Alpha 元通道分辨率倍增器）：倍增 Alpha Meta Pass 的分辨率，允许在烘焙低分辨率光照贴图时获得精确的基于着色器的 cutout。
  • Volume render mode（体积渲染模式）：所有体积使用哪种渲染模式？Auto 使用当前活动渲染模式（默认）。
  • Delete previous lightmaps before bake（烘焙前删除以前的光照贴图）：在烘焙新光照贴图之前，实际删除此场景中所有先前渲染的光照贴图文件。
  • Log level（日志级别）：定义烘焙期间向控制台打印多少信息。可能的值：
    • 0：不打印任何内容。
    • 1：只打印进度信息。
    • 2：只打印警告。
    • 3：打印所有内容。
  • Alternative scale in lightmap（替代的 Scale in Lightmap）：使 ‘Scale in Lightmap’ 渲染器属性表现得更像内置 Unity 行为。
  • Align to texture compression blocks with xatlas（使用 xatlas 对齐纹理压缩块）：使 xatlas 将 UV 块对齐到 4x4 块边界，这会产生更利于压缩的结果。
  • Generate smooth positions（生成平滑位置）：是否应调整采样位置以防止带平滑法线的低多边形几何体上出现错误阴影？在极少数使用法线严重不匹配的几何体时可以禁用。技术解释见此文章。
  • Smooth positions per-triangle（每三角形平滑位置）：是否应逐三角形决定平滑/平面位置？在极少数使用法线严重不匹配的几何体时可以禁用。
  • Use ‘Receive GI’ values（使用 ‘Receive GI’ 值）：在渲染器上考虑 ‘Receive Global Illumination’（接收全局光照）值。最初 Bakery 忽略它。
  • Remove ringing in Legacy light probes（移除 Legacy 光照探针振铃）：在 Legacy 模式下启用更柔和的光照探针卷积，以防止高对比度区域的伪影。
  • Always render reflection probes（始终渲染反射探针）：每次 Render/Render Light Probes 后自动渲染反射探针。
  • Ringing removal for L2 light probes（L2 光照探针振铃移除）：对 L2 光照探针应用去振铃。值越高，探针光照越平滑；这种平滑减少了伪影（如果存在）。
  • Put menu under Tools（将菜单放在 Tools 下）：将 Bakery 菜单放在 Tools 菜单下。

如果任何格式设置为 Asset 且启用了 mipmapping，将显示一个附加选项：

  • Maximum mipmap count（最大 mipmap 数量）：定义最大 mipmap 数量。例如，如果设置为 2，一张 8K 光照贴图将只有两个附加 mipmap：4K 和 2K。更低的分辨率将被省略，从而限制 mipmapping 期间的泄漏伪影。

蒙皮网格渲染器支持（Skinned mesh renderer support）

Bakery 自 v1.65 起支持蒙皮网格。但是，有一些限制：

  • 某些 Unity 版本不支持蒙皮网格上的 UV1，并静默忽略 “Generate lightmap UVs”。确保场景中使用的实际网格具有 UV1，并尽可能使用不重叠的 UV0；
  • UV 填充调整不适用于蒙皮网格（Unity 在尝试对它们调用 Unwrap 函数时似乎会崩溃）；
  • 蒙皮网格不能有逐顶点光照贴图（引擎不支持带蒙皮的 additionalVertexStreams）。

着色器微调（Shader Tweaks）

Bakery 提供可应用于 Unity 着色器的可选着色器修改，以改进光照贴图采样，并使实时光照更接近光照贴图。着色器微调菜单可以通过 Bakery->Shader Tweaks 访问。

这些选项将修补基础 Unity 着色器包含文件（来自 CGIncludes 文件夹），这些文件被大多数内置和第三方着色器使用。所有修改将影响用此编辑器版本打开的所有项目，但也可以轻松还原。着色器微调影响标准和 surface 着色器的工作方式。HDRP、LWRP 和其他 SRP 不受影响。

  • Use bicubic interpolation for lightmaps（为光照贴图使用双三次插值）：将使用双三次插值而不是默认的双线性。此微调可以很好地修复低分辨率光照贴图的许多锯齿边缘。目前它只在 DX11 和现代主机上工作，其他平台将继续使用双线性。

  • Use physical light falloff (forward)（使用物理光照衰减（前向））：用更物理正确的平方反比替换实时点/聚光灯的默认衰减。“Range” 只会在边缘附近轻微淡化它（与启用了 Physical Falloff 复选框的 Bakery 光源匹配）。只影响前向渲染器。更多细节见 Point Light Attenuation。
  • Use physical light falloff (deferred)（使用物理光照衰减（延迟））：同上，但只影响延迟渲染器。

Bakery 着色器（Bakery shaders）

Bakery 包含自己的着色器，支持顶点光照贴图以及 RNM 和 SH 方向模式。它还允许从方向数据计算近似的烘焙镜面反射。常规颜色光照贴图、阴影遮罩和 Dominant Direction 模式不需要 Bakery 着色器，因为这些功能大多数 Unity 着色器都已经支持。

标准渲染管线（Standard render pipeline）

Bakery/Standard：扩展常规 Standard 着色器。附加选项：

  • Allow Vertex Lightmaps（允许顶点光照贴图）：允许此材质用于顶点光照贴图。
  • Allow RNM Lightmaps（允许 RNM 光照贴图）：允许此材质用于 RNM 方向模式。
  • Allow SH Lightmaps（允许 SH 光照贴图）：允许此材质用于 SH 方向模式。

所有 “Allow” 开关都在着色器中启用某个代码路径。出于性能原因，建议一个材质只使用一个 “allow” 选项。

  • Enable Lightmap Specular（启用光照贴图镜面反射）：使用来自 Dominant Direction、RNM 或 SH 方向模式的数据计算烘焙镜面反射。注意由于缺乏信息，效果非常近似。如果你在 Unity 4 中使用过烘焙镜面反射，应该可以与之相比。它与高度扰动的法线贴图搭配效果最好，在平坦表面上效果不佳。
  • Enable VertexLM directional（启用顶点 LM 方向）：如果存在顶点光照贴图，指定 Dominant Direction 数据存储在顶点中并应被使用。
  • Enable VertexLM SH（启用顶点 LM SH）：如果存在顶点光照贴图，指定 SH 数据存储在顶点中并应被使用。
  • Enable VertexLM Shadowmask（启用顶点 LM 阴影遮罩）：如果存在顶点光照贴图，指定阴影遮罩存储在顶点中并应被使用。
  • Enable MonoSH（启用 MonoSH）：将方向贴图视为 MonoSH 贴图。
  • Non-linear SH（非线性 SH）：在 SH 方向模式下，此选项可以增强对比度（更接近真实值），但使着色器稍慢。此技巧基于 Geomerics 的 “Reconstructing Diffuse Lighting from Spherical Harmonic Data"（从球谐数据重建漫反射光照）论文。
  • Non-linear Light Probe SH（非线性光照探针 SH）：类似于 Non-linear SH，但用于光照探针。对于探针，最显著的优点是消除错误的负值。此问题经常出现在具有明亮 HDR 光源的高对比度场景中。这是球谐的固有局限，并非 Bakery 特有（即使用内置光照贴图器也可以得到类似伪影）。
  • Force Bicubic Filter（强制双三次过滤）：为所有附加贴图启用双三次过滤。要获得完整的双三次过滤（包括第一个颜色贴图），建议还在 Shader Tweaks 中启用它。

HDRP/URP 注意事项（Notes on HDRP/URP）

一旦包被导入 HDRP 或 URP 项目，通常可以立即使用，但有一些需要注意的事项：

  • 示例场景同时使用常规 Standard 着色器，某些情况下使用 “Bakery Standard” 着色器。HDRP 和 URP 提供了一种将项目着色器从 Standard 更新到 Lit 的机制，但它们不能从 Bakery Standard 升级。用来自 Bakery_ShaderGraphHDRP.unitypackage 或 Bakery_ShaderGraphURP.unitypackage 的材质替换 Bakery Standard 材质。
  • 在 HDRP 中，默认的 HDRI 天空强度很高（11），并且天空反射默认不被遮挡。再加上默认的眼睛适应，可能导致某些示例场景几乎不可见，因为它们是使用低得多的强度烘焙的。在这种情况下将 HDRI 天空强度降低到 1。HDRI 设置通常位于 Assets/HDRPDefaultResources/DefaultSettingsVolumeProfile。
  • 在 HDRP 中，如果示例场景中的光源太亮，请点击 Bakery 光源组件上的 “match real-time to lightmapped”。
  • 在 HDRP 中使用 OpenImageDenoise 2（最佳）或 OptiX 7 降噪器，因为它更适合高强度值。
  • 在 HDRP 中，“distance” 和常规 Shadowmask 可以在 Light 组件本身上切换，而不是在全局设置中。
  • 不要在 Skylight 上使用 “match” 按钮，因为 HDRP 使用非常特殊的程序化天空着色器。相反，用这种方式将其烘焙到 HDRI 中。
  • 建议在使用 HDRP 时始终将 Light Probe Mode 设置为 L2 或 L1，因为 HDRP 的渲染器未针对 Legacy 模式优化。
  • 最新版本的 HDRP/URP 有自己的 IES 文件导入器。由于资源类型不匹配，Unity 会将它们从使用旧版本保存的 Bakery IES 光源上拔掉，这意味着它们将显示为常规点光源。它们可以被重新插回并重新保存。

第 26 页：HDRP/URP 示例场景查看、升级 Bakery

Bakery 的示例场景是为内置渲染管线设计的，因此需要几个步骤才能在 HDRP/URP 中正确渲染它们。以下是一些提示；假设是带有默认 HDRP/URP 设置的新项目：

在 HDRP 中查看示例场景（Viewing example scenes on HDRP）

  • 导入 Bakery 后，将标准材质升级到 HDRP：Edit->Rendering->Materials->Convert All Built-in Materials To HDRP。
  • 将 Bakery_ShaderGraphHDRP.unitypackage 导入项目，因为它包含实现高级 Bakery 功能的特殊着色器图（经典颜色/方向/遮罩光照贴图不需要）。
  • 选择 DefaultSettingsVolumeProfile.asset。在 HDRI Sky 部分，将 Exposure Compensation 改为 1。否则默认 HDRP 与示例场景相比会太亮，并且由于此曝光调整它们会显示为黑色。
  • 在示例场景中选择光源时，HDRP 将初始化自己的光照数据。有时可能导致光源立即变得更亮。点击 “Match real-time to lightmapped” 以同步。
  • 在渲染光照探针之前将 Light Probe Mode 设置为 L2。
  • example_directional：将着色器改为 BakeryDirSpecGraph 以查看烘焙高光（或仅使用常规 HDRP/Lit 进行仅漫反射法线贴图）。删除球体，因为目前没有支持逐顶点方向的着色器图。
  • example_directional_MonoSH：将着色器改为 BakerySpecMonoSHGraph（或 BakeryMonoSHGraph 获得一个不带高光的稍便宜的版本）。删除球体，因为目前没有支持逐顶点 MonoSH 的着色器图。
  • example_RNM：将着色器改为 BakeryRNMGraph。
  • example_SH：将着色器改为 BakerySpecSHGraph（或 BakerySHGraph 获得一个不带高光的稍便宜的版本）。删除球体，因为目前没有支持逐顶点 SH 的着色器图。
  • example_mixed_directional_mode：类似地，MonoSH/RNM/SH 平面需要不同的图。
  • example_lights：将顶点光照贴图球体的着色器改为 BakeryVertexColorGraph。
  • example_prefabs_bake：无需进一步调整。
  • example_sectors：无需进一步调整。
  • example_shadowmask：选择 DirectLight 并点击 “Match real-time to lightmapped” 以修复亮度。在所有 HDRP 光源上将 Shadowmask Mode 设置为 Shadowmask。
  • example_sponza_day：将 OpenImageDenoise 2（或 Optix 7，如果不支持）设置为首选降噪器。
  • example_sponza_evening：将 OpenImageDenoise 2（或 Optix 7，如果不支持）设置为首选降噪器。
  • example_subtractive：HDRP 不支持相减模式。
  • example_volumes_simple：将火车着色器改为 BakeryVolumeSpecGraph（或 BakeryVolumeGraph 获得一个不带高光的稍便宜的版本）。
  • example_volumes_simple_shadowmask：HDRP 目前不支持阴影遮罩体积。
  • example_volumes_advanced：与 example_volumes_simple 相同。
  • example_translucency：场景大部分应该看起来正常。对于 “Dynamic sphere lit by volume”，将着色器设置为 BakeryVolumeGraph。

在 URP 中查看示例场景（Viewing example scenes on URP）

  • 导入 Bakery 后，将标准材质升级到 URP：打开 Assets/Bakery/examples/content，通过输入 “t:material” 选择所有材质，并只搜索下面的 “content” 文件夹。点击 Edit->Rendering->Materials->Convert Selected Built-in Materials To URP。
  • 将 Bakery_ShaderGraphURP.unitypackage 导入项目，因为它包含实现高级 Bakery 功能的特殊着色器图（经典颜色/方向/遮罩光照贴图不需要）。
  • example_directional：将着色器改为 BakeryURPLit，启用 “Bakery Lightmapped Specular”（或仅使用常规 URP/Lit 进行仅漫反射法线贴图）。删除球体，因为目前没有支持逐顶点方向的着色器图。
  • example_directional_MonoSH：将着色器改为 BakeryURPLit，将 Bakery Mode 设置为 MonoSH，启用 “Bakery Lightmapped Specular”。在顶点光照球体上也启用 “Per-vertex”。
  • example_RNM：将着色器改为 BakeryURPLit，将 Bakery Mode 设置为 RNM，启用 “Bakery Lightmapped Specular”。
  • example_SH：将着色器改为 BakeryURPLit，将 Bakery Mode 设置为 SH，启用 “Bakery Lightmapped Specular”。删除球体，因为目前没有支持逐顶点 SH 的着色器图。
  • example_mixed_directional_mode：类似地，使用 BakeryURPLit 并设置不同的 Bakery Mode（MonoSH、RNM、SH）。非方向/主方向/烘焙法线贴图可以使用常规 URP/Lit。
  • example_lights：无需进一步调整。
  • example_prefabs_bake：无需进一步调整。
  • example_sectors：无需进一步调整。
  • example_shadowmask：与内置管线类似，取消勾选 Bakery 窗口（或项目 Quality Settings）中的 Distance Shadowmask，以在相机附近看到实际的烘焙/实时阴影混合。
  • example_sponza_day：在树叶材质上启用 alpha clipping。
  • example_sponza_evening：与 example_sponza_day 相同。
  • example_subtractive：无需进一步调整。
  • example_volumes_simple：将火车着色器改为 BakeryURPLit 并将 Bakery Mode 设置为 Volume。可选地启用 “Bakery Lightmapped Specular”。
  • example_volumes_simple_shadowmask：与 example_volumes_simple 相同，但还要启用 “Volume Shadowmask”。
  • example_volumes_advanced：与 example_volumes_simple 相同。
  • example_translucency：场景大部分应该看起来正常。对于 “Dynamic sphere lit by volume”，将着色器设置为 BakeryURPLit 并将 Bakery Mode 设置为 Volume。

升级 Bakery（Upgrading Bakery）

升级资源时，建议遵循以下步骤：

  • 关闭 Bakery 窗口。
  • 关闭 Unity。
  • 重新打开它。
  • 导入更新后的包。

注意，如果不先关闭 Unity，导入可能会因为 DLL 文件被锁定而失败（打印诸如 “alphabuffergen.dll: Access is denied.” 的消息）。

基本用法（Basic usage）

获取和修改渲染设置：

ftLightmapsStorage storage = ftRenderLightmap.FindRenderSettingsStorage();

可用设置的完整列表可以在 ftLightmapsStorage.cs 中看到。

获取光照贴图器实例并（重新）加载设置：

ftRenderLightmap bakery = ftRenderLightmap.instance != null ? ftRenderLightmap.instance : new ftRenderLightmap();
bakery.LoadRenderSettings();

渲染光照贴图（如果探针设置为 L1 或 L2 模式，也渲染探针）：

bakery.RenderButton(bool showMsgWindows)

仅渲染光照探针：

bakery.RenderLightProbesButton(bool showMsgWindows)

仅渲染反射探针：

bakery.RenderReflectionProbesButton(bool showMsgWindows)

showMsgWindows 告知是否可以显示任何对话框/确认。如果设置为 false，则被抑制。

检查烘焙是否正在进行：

ftRenderLightmap.bakeInProgress

使用示例请查看 Batch Scene Baker 脚本。

ftGlobalStorage gstorage = ftLightmaps.GetGlobalStorage()

ftLightmapsStorage.CopySettings(ftLightmapsStorage src, ftGlobalStorage dest)

ftLightmapsStorage.CopySettings(ftGlobalStorage src, ftLightmapsStorage dest)

事件（Events）

脚本可以订阅 ftRenderLightmap 类中的静态事件。

完整 Render 之前调用：

EventHandler OnPreFullRender

在 Legacy 光照探针模式下，每个光照探针渲染之前调用。ProbeEventArgs 是一个包含 pos 字段（当前光照探针位置）的结构体：

EventHandler<ProbeEventArgs> OnPreRenderProbe

Legacy 光照探针渲染完成后调用：

EventHandler OnFinishedProbes

完整 Render 结束后调用：

EventHandler OnFinishedFullRender

EventHandler OnPreReflectionProbeRender

反射探针渲染完成后调用：

EventHandler OnFinishedReflectionProbes
