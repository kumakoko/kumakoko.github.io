UniTask Forget() 作用与示例

UniTask 是基于 ValueTask 为 Unity 实现的异步库，Forget() 是 UniTask 扩展方法。

Forget() 是干嘛的

  1. UniTask 本身是可等待异步对象，如果你不 await，也不接收返回变量，编译器会报警告：未观察到的 UniTask，提示你这个异步任务被丢弃了。
  2. Forget() 的作用：消除编译器警告，告诉代码：这个异步任务我不等待、不处理返回值、也不捕获异常，就让它后台跑。
  3. ⚠️重点风险：
  • 调用 Forget() 之后，任务内部抛出的异常不会被捕获，会直接在Unity控制台报错。
  • 它不会阻塞主线程，不会等待任务完成，调用之后立刻往下执行，任务继续后台运行。
  • 只适合：你不需要等待结果、不在乎失败与否的异步操作。

对比：

  • await xxxUniTask()：等待执行完成，可以捕获异常；
  • xxxUniTask.Forget()：不等待，直接放行，吃掉“未await警告”，异常仍然会爆出。

安装说明

要使用 Forget，需要引入命名空间：

using Cysharp.Threading.Tasks;

示例1：基础 Forget 使用

using UnityEngine;
using Cysharp.Threading.Tasks;

public class UniTaskForgetDemo : MonoBehaviour
{
    void Start()
    {
        // 如果直接调用 DoSomeWork(); 不await，编译器会警告
        // DoSomeWork(); 

        // Forget：消除警告，任务后台跑，Start立刻执行完毕，不会等3秒
        DoSomeWork().Forget();
        
        Debug.Log("Start函数执行完毕，不会等待异步任务！");
    }

    // 模拟耗时异步任务
    async UniTask DoSomeWork()
    {
        Debug.Log("任务开始");
        await UniTask.Delay(3000); // 等待3秒
        Debug.Log("3秒后任务执行完成");
    }
}

输出顺序：

Start函数执行完毕，不会等待异步任务！
任务开始
// 3秒后打印
3秒后任务执行完成

示例2：Forget 异常会直接抛出（重要坑）

async UniTask TaskWithError()
{
    await UniTask.Delay(1000);
    throw new System.Exception("任务里面出错了！");
}

void TestError()
{
    // Forget不会捕获异常，1秒后Unity控制台直接报异常
    TaskWithError().Forget();
}

这里异常不会被吞掉，会在Unity报错，很多新手以为Forget会吞异常，这是高频踩坑点。

如果想要忽略异常，不要只用Forget，搭配 SuppressCancellationThrow / TryCatch

方式A：WithSuppressCancellationThrow（只忽略取消异常，普通异常依旧抛出）

DoSomeWork().WithSuppressCancellationThrow().Forget();

方式B：内部try‑catch，真正吞掉异常

async UniTask SafeTask()
{
    try
    {
        await UniTask.Delay(1000);
        throw new System.Exception("出错");
    }
    catch(System.Exception e)
    {
        Debug.LogWarning($"捕获异常：{e.Message}");
    }
}

void CallSafe()
{
    SafeTask().Forget();
}

什么时候该用 Forget？

✅适合场景：

  1. UI点击触发一个动画/音效，我不需要等待它结束，也不需要返回结果；
  2. 触发一个后台次要操作，不阻塞当前逻辑。

❌不建议用 Forget：

  1. 需要知道任务是否成功；
  2. 需要处理返回结果；
  3. 需要处理异常；

这种场景应该用 await，或者存 UniTask 变量后续 await。

补充：和 fire and forget（即发即弃）概念

UniTask 的 .Forget() 就是实现 fire‑and‑forget 模式。

原生C# async void 类似，但 async void 在Unity里异常很难调试；UniTask推荐优先用 UniTask+Forget 替代 async void。

反例，不推荐写 async void

// 不推荐！async void异常很难追踪
async void BadExample()
{
    await UniTask.Delay(1000);
}

小结

  1. Forget()：消除「未await UniTask」编译器警告，不等待任务完成；
  2. 不会捕获异常，任务抛异常依然会报错；
  3. 仅用于即发即弃、不需要等待结果的异步；
  4. 需要处理异常就在async函数内部写try‑catch。

UniTask.Await() vs Forget()

先厘清：Await() 是实例方法 uniTask.Await()；而 await 是C#关键字 await uniTask，两者不一样，很多人混淆。

  • await：C#语言关键字，必须放在 async 函数内
  • .Await()：UniTask 的实例方法，返回值就是 UniTask，等价于本身，一般很少直接手写调用
  • .Forget()：扩展方法，即发即弃，消除警告

重点：task.Await() ≠ C# await关键字

1. 三者概念区分

方式是否等待任务完成是否阻塞调用方法是否处理异常编译器警告使用场景
await task（C#关键字）✅等待完成会挂起当前async方法，后面代码等任务结束才跑可以try‑catch捕获异常无需要等待异步结果，最常用
task.Await()✅等待完成不会自动挂起！它只是返回自身UniTask对象，你不写await就等于没等不捕获，只是返回任务对象⚠️警告，未await极少直接调用；主要用于链式语法
task.Forget()❌不等待，直接放行调用处立刻继续往下跑，任务后台跑异常直接抛出，不会吞异常✅消除未await警告fire‑and‑forget，即发即弃

坑点：task.Await() 只是返回 this，单纯写 myTask.Await(); 不写前面的 await 关键字，等于完全没有等待！还会报未await警告。

// 错误！很多人误以为 .Await() 会等待，这行不会等待！
myUniTask.Await(); 

// 正确，真正等待：关键字await + .Await()返回的任务对象
await myUniTask.Await();

.Await() 设计目的更多是链式调用，比如：

// 链式写法，Await返回任务，交给await关键字等待
await UniTask.Delay(1000).Await();

日常业务代码几乎不会手动写 .Await()，直接 await UniTask.Delay(1000)。

2. Forget()

// 调用后立刻往下执行，任务后台跑，不等待
DoWork().Forget();
Debug.Log("立刻执行，不等任务");
  • 当前函数不会暂停，执行Forget之后马上执行下一行代码；
  • 消除编译器“未观察UniTask”警告；
  • 任务内部异常依然会抛到Unity控制台；
  • 不需要结果、不需要等待，“触发就不管”。

3. await关键字（最常用）

await DoWork();
Debug.Log("要等DoWork全部做完才会走到这里");
  • 当前async函数会挂起，让出主线程；任务完成之后，回到原线程继续执行后面代码；
  • 可以用 try‑catch 捕获任务异常；
  • 需要拿到结果、要等待逻辑完成的时候必须用。

4. 完整可运行对比示例

using UnityEngine;
using Cysharp.Threading.Tasks;

public class AwaitVsForget : MonoBehaviour
{
    void Start()
    {
        Debug.Log("=====测试Forget=====");
        TestForget().Forget();

        Debug.Log("=====测试Await实例方法（错误示范）=====");
        TestAwaitInstance();
    }

    // Forget测试
    async UniTask TestForget()
    {
        Debug.Log("Forget:开始");
        await UniTask.Delay(1500);
        Debug.Log("Forget:1.5秒后执行完毕");
    }

    void TestAwaitInstance()
    {
        var t = UniTask.Delay(1500);
        // 仅仅调用 .Await()，没有写 await关键字，不会等待！
        t.Await(); 
        Debug.Log("这里不会等1.5秒，直接打印！");
    }

    // 正确使用Await()，搭配await关键字
    async UniTask CorrectAwaitUsage()
    {
        // .Await()返回任务对象，再用关键字await去等待
        await UniTask.Delay(1500).Await();
        Debug.Log("等待1.5秒结束");
    }
}

Forget:开始
=====测试Await实例方法（错误示范）=====
这里不会等1.5秒，直接打印！
// 1.5秒之后
Forget:1.5秒后执行完毕

5. 关键总结

  1. task.Await()只是返回任务本身，本身不具备等待能力；真正等待靠C#的await关键字。
    • ❌ task.Await(); 不会等待；
    • ✅ await task; 才会等待。
  2. .Forget()：不等待，消除警告，后台运行任务，即发即弃。
  3. await task：挂起async函数，等待任务完成，支持异常捕获，业务首选。

使用建议

  • 99%场景直接使用 await xxx，不要手写 .Await()；
  • 只有不需要等待结果，才用 .Forget()；
  • 千万不要把 task.Await() 当成等待函数，这是高频踩坑。

补充小提示

UniTask还有 Forget(/*IProgress*/) 重载，可以接收进度回调，同样不会等待任务。

SomeTask().Forget(progress =>
{
    Debug.Log($"进度 {progress}");
});
