UniTask 包装回调式异步函数

很多老API、第三方SDK都是回调(callback)模式：调用一个方法，传进去OnSuccess、OnFail回调，函数直接返回void，不能await。 UniTask提供 UniTaskCompletionSource 来把回调接口封装成可 await 的 UniTask，这是标准做法。

命名空间：using Cysharp.Threading.Tasks;

核心类：UniTaskCompletionSource

  • UniTaskCompletionSource<T>：用来手动控制UniTask的完成/失败/取消
  • .Task 属性：得到可供外部await的 UniTask<T>
  • 完成：TrySetResult(T result) → 任务成功结束，返回结果
  • 失败：TrySetException(Exception ex) → 任务抛出异常
  • 取消：TrySetCanceled() → 任务变成取消状态

⚠️注意：全部是TrySetXXX，代表只能设置一次，多次调用会忽略。

示例1：无返回值回调（成功/失败回调）

假设原有回调风格函数：

// 原始回调风格API，不是async，靠回调通知结果
void OldAsyncMethod(Action onSuccess, Action<string> onError)
{
    // 模拟异步，比如网络请求、SDK加载
    UnityEngine.Debug.Log("开始执行旧版回调接口");
    UnityEngine.Time.time;
    // 模拟延迟后回调，真实场景是SDK内部触发
    UniTask.Delay(2000).Forget(() =>
    {
        bool ok = true;
        if (ok)
            onSuccess?.Invoke();
        else
            onError?.Invoke("出错啦");
    });
}

包装成 UniTask

// 把回调API封装成可await的UniTask
UniTask WrapOldAsyncMethod()
{
    // 创建完成源
    var tcs = new UniTaskCompletionSource();

    // 调用旧回调接口
    OldAsyncMethod(
        onSuccess: () =>
        {
            // 成功，标记任务完成
            tcs.TrySetResult();
        },
        onError: (errMsg) =>
        {
            // 失败，抛出异常给await方捕获
            tcs.TrySetException(new System.Exception(errMsg));
        }
    );

    // 返回可供await的任务
    return tcs.Task;
}

使用包装后的方法

async UniTask Test()
{
    try
    {
        await WrapOldAsyncMethod();
        Debug.Log("执行成功");
    }
    catch (System.Exception e)
    {
        Debug.LogError($"执行失败：{e.Message}");
    }
}

示例2：带返回结果的回调 UniTask

原始回调，成功会返回数据：

// 旧API：成功回调带回string结果
void OldGetData(Action<string> onSuccess, Action<int> onError)
{
    UniTask.Delay(1500).Forget(() =>
    {
        onSuccess?.Invoke("服务器返回的数据");
        // onError?.Invoke(404);
    });
}

包装：

UniTask<string> WrapOldGetData()
{
    var tcs = new UniTaskCompletionSource<string>();

    OldGetData(
        onSuccess: data =>
        {
            tcs.TrySetResult(data);
        },
        onError: code =>
        {
            tcs.TrySetException(new System.Exception($"错误码：{code}"));
        }
    );

    return tcs.Task;
}

调用：

async UniTask Run()
{
    string res = await WrapOldGetData();
    Debug.Log(res);
}

示例3：支持CancellationToken取消（非常重要Unity场景）

Unity很多时候需要MonoBehaviour销毁时取消异步，UniTaskCompletionSource支持监听取消令牌。

UniTask<string> WrapOldGetDataWithCancel(CancellationToken token)
{
    var tcs = new UniTaskCompletionSource<string>();

    // 如果外部CancellationToken触发取消，把任务置为取消
    if (token.IsCancellationRequested)
    {
        tcs.TrySetCanceled();
        return tcs.Task;
    }

    // 注册取消回调
    var registration = token.Register(() =>
    {
        tcs.TrySetCanceled();
    });

    OldGetData(
        onSuccess: data =>
        {
            registration.Dispose(); // 取消注册，防止内存泄漏
            tcs.TrySetResult(data);
        },
        onError: code =>
        {
            registration.Dispose();
            tcs.TrySetException(new System.Exception($"错误码：{code}"));
        }
    );

    return tcs.Task;
}

调用时传入Mono的取消token（this.GetCancellationTokenOnDestroy()）：

// 在MonoBehaviour中调用
await WrapOldGetDataWithCancel(this.GetCancellationTokenOnDestroy());

当GameObject销毁，token取消，await处抛出OperationCanceledException。

简化工具：UniTask.FromCallback

UniTask还提供了 UniTask.FromCallback 辅助重载，不用手写完整UniTaskCompletionSource，适合简单回调。

// FromCallback 包装简单回调
UniTask FromCallbackDemo()
{
    return UniTask.FromCallback<Action>(callback =>
    {
        // callback就是onSuccess，把它传给旧接口
        OldAsyncMethod(callback, err => { });
    });
}

复杂多回调、带错误处理，还是优先用 UniTaskCompletionSource，可读性更好。

常见踩坑点

  1. 不要多次调用 TrySetResult / TrySetException，只会第一次生效。
  2. 回调可能被多次调用（有些SDKbug会多次回调），用TryXXX就安全，不会报错。
  3. 如果使用CancellationToken，一定要Dispose注册的registration，避免内存泄漏。
  4. 不要 Forget() 包装出来的任务，如果内部异常，依然会抛到控制台；需要异常捕获请在外层try‑catch。
  5. UniTaskCompletionSource不要保存为成员变量，一般是局部变量，每次调用新建实例。

什么时候用这套模式

  • SDK、第三方库只提供回调，没有async/await版本
  • 旧项目遗留的Action回调异步接口
  • 自己封装一些IO、网络、加载逻辑，想要统一await写法

简单总结： UniTaskCompletionSource 就是一座桥：回调来了手动SetResult，外部就可以await这个Task。

如果你需要，我可以写一个真实场景例子：比如把Unity的WWW/UnityWebRequest回调模式包装成UniTask。

UniTaskCompletionSource 包装 Task 异步函数

先说一个关键点：绝大多数情况，不需要用 UniTaskCompletionSource 去包装 Task。 UniTask 原生就提供 UniTask.WaitForTask() / AsUniTask() 扩展，可以直接把 .NET Task / Task<T> 转为 UniTask，这是最高效方式。

UniTaskCompletionSource 的定位是：给回调、事件驱动这种没有Task的场景手动构造任务； 但你依然可以用它来包装 Task，用于理解原理，或者需要自定义拦截、捕获、转换完成逻辑的场景。

命名空间：

using Cysharp.Threading.Tasks;
using System.Threading.Tasks;

方式1：推荐：原生内置转换（不要手写UniTaskCompletionSource）

Task → UniTask

// .NET Task
Task DotNetTask()
{
    return Task.Delay(1000);
}

// 直接转 UniTask
UniTask ut = DotNetTask().AsUniTask();
await ut;

Task → UniTask

Task<string> DotNetTaskT()
{
    return Task.FromResult("hello");
}

UniTask<string> ut2 = DotNetTaskT().AsUniTask();
string res = await ut2;

AsUniTask() 底层做了桥接，没有额外堆分配（大部分路径），性能远好于自己手写 UniTaskCompletionSource。

方式2：使用 UniTaskCompletionSource 手动包装 Task（原理演示）

⚠️仅当你需要拦截任务完成、做额外逻辑时才这么写，普通转换不要这么写。

原理：

  1. 创建 UniTaskCompletionSource<T>
  2. 给原始 .NET Task 注册 ContinueWith 回调
  3. 在回调里面：成功就 TrySetResult；异常就 TrySetException；取消就 TrySetCanceled
  4. 返回 tcs.Task

示例1：包装无返回值 Task

// 原始 .NET Task 方法
Task SomeDotNetTask()
{
    return Task.Delay(1200);
}

// 使用 UniTaskCompletionSource 手动包装 Task
UniTask WrapTaskByTcs()
{
    var tcs = new UniTaskCompletionSource();

    Task task = SomeDotNetTask();

    task.ContinueWith(t =>
    {
        if (t.IsCanceled)
        {
            tcs.TrySetCanceled();
        }
        else if (t.Exception != null)
        {
            // AggregateException 取出内部异常
            tcs.TrySetException(t.Exception.InnerException!);
        }
        else
        {
            tcs.TrySetResult();
        }
    }, TaskScheduler.Current);

    return tcs.Task;
}

// 使用
async UniTask Test()
{
    await WrapTaskByTcs();
    Debug.Log("done");
}

示例2：包装带返回值 Task

Task<int> SomeDotNetTaskWithResult()
{
    return Task.FromResult(666);
}

UniTask<int> WrapTaskTByTcs()
{
    var tcs = new UniTaskCompletionSource<int>();

    Task<int> task = SomeDotNetTaskWithResult();

    task.ContinueWith(t =>
    {
        if (t.IsCanceled)
        {
            tcs.TrySetCanceled();
        }
        else if (t.Exception != null)
        {
            tcs.TrySetException(t.Exception.InnerException!);
        }
        else
        {
            tcs.TrySetResult(t.Result);
        }
    }, TaskScheduler.Current);

    return tcs.Task;
}

调用

int val = await WrapTaskTByTcs();
Debug.Log(val);

方式3：带上 CancellationToken 的手动包装

如果需要支持取消令牌：

UniTask<int> WrapTaskWithCancel(CancellationToken token)
{
    var tcs = new UniTaskCompletionSource<int>();

    var netTask = SomeDotNetTaskWithResult();

    // 外部取消触发
    var reg = token.Register(() =>
    {
        tcs.TrySetCanceled();
    });

    netTask.ContinueWith(t =>
    {
        reg.Dispose(); // 释放注册，防止泄漏
        if (t.IsCanceled)
            tcs.TrySetCanceled();
        else if (t.Exception != null)
            tcs.TrySetException(t.Exception.InnerException!);
        else
            tcs.TrySetResult(t.Result);
    }, TaskScheduler.Current);

    return tcs.Task;
}

关键对比：什么时候用 AsUniTask，什么时候手动 TCS 包装 Task

场景方案
只是简单把 Task 转 UniTask，不需要额外逻辑✅ task.AsUniTask()（官方推荐，性能最好）
需要在任务完成前后插入自定义逻辑、拦截异常、修改返回值✅ 手动 UniTaskCompletionSource + ContinueWith
原始不是Task，是回调Action回调✅ UniTaskCompletionSource（必须用这个）

❌不推荐：日常转换 Task 还手写 UniTaskCompletionSource，会引入额外对象分配，增加代码量，还容易漏处理异常、取消。

容易踩的坑

  1. Task.Exception 是 AggregateException，要取 .InnerException，不要直接把 AggregateException 塞给 TrySetException，否则 await 拿到的异常包装层级不对。
  2. ContinueWith 的调度器：Unity 要注意线程，.AsUniTask() 会自动切回Unity主线程；手写 ContinueWith 如果不处理，回调可能跑在线程池，UniTaskCompletionSource本身是线程安全，但后续await恢复上下文要注意。
  3. TrySetXXX 系列方法只能生效一次，多次调用直接忽略，适合防止任务被多次完成。
  4. 不要把 UniTaskCompletionSource 存为成员变量，每次调用都新建局部实例。

补充反向：UniTask → .NET Task

如果你需要把 UniTask 转成 .NET Task：

UniTask ut = UniTask.Delay(1000);
Task netTask = ut.AsTask();

小结

  1. 把 .NET Task 转为 UniTask，优先用扩展方法 AsUniTask()，不要自己写 UniTaskCompletionSource。
  2. UniTaskCompletionSource 本质是手动“触发完成信号”，主要用于回调式API；包装Task属于附加用法，适合需要拦截处理的场景。
  3. 手写 ContinueWith 时注意处理 AggregateException、取消、释放CancellationToken注册，否则会内存泄漏、异常错乱。

UniTaskCompletionSource 包装事件模式异步

事件模式：经典的 .NET / Unity 异步模式，不是回调参数，是事件订阅。 调用方法之后，去订阅某个事件（OnCompleted、OnSuccess、OnError），等事件触发代表异步结束。 典型：Unity的WWW旧版、一些SDK：xxx.Load(); xxx.OnFinish += OnFinishHandler;

核心难点：

  1. 订阅事件，任务完成后必须取消订阅，否则内存泄漏、多次触发会多次调用SetResult。
  2. 要处理成功事件、失败事件；还要处理CancellationToken取消。
  3. 事件可能触发多次，要用TrySetXXX安全方法。

命名空间

using Cysharp.Threading.Tasks;
using System;

模拟一个事件式异步类（示例源）

这是真实业务里常见的事件驱动对象，没有Task，没有回调入参，靠事件通知结果：

/// <summary>
/// 模拟事件驱动的异步工具
/// </summary>
public class EventAsyncLoader
{
    // 事件：加载完成
    public event Action<string> OnLoadSuccess;
    // 事件：加载失败
    public event Action<int> OnLoadFailed;

    public void StartLoad(string url)
    {
        // 模拟异步网络，延迟后触发事件
        UniTask.Delay(2000).Forget(() =>
        {
            // 模拟成功
            OnLoadSuccess?.Invoke($"[{url}]加载完成数据");
            // 模拟失败：OnLoadFailed?.Invoke(500);
        });
    }
}

使用原始事件写法（丑陋）：

var loader = new EventAsyncLoader();
loader.OnLoadSuccess += data =>
{
    Debug.Log(data);
};
loader.OnLoadFailed += code =>
{
    Debug.LogError(code);
};
loader.StartLoad("test");

我们目标：把它包装成 UniTask<string> LoadAsync(string url)，直接 await。

使用 UniTaskCompletionSource 包装事件

关键点：

  1. 每次调用创建局部 UniTaskCompletionSource<string>
  2. 订阅成功、失败事件；事件内部调用 TrySetResult / TrySetException
  3. 任务无论成功/失败/取消，都必须取消事件订阅，防止内存泄漏！
  4. 如果外部传入CancellationToken，取消时要取消事件订阅 + TrySetCanceled
public static UniTask<string> LoadAsync(this EventAsyncLoader loader, string url, CancellationToken cancellationToken = default)
{
    var tcs = new UniTaskCompletionSource<string>();

    // 事件处理器，存局部变量，方便注销
    Action<string> onSuccess = null;
    Action<int> onFailed = null;

    // 取消令牌注册
    CancellationTokenRegistration registration = default;

    // 清理函数：解订阅、释放注册，无论成功/失败/取消都要执行
    void CleanUp()
    {
        loader.OnLoadSuccess -= onSuccess;
        loader.OnLoadFailed -= onFailed;
        registration.Dispose();
    }

    onSuccess = (result) =>
    {
        CleanUp();
        tcs.TrySetResult(result);
    };

    onFailed = (errorCode) =>
    {
        CleanUp();
        tcs.TrySetException(new Exception($"加载失败，错误码：{errorCode}"));
    };

    // 订阅事件
    loader.OnLoadSuccess += onSuccess;
    loader.OnLoadFailed += onFailed;

    // 如果外部触发取消
    if (cancellationToken.CanBeCanceled)
    {
        registration = cancellationToken.Register(() =>
        {
            CleanUp();
            tcs.TrySetCanceled();
        });
    }

    // 启动原始事件异步操作
    loader.StartLoad(url);

    return tcs.Task;
}

使用包装后的方法

async UniTask TestEventWrapper()
{
    var loader = new EventAsyncLoader();
    try
    {
        // MonoBehaviour中可以传入 this.GetCancellationTokenOnDestroy()
        string data = await loader.LoadAsync("http://xxx", this.GetCancellationTokenOnDestroy());
        Debug.Log($"获取结果：{data}");
    }
    catch (OperationCanceledException)
    {
        Debug.Log("任务被取消");
    }
    catch (Exception ex)
    {
        Debug.LogError(ex.Message);
    }
}

重点坑点解释

  1. 必须手动 -= 取消事件订阅 事件订阅是强引用，如果不注销：即使任务结束，事件还持有handler，对象不会GC，造成内存泄漏。

回调模式不需要，事件模式这是头等大坑。

  1. 用局部变量保存handler 不能直接在+=写lambda，否则外面-=无法匹配同一个委托实例，无法注销。
// ❌错误写法，无法 -= 取消订阅
loader.OnLoadSuccess += res => { };

  1. 使用TrySetResult，不要SetResult 有些SDK/组件会重复触发事件，TrySetXXX只会第一次生效，不会抛异常。

  2. CleanUp 统一释放 成功、失败、取消三条路径都调用CleanUp，保证事件一定解订阅，CancellationTokenRegistration一定Dispose。

变体：只靠单个“完成事件”，需要自己判断成功失败标记

有些组件只有一个OnCompleted事件，事件参数包含成功/失败状态：

// 假设事件
public event Action<LoadResult> OnCompleted;

public class LoadResult
{
    public bool isSuccess;
    public string data;
    public int errorCode;
}

包装示例片段：

var tcs = new UniTaskCompletionSource<string>();
Action<LoadResult> onCompleted = null;
void CleanUp() { loader.OnCompleted -= onCompleted; }

onCompleted = res =>
{
    CleanUp();
    if (res.isSuccess)
    {
        tcs.TrySetResult(res.data);
    }
    else
    {
        tcs.TrySetException(new Exception($"err:{res.errorCode}"));
    }
};
loader.OnCompleted += onCompleted;
loader.StartLoad();
return tcs.Task;

对比三种场景使用 UniTaskCompletionSource

异步模式特征UniTaskCompletionSource要点
回调模式调用函数时传入Action回调回调内SetResult；不需要取消事件订阅
Task模式返回Task对象优先用AsUniTask()，尽量不用TCS包装Task
事件模式调用方法，订阅对象的事件重点：保存委托、完成后必须-=取消订阅，防止内存泄漏

补充：UniTask 有没有辅助工具简化事件包装？

UniTask没有像FromCallback专门封装事件的API。

事件模式必须手写上面这套模板：保存委托、订阅、CleanUp解订阅。 因为事件的注销逻辑是强业务相关，库无法封装。

总结模板（可以直接复制套用）

包装事件异步的标准模板步骤：

  1. 新建局部 UniTaskCompletionSource<T>
  2. 定义局部委托变量保存事件handler
  3. 写统一CleanUp函数：取消事件订阅 + Dispose CancellationTokenRegistration
  4. handler内部先调用CleanUp，再TrySetResult / TrySetException
  5. CancellationToken.Register触发时调用CleanUp + TrySetCanceled
  6. 调用原始异步启动方法，返回tcs.Task

最容易踩坑：忘记-=取消事件订阅，内存泄漏；lambda直接订阅导致无法取消。
