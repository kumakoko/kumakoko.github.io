SceneCollectionManager类的作用分析

SceneCollectionManager 是一个 ScriptableObject（可序列化资源），它是 WorldStreamer 2 系统中的瓦片数据容器与运行时状态管理者。如果说 Streamer 是流送系统的"大脑"（决策调度），那么 SceneCollectionManager 就是"记忆体"（存储配置 + 记录状态）。

一、核心定位

继承自 ScriptableObject，通过 Assets/Create/Scene Collection Manager 菜单创建为 .asset 文件。一个 Streamer 可以持有多个 SceneCollectionManager（即多个"层"，如地形层、植被层、碰撞层），每层独立配置流送参数。

它的双重角色：

  1. 配置资产（编辑器下）：存储瓦片的静态信息（尺寸、范围、场景名列表）
  2. 运行时状态持有者（运行时）：记录当前玩家所在网格、已加载瓦片列表、正在加载的数量

二、主要职责

1. 存储瓦片静态配置

字段作用
xSize / ySize / zSize单个瓦片的世界尺寸（默认 500）
xSplitIs / ySplitIs / zSplitIs该层是否沿对应轴分割
names该层包含的所有场景文件名数组（如 Scene_x0_z0.unity）
prefixScene场景名前缀（默认 "Scene"）
path场景资源路径
priority该层的加载优先级（多层时决定谁先加载）
loadingRange加载范围（以网格为单位，如 3 表示周围 3 圈）
deloadingRange卸载范围（超出此范围的瓦片被卸载）
loadingRangeMin + useLoadingRangeMin环形流送——中心挖空区域
xLimitsx / xLimitsy 等该层瓦片在 X/Y/Z 轴上的索引边界
unloadRangeConnect跨层联动卸载（如高层加载时卸载底层同位置瓦片）
maxParallelSceneLoading该层最大并发加载数

2. 构建瓦片查找字典 —— PrepareScenesArray()

PrepareScenesArray() 将 names 字符串数组解析为 Dictionary<Vector3Int, SceneSplit> scenesArray：

  • 调用 Streamer.SceneNameToPos 从场景名（如 Scene_x2_z-1.unity）解析出网格坐标 (x, y, z)
  • 为每个场景创建 SceneSplit 对象，存入字典
  • 若启用了 overideRangeLimit（循环模式下），还会用取模运算填充边界外的虚拟瓦片，使玩家走到世界边缘时能从对侧"穿回"

3. 计算流送边界 —— CalculateLoadingLimits()

CalculateLoadingLimits() 根据配置和循环模式计算：

  • xLoadingLimitx / xLoadingLimity：X 轴加载范围的上下界
  • xLoadingRange：加载范围总长度
  • 循环模式下会扩展边界以容纳 deloadingRange，避免边缘瓦片刚加载就被卸载

4. 玩家网格定位 —— CheckPosition() / GetTilePosition()

CheckPosition() 将玩家世界坐标转换为网格索引：

xPos = FloorToInt(pos.x / xSize)

并与上次记录的 xPos/yPos/zPos 比较，若变化则返回 true，触发 Streamer 的加载/卸载流程。

5. 运行时状态管理

字段作用
xPos / yPos / zPos当前玩家所在网格索引
loadedScenes当前已加载的 SceneSplit 列表
currentlySceneLoading当前正在加载的瓦片数（用于并发控制）
scenesArray全部瓦片的查找字典

6. 编辑器工具方法

  • GetSceneCollectionWolrdLimits()：返回该层瓦片的世界坐标边界
  • ResetPosition()：将 xPos/yPos/zPos 重置为 int.MinValue，强制下次位置检查触发加载
  • SceneNameToVectorIntPos()：静态工具，场景名转坐标

三、与 Streamer 的协作关系

Streamer (调度者)
    │
    ├─ sceneCollectionManagers[]  ← 持有多个 SCM
    │
    ├─ PrepareScenesArray()  →  调用每个 SCM 的 CalculateLoadingLimits + PrepareScenesArray
    │
    ├─ CheckPositionTiles()
    │    └─ 遍历 SCM.CheckPosition(pos)  →  判断玩家是否跨格
    │
    ├─ SceneLoading()
    │    └─ 遍历 SCM，读取 scm.loadingRange / scm.scenesArray
    │         └─ scm.loadedScenes.Add(split)
    │
    └─ SceneUnloading()
         └─ 遍历 SCM.loadedScenes，对比 deloadingRange
              └─ scm.loadedScenes.Remove(split)

关键点：Streamer 不直接持有瓦片数据，所有瓦片的"在哪里"、“加载了哪些”、“加载范围多大"都由各 SceneCollectionManager 自行维护。Streamer 只负责遍历所有层并发起加载/卸载指令。

四、设计特点

  1. 数据与逻辑分离：SceneCollectionManager 是纯数据+轻量计算，不含 MonoBehaviour 生命周期，可作为资产在多个场景/工程间复用
  2. 多层独立：每个 SceneCollectionManager 可独立配置尺寸、范围、优先级，支持地形/植被/碰撞等分层流送
  3. 循环世界支持：通过 mod 取模在 scenesArray 中填充镜像瓦片，实现无缝循环
  4. 跨层联动：unloadRangeConnect 允许一层的加载触发另一层同位置瓦片的卸载（如加载高精度地形时卸载低精度）

五、总结

SceneCollectionManager 是流送系统的"瓦片数据层”：它既作为可编辑的配置资产定义了某一层世界的瓦片划分规则（尺寸、范围、场景列表），又在运行时维护该层的流送状态（玩家当前网格、已加载瓦片、并发计数）。Streamer 通过组合多个 SceneCollectionManager 实现多层世界的独立流送，而 SceneCollectionManager 本身不执行任何异步加载操作，只提供数据和判定，职责清晰。
