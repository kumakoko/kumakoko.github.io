World Streamer 2 最本质的方法理念

Table of Contents

  • 二、组织方式：SceneCollectionManager
  • 三、加载流程
  • 四、卸载流程
  • 五、附加能力（不止是简单分块加载）
  • 总结

问：从代码来看，WorldStreamer插件，其本质是不是把大场景分割成小块，然后用一套组织方式和加载方式，动态地只加载玩家视野范围内的若干小块？

从代码来看，WorldStreamer插件的核心原理确实是：把大场景分割成小块，然后动态地只加载玩家视野范围内的若干小块。详细解释如下：

  1. 场景分割阶段：

    • 编辑器中有一个 SceneSplitter 工具，将大场景按网格分割成多个小块场景
    • 每个小块场景以命名规则存储，如 Scene_x0_y0_z0、Scene_x1_y0_z0 等
    • 每个小块有固定的尺寸（xSize, ySize, zSize），比如默认500x500x500

  2. 组织方式：

    • 使用 SceneCollectionManager（ScriptableObject）来管理一个场景集合
    • 场景集合中存储了所有分割后场景的名字数组 names[]
    • 通过 PrepareScenesArray 将场景名字转换为 Dictionary<Vector3Int, SceneSplit>，键是网格坐标，值是SceneSplit对象
    • 支持多层场景集合（如地形层、植被层、建筑层等），每层独立控制加载范围

  3. 加载方式：

    • Streamer 组件挂载到场景中，引用玩家对象
    • PositionChecker 协程定期（positionCheckTime，默认0.1秒）检查玩家位置
    • CheckPosition 计算玩家当前所在的网格坐标（通过 pos / size）
    • 当玩家跨越网格边界时，触发 SceneLoading 和 SceneUnloading
    • SceneLoading：以玩家所在网格为中心，按螺旋顺序遍历 loadingRange 范围内的所有网格，将需要加载的场景加入 scenesToLoad 列表
    • LoadLevelAsyncManage：每帧管理加载队列，控制并发加载数量
    • StreamerLoadingManager：实际执行异步场景加载（SceneManager.LoadSceneAsync Additive模式）和卸载
    • 加载完成后，将场景根对象移到正确的世界位置

  4. 卸载方式：

    • SceneUnloading：检查所有已加载场景，如果超出 deloadingRange 范围，则加入卸载队列
    • StreamerLoadingManager.UnloadAsync：异步卸载场景
    • 还会调用 Resources.UnloadUnusedAssets() 清理内存

  5. 其他特性：

    • 支持循环世界（looping）：当玩家到达边界时，从另一边绕回来
    • 支持环形加载（useLoadingRangeMin）：可以设置内部不加载的范围
    • 支持多层场景集合的联动卸载（unloadRangeConnect）
    • 支持碰撞体流（ColliderStreamer）：可以单独流加载碰撞体场景
    • 支持地形邻居连接（TerrainNeighbours）
    • 支持WorldMover：将整个世界向玩家移动，避免浮点数精度问题

所以提问者的理解基本正确，但需要补充一些细节：

  • 不仅仅是"视野范围"，而是一个可配置的加载范围（loadingRange）和卸载范围（deloadingRange）
  • 加载范围通常比视野大，是提前加载的缓冲区
  • 支持多层独立流加载
  • 支持循环世界
  • 有异步加载队列管理，控制帧率

通过分析代码，WorldStreamer 的本质确实是将大场景网格化切分，然后根据玩家位置动态加/卸载周围的场景块。下面从代码角度详细拆解它的工作原理：

一、场景分割阶段（编辑器期）

插件提供 SceneSplitter 编辑器工具，把一个完整大场景按固定尺寸（xSize/ySize/zSize，默认 500×500×500）切成 N 个小场景，每个场景以坐标命名，例如 Scene_x0_y0_z0.unity、Scene_x1_y0_z0.unity。

二、组织方式：SceneCollectionManager

SceneCollectionManager.cs 是一个 ScriptableObject，充当"场景块清单"：

  • 存储所有切分后场景名数组 names[]
  • 运行时通过 PrepareScenesArray() 把名字解析成 Dictionary<Vector3Int, SceneSplit>，键是网格坐标 (x,y,z)，值是 SceneSplit 数据结构
  • 一个 Streamer 可挂多个 SceneCollectionManager，实现多层独立流加载（如地形层、植被层、建筑层各自控制加载范围和优先级）

关键的范围参数：

  • loadingRange：加载半径（网格数）
  • deloadingRange：卸载半径
  • useLoadingRangeMin + loadingRangeMin：支持"环形加载"，挖掉中心区域不加载

三、加载流程

核心在 Streamer.cs：

  1. 位置检测：PositionChecker() 协程每隔 positionCheckTime（默认 0.1s）检查玩家位置
  2. 网格定位：CheckPosition() 用 floor(pos / size) 算出玩家所在网格坐标
  3. 触发加载：当玩家跨越网格边界时，调用 SceneLoading()
  4. 螺旋遍历：SceneLoading() 以玩家为中心，按螺旋顺序遍历 loadingRange 内的所有网格，把存在的且未加载的 SceneSplit 加入 scenesToLoad 队列
  5. 异步加载：LoadLevelAsyncManage() 每帧从队列取出任务，通过 StreamerLoadingManager.LoadSceneAsync() 调用 SceneManager.LoadSceneAsync(name, Additive) 异步加载
  6. 定位归位：加载完成后在 OnSceneLoaded() → AddSceneGoMin() 中，把场景根物体移到正确世界坐标 pos * size

四、卸载流程

  • SceneUnloading()（延迟 destroyTileDelay 秒执行）遍历已加载场景，若距离玩家网格超过 deloadingRange 则标记卸载
  • StreamerLoadingManager.UnloadAsync() 调用 SceneManager.UnloadSceneAsync()
  • 之后调用 Resources.UnloadUnusedAssets() 释放内存

五、附加能力（不止是简单分块加载）

特性说明
循环世界 (looping)玩家走到边界时从对侧绕回，通过 mod 取模实现坐标映射
环形加载loadingRangeMin 挖空中心，避免重复加载
多层联动卸载unloadRangeConnect 让某层随另一层一起卸载
碰撞体分流ColliderStreamer 单独流加载碰撞体场景，降低物理开销
地形邻居TerrainNeighbours 修复 LOD 接缝
WorldMover整体世界向玩家平移，解决大世界浮点数精度问题
并发控制maxParallelSceneLoading + sceneLoadWaitFrames 控制每帧加载量，避免卡顿

总结

WorldStreamer 的核心思想就是如问题所说的——“大场景切小块 + 按玩家位置动态加卸载”，但它在此基础上做了工程化增强：多层独立流、环形/螺旋加载顺序、循环世界、异步队列管理、碰撞体分离、精度修正等，使其能支撑真正的开放大世界。
