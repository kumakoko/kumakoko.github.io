StreamerLoadingManager类的作用分析

StreamerLoadingManager 是 WorldStreamer 2 系统中的异步场景加载/卸载执行器。如果说 Streamer 是"决策者"（决定加载/卸载哪些瓦片），SceneCollectionManager 是"数据持有者"，那么 StreamerLoadingManager 就是**“执行者”**——它真正调用 Unity 的 SceneManager.LoadSceneAsync / UnloadSceneAsync 来完成场景的 IO 操作，并管理整个异步操作的生命周期。

一、核心定位

  • 普通 C# 类（非 MonoBehaviour），在 Streamer.Start() 中被实例化：loadingManager = new StreamerLoadingManager() { Streamer = this };
  • 持有对 Streamer 的引用，用于启动协程（Streamer.StartCoroutine(...)）
  • 维护三个核心队列：待加载队列、待卸载队列、进行中的异步操作列表

二、主要职责

1. 维护加载/卸载队列

字段类型作用
_scenesToLoadList<SceneToLoad>等待加载的场景队列
_scenesToUnloadList<SceneToUnload>等待卸载的场景队列
_asyncOperationsList<AsyncOperation>正在进行的异步操作（防止重复提交）

SceneToLoad / SceneToUnload 是内部结构体，通过 SceneType 枚举区分三种场景类型：

  • Scene：普通场景（按名称加载）
  • Collider：碰撞体场景（关联 ColliderStreamer）
  • SceneSplit：瓦片场景（关联 SceneSplit）

2. 加载/卸载状态机

内部枚举 LoadingState { Loading, Unloading } 控制执行顺序：

[Update()] 每帧调用
    │
    ├─ 若 _operationStarted 或 _asyncOperations 非空 → 跳过（等待当前操作完成）
    │
    ├─ 状态 == Unloading:
    │    ├─ 有待加载 → 切换为 Loading
    │    └─ 有待卸载 → 启动 UnloadAsync() 协程
    │
    └─ 状态 == Loading:
         ├─ 有待加载 → 启动 LoadAsync() 协程
         └─ 无待加载 → 切换为 Unloading

设计意图：加载和卸载串行交替执行，避免同时大量 IO 造成卡顿。优先处理加载（保证玩家视野内瓦片尽快出现），加载队列清空后再处理卸载。

3. 异步加载执行 —— LoadAsync()

LoadAsync() 协程逐个处理 _scenesToLoad：

  • 对每个待加载项，先检查它是否已经在 _scenesToUnload 队列中（CheckIfSplitIsUnloaded 等）：
    • 若在卸载队列中：说明该场景刚被卸载但还未真正完成，此时直接复用已加载的 GameObject，从卸载队列移除，避免重复加载
    • 若不在：调用 SceneManager.LoadSceneAsync(sceneName, LoadSceneMode.Additive) 发起异步加载
  • 每个异步操作注册 completed 回调：
    • SceneSplit 类型：回调中调用 Streamer.OnSceneLoaded 完成瓦片初始化（设置位置、关联场景对象）
    • 其他类型：仅标记操作完成
  • 每个操作之间 yield return null，分散到多帧执行
  • 加载完成后 _operationStarted = false，允许下一轮

4. 异步卸载执行 —— UnloadAsync()

UnloadAsync() 协程逐个处理 _scenesToUnload：

  • 根据 SceneType 确定要卸载的 Scene：
    • Scene：直接用队列中的 Scene
    • SceneSplit：从 split.scene 获取，并调用 CheckForColliderStreamer 检查子物体中的 ColliderStreamer，若未卸载则先卸载碰撞体场景
    • Collider：从 colliderStreamer.sceneGameObject.scene 获取
  • 给根物体重命名加 (Unloading) 前缀便于调试
  • 调用 SceneManager.UnloadSceneAsync(scene) 发起异步卸载
  • 同样 yield return null 分散帧

5. 异步操作生命周期管理

  • OnOperationDone()：异步操作完成时回调，启动 RemoveAsyncOperation 协程
  • RemoveAsyncOperation()：延迟两帧后从 _asyncOperations 中移除该操作（等待 Unity 内部清理完毕）

6. 对外接口

方法作用
LoadSceneAsync(SceneSplit)将瓦片加入加载队列
LoadSceneAsync(string)将普通场景加入加载队列
LoadColliderAsync(ColliderStreamer)将碰撞场景加入加载队列
UnloadSplitAsync(SceneSplit)将瓦片加入卸载队列
UnloadSceneAsync(Scene)将普通场景加入卸载队列
UnloadColliderAsync(ColliderStreamer)将碰撞场景加入卸载队列
Update()每帧驱动状态机（由 Streamer.Update 调用）

三、与 Streamer 的协作关系

Streamer.Update()
    ├─ LoadLevelAsyncManage()
    │    └─ 从 scenesToLoad 取出瓦片
    │         └─ loadingManager.LoadSceneAsync(split)  ← 加入加载队列
    │
    └─ loadingManager.Update()  ← 驱动状态机
         ├─ LoadAsync()  → SceneManager.LoadSceneAsync
         │    └─ completed → Streamer.OnSceneLoaded()
         │         └─ Streamer.AddSceneGoMin() 设置瓦片位置
         │
         └─ UnloadAsync() → SceneManager.UnloadSceneAsync

Streamer.SceneUnloading()
    └─ loadingManager.UnloadSplitAsync(split)  ← 加入卸载队列

关键点：Streamer 只负责把瓦片放入队列，实际的 SceneManager API 调用、协程调度、状态切换全部由 StreamerLoadingManager 封装。

四、设计特点

  1. 单线程串行化：通过 _operationStarted 标志和 _asyncOperations 列表，确保同一时刻只有一个加载或卸载协程在运行，且所有异步操作完成后才开始下一批，避免场景冲突

  2. 加载/卸载去重：加载前检查卸载队列，卸载前若场景已在加载队列则直接复用，避免"刚卸载又加载"或"刚加载又卸载"的抖动

  3. 帧分散：每个场景操作之间 yield return null，防止一帧内大量 IO 导致卡顿

  4. 三场景类型统一管理：普通场景、瓦片场景、碰撞场景共用同一套加载/卸载状态机，通过 SceneType 区分处理细节

  5. 非 MonoBehaviour 设计：自身不挂在物体上，通过持有 Streamer 引用借用其协程能力，保持类的纯粹性

五、总结

StreamerLoadingManager 是流送系统的"异步 IO 执行层"：它将 Streamer 决策出的加载/卸载需求转化为 Unity SceneManager 的实际异步调用，通过加载优先、卸载次之的串行状态机，配合去重检查和帧分散策略，确保场景流送过程平滑、无冲突、不卡顿。它屏蔽了底层异步操作的复杂性，让 Streamer 只需关注"加载哪些、卸载哪些"的决策逻辑。
