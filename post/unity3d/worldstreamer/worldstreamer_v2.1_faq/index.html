根据SceneSplitterEditor的GameObject Prefix值，对场景中的game object进行分类分层

问：文档说，SceneSplitterEditor会根据GameObject Prefix值，对场景中的game object进行分类分层，这一块的代码在哪里

文档所说的"根据 GameObject Prefix 对场景中的 game object 进行分类分层"的核心代码在 SceneSplitterEditor.cs中，关键位置如下：

1. Prefix 配置入口（UI）

layer.prefixName = EditorGUILayout.DelayedTextField(
    new GUIContent("GameObject Prefix", ...),
    layer.prefixName);

此处把用户填写的字符串保存到 layer.prefixName（即 SceneCollectionManager.prefixName）。

2. 分类分层核心方法：SplitScene

SceneSplitterEditor.cs文件的SplitScene函数的第1096行到1245行代码是进行分类分层核心方法。

  1. 第1133-1135行代码：通过 ObjectsParent.gameObjectPrefix == layer.prefixName 判断对象是否已被编目到该 prefix 分组（catalog 模式）。

  2. 第1138行代码：名称前缀匹配，这是真正"按 GameObject Prefix 分类“的关键一行：

if (!isInCatalog && !item.name.StartsWith(layer.prefixName, System.StringComparison.Ordinal))
    continue;

对象名若不以 layer.prefixName 开头则跳过，否则归入此 layer。

  1. 第1146行代码：GetID(item.transform.position, layer) 再根据对象 pivot 位置算出网格 tile ID，实现"分层 + 分块”。

  2. 第1148-1216行代码：若该 tile 不存在则创建带 SceneSplitManager 的父节点 layer.prefixScene + itemId，并更新 layer 的 x/y/z 坐标范围。

  3. 第1218-1238行代码：把对象挂到对应 tile 下；若来自 catalog（ObjectsParent），则放进 tile 下的 ObjectsInSceneParent 子节点，从而保留分组结构。

3. 调用入口

  1. 第243行代码：每个 layer 旁边 “S” 按钮 → SplitScene(layer)（单层切分）。
  2. 第392-407行代码：“Split All Scenes Into Virtual Grid” 按钮 → 遍历所有 layer 调用 SplitScene。

4. 相关辅助方法

  1. 第995-1091行代码：根据对象位置和 layer 的 xSize/ySize/zSize 计算所属网格 ID 与 tile 中心位置。
  2. 第1251-1276行代码：用 prefixScene 找回已有的 split 父节点（用于增量更新）。
  3. 第1307-1409行代码：清空旧 split，把对象还原到 ObjectsParent 下，是 SplitScene 的逆操作。

分层的时候，是会把原有的game object移动到一个新的父节点下吗？

是的，会把原有 game object 移动到新创建的父节点下。具体逻辑在SceneSplitterEditor类的SplitScene方法中，第1218-1238行代码：

两种情况

  1. 情况 1：普通对象（非 catalog 对象）SceneSplitterEditor.cs第1218-1221行代码
if (!isInCatalog)
{
    item.transform.SetParent(split.transform);
}

直接把对象reparent到新创建的tile父节点split（名为 layer.prefixScene + itemId，例如 prefix_x1_y2_z3，挂有 SceneSplitManager 组件）下。

  1. 情况 2：catalog 对象（父节点是 ObjectsParent）第1222-L1238行代码：
else
{
    ObjectsParent objectsParent = 
	    item.transform.parent.GetComponent<ObjectsParent>();
    ObjectsInSceneParent objectsInSceneParent           
	    split.GetComponentInChildren<ObjectsInSceneParent>();
    if (objectsInSceneParent == null)
    {
        GameObject go = new GameObject(
		        objectsParent.gameObjectPrefix + " Objects");
        objectsInSceneParent = go.AddComponent<ObjectsInSceneParent>();
        objectsInSceneParent.gameObjectPrefix = objectsParent.gameObjectPrefix;
        objectsInSceneParent.transform.SetParent(split.transform);
    }
    item.transform.SetParent(objectsInSceneParent.transform);
}

对象被移到 split 节点下的一个 ObjectsInSceneParent 子节点（名为 <prefix> Objects）下，保留原 ObjectsParent 的分组语义。

层级结构示意

切分前：

Scene
├── StreamedT_Terrain_01   (ObjectsParent 子物体)
├── StreamedT_Terrain_02
└── StreamedT_Tree_05      (普通对象)

切分后（假设都落在同一个 tile _x1_y0_z0）：

Scene
└── prefix_x1_y0_z0  (SceneSplitManager)
    ├── StreamedT_Tree_05                    ← 普通对象直接挂到 split 下
    └── StreamedT Objects (ObjectsInSceneParent)
        ├── StreamedT_Terrain_01             ← catalog 对象挂到 ObjectsInSceneParent 下
        └── StreamedT_Terrain_02

几个相关细节

  1. 第1142-L1143行代码：跳过有非 ObjectsParent 父节点的对象，避免把已经是子层级的对象重复处理。
  2. 第L1119行代码：每次 SplitScene 开头会先调用 ClearSceneGO(layer)，把之前已经分到旧 split 节点下的对象还原回 ObjectsParent 下（或解除父节点），所以重新切分是幂等的，不会丢失对象。
  3. 想撤销分层，点 “C” 按钮 → 第L1281-L1302行代码：也会调用 ClearSceneGO 把对象从 split 节点里"摘"出来。
