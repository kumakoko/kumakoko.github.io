World Streamer v2.1 中文核心手册（操作指南）

原文：《World Streamer Manual v.2.1》，作者 Bartłomiej Galas（NatureManufacture） 本文档为原手册的中文结构化摘要，保留全部操作步骤、参数含义与注意事项，省略纯截图说明与重复脚注。

0. 这是什么

World Streamer 是一个 内存异步流式加载系统（memory async streaming）。它把整个游戏世界切成小块存放在磁盘上，只在玩家靠近或满足触发条件时才加载对应 Scene，从而在不出现加载画面的情况下实现：

  • 无尽空间游戏、2D 平台跳跃、第三人称、开放世界、建筑漫游、单机/多人
  • 可做循环世界、星球模拟、远景背景生成
  • 降低 CPU / RAM / VRAM / GPU 占用，减少场景中同时存在的对象数量
  • “Floating Point Fix System” 消除超大坐标带来的引擎精度问题
  • “Local Area Updater” 让编辑器只加载局部区块，避免打开整个大世界卡顿

核心理念：把世界按"虚拟网格（virtual grid / grid eye）“切成 Scene 文件，按层（layer）组织，跟随玩家/相机异步加载。

⚠️ HD / URP 用户：需打开 HD and URP Support Packs 文件夹，按 README 导入对应版本支持包。

1. 功能清单（Features）

  • 浮点误差修复系统、循环世界系统、多人支持、多场景编辑
  • 多层独立流式、多开发者同区域协作
  • Terrain 切分工具、从 Terrain/植被生成低多边形网格
  • 去除世界尺寸限制；编辑器中操作超大/超精细场景不卡顿
  • 异步后台加载；与 Amplify、Granite 等纹理流式系统兼容
  • 内置加载画面系统；Terrain LOD 系统
  • Terrain 管理器（切分、分块管理）
  • 附加 Terrain 剔除系统（可降低 10–90% Terrain 的 CPU/GPU）
  • Ring Streaming：远处用低 LOD 模型替换高质量 Terrain/植被
  • Collider Streaming：进门/撞触发器时加载室内、洞穴等
  • 被流式加载的 Scene 还能再加载 Scene（套娃结构）
  • WebPlayer 支持
  • Local Area Updater：编辑器只加载指定区域/层
  • 兼容 Terrain Stitcher、Multiple Terrain Brush
  • 全开源带注释代码、合批支持、GI/Lighting 管理器
  • 初始/传送加载期间玩家处于安全位置
  • 物理管理器（必要时冻结动态物体）
  • Occlusion Culling 支持；带浮点修复的 Unity NavMesh

2. 项目前置要求（必须做）

2.1 添加三个 Tag

Project Settings → Tags & Layers 中添加：

Tag 名挂在哪个 GameObject对应预制体
SceneStreamer任何挂了 Streamer.cs 的对象_Streamer_Major、_Streamer_Minor
WorldMover任何挂了 WorldMover.cs 的对象_World_Mover
ColliderStreamerManager任何挂了 ColliderStreamerManager.cs 的对象_Collider_Streamer_Manager

不打 Tag，build 甚至编辑器里都加载不出东西，会报一堆错。新项目务必先查 Tag。

2.2 Player Settings

  • ✅ Incremental GC（开启增量 GC）——显著加快流式加载，务必常开
  • ✅ Prebake Collision Meshes——build 时加快碰撞加载，但会让编辑器变慢（因为 Unity 把网格烘焙成块）；大幅降低物理开销
  • 建议开启 Optimize Mesh Data——减小包体、加快流式加载，但会极大延长 build 时间，仅最终 build 勾选

2.3 两个场景

  • “Work” 场景：放所有要流式加载的模型/Terrain，用来切分世界、生成虚拟网格与层
  • “Gameplay” 场景：只放玩家、方向光、相机、UI；流式用的世界内容全部从磁盘加载；Streamer 预制体也放这里

3. 核心组件一览

组件作用
Scene Manager（Tools → Nature Manufacture → World Streamer → Scene Manager）大工具窗口：从场景对象创建虚拟网格和层、管理灯光、切 Terrain、生成低模、生成 Scene
Scene Collection（预制体）保存某一层的所有 Scene、网格元素尺寸、世界尺寸等信息；由 Scene Splitter / Local Area Updater 生成或刷新
Scene Objects与 Scene Collection 关联的实际 Scene 文件
Streamer 预制体（_Streamer）在 Gameplay 场景里持有 Scene Collection，按设置流式加载；可一个管全部层，也可多个分管
Collider Streamer（Collider_Stream_xxx_stream）撞到触发器后加载对应 Scene
Collider_Stream_Manager（_Collider_Streamer_Manager）管理所有 Collider Streamer；支持"藏在网格 Scene 里的 Collider Scene”（套娃）
Local Area Updater合并/局部加载/刷新/修改/删除已切分世界的局部，支持多人同区域协作
Streamer GUI（_Streamer_GUI / _Loading_Screen_UI）加载画面、传送、重生、位置调试 UI
World_Mover（_World_Mover）浮点修复系统里定期重置世界坐标；保存真实坐标与重置后本地坐标的差值（用于生成对象、多人 RPC）
Player_Mover初始加载/传送期间把玩家移到安全位置
Player Teleport（_PlayerTeleport）传送点/重生点位置，可动态
Object to Move挂在需要跟随玩家一起做坐标重置的非流式对象上（相机、单人 AI、天空盒等）
TerrainCullingSystem给 Terrain 额外性能：相机看不见/太远时关掉它
Physic Culling System玩家离太远时冻结动态物理对象，记录速度方向；回来后恢复，避免因数据未加载而漏碰撞
Object Parent挂在层级目录（父节点）上，切分过程中保留父子结构

4. 快速上手（Test Scene）

  1. 先按 §2.1 配好三个 Tag。
  2. 打开任意 Gameplay Demo 场景：WorldStreamer → Tutorial Work and Game Scenes → 选一个 Game 场景（有 mobile / standalone 多种变体）。
  3. 选中 Hierarchy 中的 Streamer 对象，点 “Add to Build Settings”——所有网格元素（Scene）必须加进 Build Settings，否则无法加载。
  4. 对 Collider Streaming 用的室内场景也加进 Build Settings： WorldStreamer → SplitScenes → ColliderScenes → Prefabs → 选中 Colider Stream Interior_stream 等预制体，点 Add to Build Settings。
  5. 直接 Build 后运行（不要只按 Play）。Play 模式会把 build 期的烘焙（合批、碰撞烘焙等）挤到运行时，性能很差；build 后一切正常。

💡 记住：World Streamer 的真正威力在 build 里体现。编辑器里卡顿/尖峰多是正常的（静态合批可临时关闭来缓解，但 drawcall 会上涨）。

5. Scene Manager 详解

打开方式：Tools → Nature Manufacture → World Streamer → Scene Manager。 建议在空的 “Work” 场景中打开；把要流式的内容复制进来，方向光/玩家/UI 留在 Gameplay 场景。

5.1 Terrain Manager 区

  • Terrain Settings：切完后所有 Terrain 共用的设置（draw instanced、pixel error、草/树/风）
  • Terrain Splitter：把 Terrain 按倍数切分。例：1000×1000、513 heightmap，切 2 次 → 4 块 500×500、257 heightmap
  • Add Terrain Culling：给所有 Terrain 批量加剔除脚本
  • Terrain Low Poly Mesh Generator（重要！）：从 Terrain 生成含树的低模远景
    • Ambient Color：自动设，可调
    • Terrain LOD：低模密度，默认 3 即可
    • Use Basemap：用 basemap 还是 splatmap 生成纹理。自定义 shader（CTS 等）建议 splatmap
    • Use Smoothness：是否把 smoothness 存到 basemap alpha 通道
    • Basemap Resolution：远景纹理分辨率，默认 512（1024 也可）
    • Normal Details / Normal Strength：烘焙法线贴图细节与强度
    • Create normal from shape / from texture：从地形形状/纹理生成法线并混合
    • Y Offset：低模相对原 Terrain 略向下移，避免缝隙
    • Vertex down distance：Terrain 边缘"墙"下移距离，防止低模与原 Terrain 间出现空洞
    • Tree Prototypes：可把树烘焙进低模（仅 NM 树或最后一 LOD 为 cross 面片的树；小树种别烤，远了看不见浪费）
    • 导出按钮：导出"含树低模"/“仅 Terrain 低模”/“仅树”

5.2 Streaming Layers 区

  • Add Layer：新建一个层/组，独立流式。典型层：Terrains、Small Models、Big Models、Medium Models、Far Low Poly Terrains、Lights、Particles、FX
  • Split X / Y / Z：选择虚拟网格沿哪些轴切分
    • 太空游戏：勾 XYZ
    • RTS/RPG/赛车：勾 XZ（高度不重要）
    • Unity Terrain：只勾 XZ；若想玩家飞太高时卸载 Terrain 才勾 Y
  • X/Y/Z Size：单个网格元素的尺寸
    • 不能太大（一次加载太多），不能太小（Scene 数量爆炸）
    • 要和对象尺寸匹配：200×200 的建筑不要放进 20×20 网格；一组建筑可以放进 1000×1000 网格
    • Unity Terrain 的 X/Z Size 必须等于 Terrain 的长/宽
  • GameObject Prefix（关键）：切分时按物体名开头的前缀归类到层。留空则把场景里所有对象塞进这一层。也可用 Object Parent 脚本挂在文件夹上，脚本里设同样前缀
  • Scene Prefix：虚拟网格元素/Scene 的命名前缀，如 World_A_Small_Models、World_A_Terrain_LOD0。生成后名字会带上行列号，如 World_A_Small_Models_x3_y0_z-2
  • Split Scene（或 S）：执行切分，把对象按名前缀归层、按 pivot 位置归到对应网格
  • Clear Scene Split（或 C）：撤销切分
  • Generate Scenes from Virtual Grid（或 G）：从网格元素生成 Scene 文件，并生成同名 Scene Collection 预制体（存到 WorldStreamer → SplitScenes → <Layer>）
  • S / G / C / X：分别只对当前层做 切分 / 生成 Scene / 撤销切分 / 删除该层
  • Layer Order：若某层 GameObject Prefix 为空，它必须放在最后；否则所有对象会被它吃掉
  • Gizmo Color：点中网格元素时显示边界的颜色；Gameplay 场景里也用于可视化流式范围
  • Generate Scenes from Colliders only：为 Collider Streaming 生成 Collider_Stream 预制体和 Scene

⚠️ pivot 注意：对象作为子物体挂到父物体下时，系统取的是父物体的 pivot位置来决定它落在哪个网格。层级里开启显示 pivot 图标来检查。

📐 网格坐标示例：层 “Models”，前缀 “Object”，网格 3×3×3。

  • Object_A (5,5,5) → Models_x1_y1_z1
  • Object_B (-1,1,1) → Models_x-1_y0_z0
  • Object_C (0,0,0) → Models_x0_y0_z0 网格原点从 (0,0,0) 开始。

5.3 Light Manager 区

  • 为生成的 Scene 设置统一的光照设置（lightmap、烘焙 ambient、fog 等），避免流式加载时告警
  • Scene Collection Manager：把 Scene Collection 拖进来，系统会把 Light Probe Grid 按该层网格尺寸切片、重命名、分发到对应切分文件夹；原 probe grid 禁用
  • 初始设置一般从 Work 场景继承，Work 场景配好即可

5.4 Build Settings 区

  • Scene collections：拖入所有 Scene Collection，自动加入其下所有 Scene
  • Collider Streamers：拖入所有 Collider_Stream 预制体
  • Add scenes to build settings / Remove scenes from build settings：一键批量加/删

6. Streamer 对象参数（Gameplay 场景里的 _Streamer）

参数含义
Active启用/停用该层流式
Priority加载顺序，从最小值往大值加载
Scene Collection拖入对应层的 Scene Collection 预制体。这是把流式系统与你的场景集合预制体（scene collection prefab）连接起来的地方。场景集合预制体中保存着关于虚拟网格元素（virtual grid elements,即场景）的信息。直接把场景集合预制体拖拽到这个窗口中即可。场景集合预制体位于它所属的、已生成场景所在的目录中，也就是 WorldStreamer → SplitScenes → 图层名 这个路径下。
Loading Range（每轴整数）以网格元素为单位的加载半径。0=1 格(1个)，1=9 格(3×3)，2=25 格(5×5)，3=49 格……每轴可不同。循环世界下必须小于"世界半长 - 1"格
Use Loading Range Min开启 Ring Streaming（环形流式）。勾选此复选框后，即可启用 “Loading Range Min” 功能，我们称之为 Ring Streaming（环形流式加载）。这是我们新推出的系统，它允许你在一个特定范围（“从From 到To”）内加载对象。之所以叫它 “环形流式”，是因为流式加载的区域看起来像一个环。对象离得太近会被移除，离得太远同样会被移除。
Loading Range Min从 Loading Range 中"挖掉"的内圈半径；内圈不加载（用于近景换另一层的高精度物体）。 这是一个按每个轴（X/Y/Z）分别设置的整数值，用于指定要从 “Loading Range”（加载范围）中挖掉的虚拟网格元素半径。

Streamer 会加载这个环内的所有内容。如果你（玩家）离得足够近，它就会把模型从内存中移除，或者干脆不加载它们。

这个功能常用于用其他层（layer）的模型 / 对象替换近距离的模型 / 对象。通俗理解：Loading Range 定义了一个 “外圈”（最远加载距离），Loading Range Min 定义了一个 “内圈”（最近加载距离），两者之间的环形区域才是真正加载的范围。这样可以用另一层的高精度模型填满内圈，用这一层的模型（通常是远景低模）负责外圈，两套模型无缝衔接 —— 这正是实现 “近景高清 + 远景低模” 的机制。
Sync with other layer两层同步加载/卸载，避免出现空洞；对方没准备好替换前不卸载
Deloading Range超出此距离开始卸载（还要再过 Destroy Tile Delay 秒才真正销毁）。循环世界下同样小于"半长 - 1"。虚拟网格元素并不是一超出范围就立刻卸载，而是要等到你在 “Destroy tile delay”（销毁瓦片延迟） 中设置的时间过后才会真正卸载。所以判断顺序是：先看距离，再看时间（先满足距离条件，再等待设定的延迟时间）。

如果世界是循环的（looped），卸载范围必须小于世界总网格数的一半再减去 1 个网格元素。

补充：最后这条约束和 Loading Range 的约束一样，是因为循环世界里加载范围以玩家为中心向两侧延伸，若范围超过半个世界，前后两半会重叠冲突，导致系统无法正确判断加载 / 卸载边界。
Position check每隔多少秒检查一次跟随对象位置
Destroy Tile Delay离开加载范围后延迟多少秒才从内存销毁。防止玩家在网格边界来回横跳导致频繁加载/卸载；Ring 模式下旧模型等新层填上再删
Max Parallel Scene Loading同时并行加载的 Scene 数。值低加载慢但不掉帧；需按设备试
Scene Load Wait Frames两个 Scene 加载之间空多少帧。小网格可设 1 或 0；太大则流式变慢
Player拖入代表玩家位置的对象（多数情况用玩家而非相机；RTS/2D 平台用相机更好）
Looping开启该 Scene Collection 的循环（每个 Streamer 独立循环）
↳ sync scene collection limits各层网格数量不同时勾此项以同步边界
↳ override single instance scene允许同一场景同时被多次加载，可循环任意大小世界
↳ Override X/Y/Z limits强制按指定世界距离在某轴循环（如 Y 轴无数据但要循环）
Spawned Player玩家是后生成的；系统等待带指定 Player Tag 的对象出现。开启后所有 Player 槽位留空

7. 传送 / 重生 / 加载屏

7.1 _PlayerTeleport预设

把_PlayerTeleport预设_拖入 Gameplay 场景，其 XYZ 即传送目标点。Inspector 里填：

  • UI Loading Streamer：含 UI Loading Streamer 脚本的对象（在 _Streamer_GUI 子级）
  • Streamers：把场景里所有 Streamer 对象拖进来
  • World Mover：若用浮点修复，拖 _World_Mover
  • Player：玩家对象
  • Player Mover：若用"安全位置"系统，拖 _Safe_Place_Spawn_and_Teleport

快捷按钮：拖 LevelReset_Teleport_button + EventSystem 入场景，Button OnClick 选 PlayerTeleport → Teleport(bool)。

7.2 加载屏 UI

  • 拖 _Streamer_GUI（高级，含 EventSystem/位置 gizmo/传送按钮/加载屏）或简单的 Loading_Screen_UI
  • 在 Loading_Screen_UI 的 Streamers 列表里只放必须挡住加载完成的 Streamer（小物件层可不放，让它游戏中再加载）
  • Wait frame（秒）：必须 > 12，建议 23 秒——给系统时间统计有多少格要加载；太短加载屏提前结束，太长浪费时间
  • Progress Img：进度条图片

8. 浮点修复系统（Floating Point Fix）

世界很大或用循环世界时必须用。坐标过大会导致物理失准、阴影闪烁等。 原理：_World_Mover 每隔 N 个网格元素就把整个世界和玩家的本地坐标重置到 0,0,0。

不支持：Static Batching（Unity 不允许移动静态合批对象）。需用自定义合批或手动合并网格；Unity Terrain 的 Static Batching 可保留，系统仍能移动它。

设置：

  • XYZ Tile Range：经过多少个网格元素后重置。例：Range=1，主 Streamer 每格 200 单位 → 每移动约 400 单位重置一次
  • Streamer Main：选最大网格（或带 Terrain）的 Streamer 作为重置时钟源
  • Streamers Additional：其余所有受影响 Streamer（99% 情况全拖进来）
  • Current Move：本地玩家坐标 - Current Move = 真实玩家坐标。多人/服务器 RPC、代码生成对象时用它校正位置

Important1：若用传送/重生，把 _World_Mover 拖到 _PlayerTeleport 的 World Mover 槽。 Important2：跟随玩家/需要保持相对位置的对象（分离相机、单人 AI、天气、天空盒）挂 Object to Move 脚本并填 _World_Mover。跟随玩家的粒子系统把 Simulation Space 改为 Local（或在重置瞬间切换），否则粒子会跳一下。

9. 循环世界（Looping）

在 Streamer 上勾 Looping，并配合浮点修复。

  • 每个 Streamer 独立循环；要同步就勾选 sync scene collection limits，或强制统一 Override X/Y/Z limits
  • 一层可以与其他层不同步地循环（例如小镇层循环得更频繁，适合太空中的小行星）
  • 与浮点修复同样不支持 Static Batching（Terrain 除外）

做循环 Terrain 的两种情形：

  1. 整块 Terrain 还没切（最简单）：复制 Terrain 副本接在边缘（原 Terrain 在 200 结束，副本就从 200 开始），用 Terrain Brush / Terrain Stitcher 融合两条边，删掉副本 → 按 §5 流程走，最后勾 Looping + 开浮点修复
  2. Terrain 已分块：只复制/融合边缘相邻的两块，融合后删掉副本，其余流程同上

10. Ring Streaming（环形流式）

用途：近景用高质量层，远景用低模层，两圈之间无缝替换。典型：近景高精度 Terrain，远景换成带树的低模 mesh。

打开方式：勾 Use Loading Range Min + 勾 Sync with other layer + 填 Loading Range Min + 选要同步的另一层 Streamer。

  • 层 A（高精度）：Loading Range Min = 1，Loading Range/Deloading Range = 6 → 只在近距圈里出现
  • 层 B（低模）：Ring 关闭，Loading Range = 6 → 从外圈到内圈都在
  • 两圈交界处无缝替换，远景只占少量顶点和 1 个 drawcall

这对 Unity Terrain 尤其重要——Unity Terrain 数据很重且不支持 LOD。

11. 物理 / Terrain 剔除 / 安全位置

  • Physic Culling System：挂在每个动态物理对象上；玩家超过 Physic Distance 后冻结对象并记录速度/方向，回来后恢复。预制体 _PhysicCulling_Test 可参考
  • Terrain Culling System：挂在每个 Terrain 分块上（切分时批量加）；通过 MainCamera Tag 识别主相机，看不见或太远就不刷新该 Terrain 的树和 LOD，省 CPU
  • _Safe_Place_Spawn_and_Teleport：初始加载/传送期间把玩家移到安全点。填 Streamers 列表、Safe Position、Player（若玩家后生成则留空，生成后自动接管）；配合传送时在 _PlayerTeleport 的 Player Mover 槽里填它

12. Terrain Streaming 完整流程

12.1 分块尺寸建议

  • (a) 不用 Ring / 低模远景：每块 Terrain = 相机远裁剪面的 110%。Loading Range 设 1（只加载 3×3=9 块），留出 10% 时间加载不穿帮
  • (b) 用 Ring Streaming + 低模替换（推荐）：每块 = 相机远裁剪面的 10%~50%
    • 10%：想在游戏里动态切换细节等级，且低模含树
    • 30~50%：一切照旧
    • 优势：远景只需少量顶点 + 1 drawcall/块，可挂很多块
  • (c) 纯低模 mesh 代替 Terrain（手机）：尺寸任意，但加载总量保持在远裁剪面 110% 左右以留出加载时间
  • 自定义 Terrain 方案（CTS 等）通常是 (b)+(c) 的组合

12.2 准备步骤

  1. 打开 Scene Manager → Terrain Manager
  2. 设置切分后 Terrain 的公共参数（draw instanced、pixel error、草/树/风）
  3. 选切分倍数（2 = X/Z 各切一刀 → 4 块），点 Split
  4. 生成低模远景（Terrain LOD=3，Basemap 512，只把大树/NM 树/billboard-cross 树烤进去，小树别烤）
  5. 源 Terrain 保留不动（方便以后改网格尺寸重切）
  6. Terrain 起始坐标必须是整数值（如 5000,-5000,0），不能是 99.98/0.1/-0.018 这种
  7. Terrain 必须落在其尺寸的整数倍位置（块 500×500、网格 500×500 → Terrain 坐标为 500,0,-500,1000…），避免网格边界与 Terrain pivot（在角上）错位
  8. 给 Terrain 重命名加前缀：LOD0_Terrain（高清）、LOD1_Terrain（低模）；或用 Object Parent 脚本
  9. （可选）做成 Prefab

12.3 切分与生成

  1. 新建/打开 Work 场景，复制 Terrain 进来
  2. 打开 Scene Manager → Streaming Layers → Add Layer
  3. 勾 Split X / Split Z（不勾 Y）
  4. X/Z Size 必须等于 Terrain 块尺寸
  5. GameObject Prefix 填 LOD0_Terrain；Scene Prefix 填 World_1_Scene_Terrain_HQ
  6. 为低模 Terrain 再建一层，前缀 LOD1_Terrain，Scene Prefix World_1_Scene_Terrain_LP
  7. 点 S / Split Scene 切分；无误后点 Generate Scenes from Virtual Grid
  8. 得到 Scene Collection 预制体 World_1_Scene_Terrain_HQ 与 World_1_Scene_Terrain_LP

12.4 Gameplay 场景设置

  1. 新建 Gameplay 场景（玩家、相机、方向光）
  2. 拖 _Streamer、_Streamer_GUI 入场景
  3. 在 _Streamer 的 Scene Collection 槽里拖入 HQ 和 LP 两个 Collection
  4. 参考值（HQ 层）：
    • Loading Range X=1, Y=0, Z=1
    • Use Loading Range Min = false
    • Deloading Range X=1, Y=0, Z=1
    • Destroy Tile Delay = 2s
    • Position check = 0.1s
    • Max Parallel Scene Loading = 1
    • Scene Load Wait Frames = 2
    • Player = 玩家
    • LP 层（Ring）：Loading Range Min = 1，Loading/Deloading Range = 6
  5. 配置加载屏：_Loading_Screen_UI 的 Streamers 列表 Size≥1，Element 0 放 HQ Streamer（HQ 全部加载完才放行玩家）
  6. 选中 _Streamer，若没加 Build Settings 会出现警告按钮，点它自动补加。每次改网格数量/尺寸都要重新点
  7. 运行

💡 改 Terrain 形状/刷树/刷贴图后不用重新切分——Terrain 数据存在 Scene 里，引用自动更新。但增删块、移动块后要重新 Split + Generate，再点 Add to Build Settings。

13. Model / Object Streaming 完整流程

13.1 分层思路（以 GTA 类为例）

  • Big Objects：建筑、道路、巨石——远距可见轮廓
  • Medium Objects：静态车、建筑附属、栅栏、灯笼、灌木、箱子、路牌
  • Small Objects：纸、泥土、井盖、花、垃圾桶、小牌子
  • Lights / Particles：可独立成层（Unity LOD 剔除灯和粒子后，灯仍在发光、粒子仍占 CPU；流式则能真正卸载）

RTS/俯视角可能只用一层；太空游戏要把星、行星、小行星分开。

13.2 准备

  1. Work 场景里复制所有要流式的对象
  2. 给预制体名加前缀：Big_Objects_Building、Medium_Objects_Fence、Small_Objects_Flower（场景实例会自动跟着改）；或用 Object Parent 脚本按文件夹分类
  3. 想单独流式的子细节从母预制体里解包；想作为 LOD 跟随母物体的保留嵌套

13.3 切分

  1. Scene Manager → Add Layer
  2. 勾 Split X/Z（Small/Medium 层可勾 Y）
  3. X/Z Size 按对象尺寸试，建议从 300×300 起。估算公式：想看 1500 单位远 → 1500/300 = 5 → Streamer Loading Range 设 5
  4. GameObject Prefix 填对应前缀（Big_Objects / Medium_Objects / Small_Objects）
  5. Scene Prefix 填 World_1_Far_View / World_1_Medium_View / World_1_Short_View
  6. S / Split → G / Generate Scenes
  7. 网格别太小（drawcall 涨、加载慢）也别太大（内存/GC 压力），多试几次

13.4 Gameplay 场景

  1. Gameplay 场景已有玩家/方向光/相机
  2. 复用现有 _Streamer（不要重复拖多个 UI），在其下新增一层并拖入对应 Scene Collection
  3. 参考值（Big 层，格 300×300，想看 1500 远）：
    • Loading Range X=5, Y=0, Z=5
    • Deloading Range X=5, Y=0, Z=5
    • Destroy Tile Delay = 1s
    • Position check = 0.1s
    • Max Parallel Scene Loading = 1
    • Looping = false
    • Scene Load Wait Frames = 1~2
  4. 配置 _Loading_Screen_UI 的 Streamers 列表
  5. 点 _Streamer 上的警告按钮把新 Scene 加进 Build Settings
  6. 运行

14. Collider Streaming（触发器流式）

用途：进门/撞触发器时加载室内、房间、楼层；可把整座城填满室内而只在门口附近加载。

14.1 生成

  1. 在要流式的对象附近建空 GameObject，命名 Collider_Stream_Interior_1
  2. 给它加 Collider，勾 Is Trigger，调整尺寸到触发范围
  3. 把要流式的对象拖成它的子物体
  4. 给它挂 ColliderScene 脚本
  5. 打开 Scene Manager → 点 Generate scenes from colliders only
  6. 生成结果在 WorldStreamer → SplitScenes → ColliderScenes：Scene + Collider_Stream_Interior_1_stream 预制体（预制体记住原始位置，拖到任何场景都在原位）

套娃（Matrioshka）：把 Collider_Stream 对象直接放进某个普通层里切分也行。系统会识别并生成 Scene，只需在 Build Settings 里批量加入；若外层层是循环+浮点修复，Collider 对象会自动跟随。这种情况下 Gameplay 场景只需拖 _Collider_Streamer_Manager。

14.2 Gameplay 场景

  1. 拖 _Collider_Streamer_Manager（必须有 ColliderStreamerManager Tag），填入 Player
  2. 设置触发 Tag（Player / MainCamera）。触发对象必须有 Collider + Rigidbody（建议 Kinematic 开、Gravity 关）
  3. 把生成的 Collider_Stream_Interior_1_stream 预制体从 Project 拖进场景
  4. 点 Add to Build Settings
  5. Player Only Activate：是否只有玩家触发才加载
  6. Unload Timer：触发者离开 collider 范围后多久卸载
  7. 运行，撞一下试试

15. 为什么需要多层（Multiple Layers）

  • 场景中对象越少，脚本越快、GC 尖峰越小
  • 大轮廓（建筑、Terrain）放远距层，小细节只在近距加载
  • Ring Streaming + 层 = 用低模替换 Unity Terrain / 用静态 billboard 粒子替换远距离粒子（Unity LOD 做不到真正卸载粒子 CPU）
  • 按 Lights / FX / Models / AI 分层 → 不同专长的多人可在同一区域同时工作互不干扰
  • 用户实测可提升 200~300% 性能；层范围是动态值，可做游戏内画质选项
  • ⚠️ 不要让所有层同时加载：Terrain 用 500×500 网格时，对象层用 350×350，这样两层网格位置（0,500,1000… vs 0,350,700,1050…）错开，不会同时刷新加载

16. Local Area Updater（局部更新器）

让编辑器只加载世界的一小块来编辑，不必打开整个世界。

16.1 操作

  1. 新建空场景保存为 Local Area Updater Scene
  2. 打开 Tools → Nature Manufacture → World Streamer → Local Area Updater
  3. Scene collections：拖入要操作的层（多个时注意顺序：空前缀层必须放最后，否则新对象会全被它吃掉）
  4. Loading distance：加载范围（按网格元素数或按 Unity 单位；各层网格尺寸不同时用单位更方便）
  5. Loading center：加载中心 XYZ
  6. Load scenes from collections around center point：立即加载周围区域
  7. Load all scenes from collections：加载全部（用于合并回大场景）
  8. Unsplit scenes：把所有 Scene 合回一个大场景（合并层、解除网格归属）
  9. Split scenes：把新加/移动的对象重新归层归网格
  10. Save loaded scenes：保存修改（会弹一个 Unity 的 buggy 窗口，直接回车/确定）
  11. Unload loaded scenes：清空
  12. Remove empty virtual grid elements：从 Scene Collection 中移除空 Scene 引用
  13. Delete empty scenes：删除空 Scene 文件（想以后复用就保留）

16.2 典型工作流

新建 Local Area 场景 → 拖入 Scene Collections → 设范围/中心 → Load around center → 改对象 → Split scenes → Save loaded scenes → Unload → 若新建了 Scene，到 Gameplay 场景点 Streamer 上的 “Add to build settings”。

17. AI / NavMesh

  • Unity 2022.3+ 新 NavMesh：NavMesh 是带位置的层级 GameObject，可像普通对象一样流式；单独一层，或与 Terrain 同层（不太重的话）。也可整张大 NavMesh 放 Gameplay 场景，用 Object to Move 跟随浮点重置
  • 自定义方案：APEX（不需要 NavMesh、能响应几何变化）；任何支持分块保存 NavMesh 并在运行时拼接的方案，或不需要 NavMesh 的寻路方案，都可工作
  • 旧版 Unity NavMesh（5.6+）：Dynamic NavMesh；或整张大 NavMesh 在 Work 场景烘焙后复制到 Gameplay 场景；或用 Local Area Updater 加载局部后分块烘焙
  • AI 生成/追击与浮点修复：
    • 生成点：用 World Mover.Current Move 校正生成位置（本地坐标 - Current Move = 真实坐标）
    • 单人：每个 NPC 挂 Object to Move 并填 _World_Mover
    • 多人：用客户端 World Mover 的 Current Move 校正 RPC 位置

18. 性能 Tips 速查

  • 纹理流式慢/GFX wait for present：调 Quality 设置里的 Async Upload Time Slice 和 Async Upload Buffer Size；Player Settings 里可试 Virtual Texturing
  • 性能只在 Development Build + Auto-Connect Profiler 下看；编辑器里的内存访问尖峰在 build 里不存在；编辑器卡顿可临时关 Static Batching
  • 想卸纹理内存：用 Amplify / Granite / Unity 内置 Virtual Texturing，Streamer 就只负责 mesh/碰撞/Terrain，加载更快
  • 静态对象必须勾 Static（build 时大幅省流式 CPU；但用浮点修复时静态合批对象要靠自定义工具烘焙/合并）
  • Prebake Collision Meshes：最终 build 勾，加载碰撞快得多，但 build 时间变长
  • Optimize Mesh Data：仅最终 build 勾
  • Incremental GC 常开
  • 场景里的任何 error/warning 都会拖慢流式系统——清干净
  • 碰撞体尽量简单、尽量用内置基础碰撞体；烘焙碰撞加载更快
  • 单个场景太重 → 切小、加载范围放大；Terrain 用独立的第二个 Streamer；不要一次加载全部
  • 避免超大网格（mesh）导入和加载，会卡引擎
  • Terrain 的 detail/control/base/heightmap 分辨率按需调低
  • GC 尖峰（常在 GC.Mark.Dependencies）= 场景对象太多或 Terrain splatmap 太大 → 用层裁掉；也可能是 Unity/脚本内存泄漏
  • Ring Streaming 把远距 Terrain 换低模可省几百 MB 内存、消除 Terrain 持续刷新的静态 CPU；树换低模可省几千 batch
  • 树、草、大量同类对象用 GPU Instancing：一次加载、只占几 KB；超大静态合批网格加载很慢
