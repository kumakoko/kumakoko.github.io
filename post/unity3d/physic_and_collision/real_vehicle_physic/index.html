悬挂

悬挂的本质就是弹簧的伸缩。

弹簧

弹簧在不受力的状态下，会有一个恒定的长度（Rest Distance）：

当弹簧被压缩/拉伸，会产生趋向于让弹簧回归恒定长度的力：

弹簧力的大小，与偏移距离成正比：

弹簧越软，偏移相同距离所需的力就越小；弹簧越硬，力就越大。所以弹簧的强度（Strength），在车辆物理中用来控制车辆悬挂的软硬：

如果没有外力干预，弹簧会趋向于拉伸、压缩的往复运动：

车辆悬挂可不希望路过减速带后，车辆上下来回弹个没完，所以需要一个让弹簧区域稳定的东西——阻尼。

阻尼

阻尼的作用是，当弹簧做拉伸/压缩运动时，让弹簧趋向于静止。所以，阻尼产生的力，与速度有关：

当弹簧受到向右的推力时，产生的向右的速度；同时阻尼感受到向右的速度，从而产生向左的反向力。阻尼系数（Damping）越大，反向力就越大，弹簧就越快趋于静止：

弹簧会在阻尼的作用下，短时间内趋于稳定：

有了弹簧和阻尼，悬挂就有了理论基础，通过配置：

  • 弹簧恒定长度（Rest Distance）
  • 弹簧硬度（Stength）
  • 阻尼系数（Damping） 就可以实现真实的车辆悬挂的感觉。

悬挂实现的几种方式

就目前学习到的悬挂实现，有3种方式：

  • Unity内置：Wheel Collider
  • 自定义：射线检测
  • 自定义：带体积的轮胎触地检测

Unity内置：Wheel Collider

  • Spring：对应弹簧强度（Strength）
  • Damper：对应阻尼系数（Damping）
  • Target Position：对应弹簧不受力时的恒定长度（Rest Length） 额外还有Suspension Distance，用于限定弹簧偏移（Offset）的最大距离。

但Wheel Collider被普遍认为稳定性不佳，且它的实现本质跟下面的射线检测，实现逻辑是一致的。

自定义实现：射线检测

射线检测，是自定义悬挂系统实现较为常见的一种方式。其原理是：

  • 在悬挂与车体连接处，发射一条射线（Physics.Raycast）
  • 射线与地面接触，得到悬挂连接处的离地高度
  • 减去悬挂恒定长度，得到悬挂压缩/拉伸的偏移

根据偏移，计算出弹簧产生的力，将弹簧的力作用于车体的刚体（Rigidbody），以支撑车体的重量（4个轮子，4份悬挂的力，作用于4个悬挂连接处）

/// <summary>
/// 处理自定义悬挂物理逻辑，替代WheelCollider悬挂部分；
/// 使用射线检测模拟弹簧悬挂，计算弹簧力、阻尼力，施加到车体刚体上
/// 每一个车轮实例调用该函数，四个轮子分别独立计算悬挂力
/// 原理说明：
/// 1. 从悬挂车体连接点向下发射射线检测地面
/// 2. 根据射线命中距离，算出悬挂压缩量
/// 3. 根据压缩量计算弹簧弹力，再叠加阻尼力抵消上下振动速度
/// 4. 将最终悬挂力作用在车体刚体对应接触点，撑起车身重量
/// 5. 同时更新车轮视觉模型位置（tfSteer为车轮Transform）
/// </summary>
public void HandleSuspension()
{
    // 射线总长度 = 悬挂静息长度 + 悬挂可伸缩行程 + 车轮半径
    // 射线最长向下探测这么远，超过代表轮子悬空离开地面
    rayLength = config.restLength + config.travalLength + config.radius;
    
    // 射线发射原点：悬挂与车身连接点的世界坐标（车身上硬点位置）
    origin = transform.position;
    
    // 射线向下方向：当前物体自身的负Y轴（跟随车身倾斜，不是世界向下）
    down = -transform.up;
    
    // 发射射线：从origin沿down方向，最大探测距离rayLength
    // isGrounded：是否射线碰到地面；hit：射线碰撞信息结构体
    isGrounded = Physics.Raycast(origin, down, out hit, rayLength);

    // ----------------------轮子接触地面的分支----------------------
    if (isGrounded)
    {
        // 射线撞击地面的世界坐标点
        contactPoint = hit.point;
        // 地面碰撞面法线（斜面会得到倾斜法线，用于力的投影修正）
        contactNormal = hit.normal;
        // 射线原点到碰撞点的距离
        contactDistance = hit.distance;

        // 悬挂向上方向，和射线向下方向相反
        Vector3 up = -down;

        // 计算悬挂压缩量：
        // (静息悬挂长度 + 车轮半径) 是轮子完全不受力时应该有的离地距离
        // 减去实际射线距离，得到被地面顶上去多少 = 压缩值
        // Clamp限制：最小0(完全拉伸无压缩)，最大travalLength(悬挂压到底)
        float compression = Mathf.Clamp((config.restLength + config.radius) - contactDistance, 0f, config.travalLength);

        // 获取【刚体上该地面接触点】的世界空间速度（包含车身移动、旋转带来的点速度）
        Vector3 pointVel = rbCar.GetPointVelocity(contactPoint);
        
        // 提取该点沿悬挂向上方向的速度分量：正数代表轮子向上运动，负数向下运动
        float speedUp = Vector3.Dot(pointVel, up);

        // 悬挂力计算公式：弹簧力 - 阻尼力
        // compression * springStrength：弹簧弹力，压缩越大弹力越大
        // speedUp * damper：阻尼，抵消悬挂上下弹跳速度，抑制抖动
        float force = (compression * config.springStrength) - (speedUp * config.damper);
        
        // 组装力向量：力沿着悬挂向上方向推车身
        Vector3 forceVec = up * force;
        
        // 在地面接触点位置，给车身刚体施加悬挂支撑力。ForceMode.Force：持续力，受Time.deltaTime影响
        rbCar.AddForceAtPosition(forceVec, contactPoint, ForceMode.Force);

        // 将悬挂力投影到地面法线方向；斜坡地面时修正垂直地面的法向力大小
        // Dot(up, contactNormal)：悬挂向上与地面法线夹角投影；Abs保证力符号正确
        float normalProj = force * Mathf.Abs(Vector3.Dot(up, contactNormal));
        
        // 平滑插值当前法向力，避免物理帧力剧烈跳动，0.3为插值系数控制平滑程度
        curNormalForce = Mathf.Lerp(lastNormalForce, normalProj, 0.3f);
        // 保存本帧法向力，下一帧作为Lerp的旧值
        lastNormalForce = curNormalForce;

        // 更新车轮视觉模型位置：射线碰撞点往上抬一个车轮半径，就是轮子模型的中心位置
        tfSteer.position = origin + down * (contactDistance - config.radius);
    }
    // ----------------------轮子悬空，射线没有碰到地面----------------------
    else
    {
        // 没有地面碰撞点，虚拟一个理论接触点：沿向下射线走到最大理论位置
        contactPoint = origin + down * (config.restLength + config.radius);
        // 悬空时地面法线临时赋值为向下
        contactNormal = down;
        // 射线直接走到最大探测距离
        contactDistance = rayLength;
        
        // 轮子离地，法向支撑力归零
        curNormalForce = 0f;

        // 根据地面倾斜虚拟车轮伸缩；dot用来模拟悬空时车轮随姿态轻微伸缩效果
        float dot = Vector3.Dot(contactNormal, Vector3.down) / 2f;
        // 计算悬空状态下车轮视觉模型的伸缩长度
        float length = config.restLength + dot * config.travalLength;
        
        // 设置悬空时车轮模型位置，轮子向外伸出，模拟悬挂完全舒展状态
        tfSteer.position = origin + down * length;
    }
}

压缩量计算 (config.restLength + config.radius) - contactDistance
contactDistance：射线原点（悬挂硬点）到地面的距离。

restLength + radius：理想静止状态下，硬点到地面的期望距离**（悬挂不受压缩，轮子刚好贴地）。

公式含义： 实际硬点到地面距离contactDistance比理想值越小 → 地面把轮子往上顶得越多 → 悬挂压缩越大。

举例： 理想静止：restLength+radius = 1.0m 射线测出来 `contactDistance = 0.7m compression = 1.0 - 0.7 = 0.3m → 悬挂被压缩了0.3米。

如果去掉radius：基准变成硬点到轮心，拿它和【硬点到地面】做减法，压缩量直接算错，弹簧力完全错乱。

NWH: Vehicle Physics 2中的悬挂实现

VP2的悬挂实现原理是：

  • 检测轮胎触地点
  • 通过触地点，反推悬挂伸缩的长度
  • 通过悬挂伸缩长度，反推作用于车体的力

总体思路与射线检测相同，但VP2做了一些稳定性、精细化和性能方面的补充。

VP2：轮胎触地检测

触地检测分为2种精细度的检测方式：

  • 单球体碰撞检测
  • 多球体碰撞检测

一般会使用单球体检测，当单球体没有检测到碰撞，或是明确指定多球体碰撞时，再使用多球体进行碰撞检测。

public override bool WheelCast(in Vector3 origin, in Vector3 direction, in float distance, in float radius, in float width, ref WheelHit wheelHit, LayerMask layerMask)
{
    bool isValid = WheelCastSingleSphere(origin, direction, distance, radius, width, ref _castResult, layerMask);

    if (forceMulticast || !isValid)
    {
        isValid = WheelCastMultiSphere(origin, direction, distance, radius, width, ref _castResult, layerMask);
    }

    if (isValid)
    {
        wheelHit.point = _castResult.point;
        wheelHit.normal = _castResult.normal;
        wheelHit.collider = _castResult.collider;
    }

    return isValid;
}

对于绝大多数平坦路面，使用WheelCastSingleSphere就能完成检测，节省性能；在起伏较大的路面，且轮胎比较宽的车辆使用场景下（比如：越野障碍场地），使用WheelCastMultiSphere更昂贵的性能消耗算法，能达到更加真实的轮胎碰撞检测效果。

单次球体碰撞检测

由悬挂与车体接触的位置，生成一个球体碰撞，这个球体由悬挂点向下移动一定的距离，过程中与其他碰撞体发生碰撞，并记录碰撞信息。

源码如下：

private bool WheelCastSingleSphere(Vector3 origin, Vector3 direction, float distance, float radius, float width, ref RaycastHit hit, LayerMask layerMask)
{
    // Decide whether to use Raycast or SphereCast based on wheel width
    bool useRaycast = width <= 0.01f;

    int hitCount = 0;

    if (useRaycast)
    {
        // Use RaycastNonAlloc for narrow wheels
        hitCount = Physics.RaycastNonAlloc(origin, direction, _raycastHits, distance, layerMask, QueryTriggerInteraction.Ignore);
    }
    else
    {
        // Use SphereCastNonAlloc for wider wheels
        hitCount = Physics.SphereCastNonAlloc(origin, radius, direction, _spherecastHits, distance, layerMask, QueryTriggerInteraction.Ignore);
    }

    if (hitCount > 0)
    {
        float minDistance = float.MaxValue;
        RaycastHit closestHit = default(RaycastHit);
        RaycastHit[] hits = useRaycast ? _raycastHits : _spherecastHits;

        for (int i = 0; i < hitCount; i++)
        {
            var h = hits[i];

            // Ignore own colliders
            if (_wheelController.vehicleColliders.Contains(h.collider))
                continue;

            // Check if the hit point is inside the wheel's volume
            Vector3 offset = h.point - origin;
            Vector3 localOffset = _transform.InverseTransformVector(offset);
            float halfWidth = width * 0.5f;

            if (localOffset.x < -halfWidth || localOffset.x > halfWidth || localOffset.z > radius || localOffset.z < -radius)
                continue;

            // Check if this hit is closer
            if (h.distance < minDistance)
            {
                minDistance = h.distance;
                closestHit = h;
            }
        }

        if (minDistance != float.MaxValue)
        {
            hit = closestHit;
            return true;
        }
    }

    return false;
}

多球体碰撞检测

生成以轮胎宽度为直径的多个球型射线。

先让球型射线在轮胎中心的高度线上依次排列，球之间的间距刚好是球的半径：

将这几个球型射线的位置移动到轮胎的下半部分，使其均匀地分布在轮胎下半部分的 180度范围：

然后这几个球型射线由悬挂处的位置向下移动指定距离，过程中检测到的碰撞体作为轮胎与地面接触的候选碰撞体。

源码如下：

private bool WheelCastMultiSphere(Vector3 origin, Vector3 direction, float distance, float radius, float width, ref RaycastHit hit, LayerMask layerMask)
{
    float castRadius = width * 0.5f;

    // Decide whether to use Raycast or SphereCast based on wheel width
    bool useRaycast = castRadius <= 0.01f;

    int zSteps = useRaycast ? 1 : Mathf.RoundToInt((radius / castRadius) * 2f);
    zSteps = Mathf.Max(zSteps, 3); // Ensure at least 3 steps for coverage
    zSteps = zSteps % 2 == 0 ? zSteps + 1 : zSteps; // Ensure an odd number
    float stepAngle = 180f / (zSteps - 1);

    Vector3 up = _transform.up;
    Vector3 forwardOffset = _transform.forward * radius;

    Quaternion steerQuaternion = Quaternion.AngleAxis(_wheelController.SteerAngle, up);
    Quaternion xStepQuaternion = Quaternion.AngleAxis(stepAngle, _transform.right);
    Quaternion xRotationQuaternion = Quaternion.identity;

    _allHits.Clear();

    for (int z = 0; z < zSteps; z++)
    {
        Vector3 castOrigin = origin + steerQuaternion * xRotationQuaternion * forwardOffset;

        int hitCount = 0;
        RaycastHit[] hits = useRaycast ? _raycastHits : _spherecastHits;

        if (useRaycast)
        {
            // Use RaycastNonAlloc for narrow wheels
            hitCount = Physics.RaycastNonAlloc(castOrigin, direction, hits, distance, layerMask, QueryTriggerInteraction.Ignore);
        }
        else
        {
            // Use SphereCastNonAlloc for wider wheels
            hitCount = Physics.SphereCastNonAlloc(castOrigin, castRadius, direction, hits, distance, layerMask, QueryTriggerInteraction.Ignore);
        }

        for (int i = 0; i < hitCount; i++)
        {
            var h = hits[i];
            _allHits.Add(h);
        }

        xRotationQuaternion *= xStepQuaternion;
    }

    if (_allHits.Count > 0)
    {
        float minDistance = float.MaxValue;
        RaycastHit closestHit = default(RaycastHit);

        for (int i = 0; i < _allHits.Count; i++)
        {
            var currentHit = _allHits[i];

            // Ignore own colliders
            if (_wheelController.vehicleColliders.Contains(currentHit.collider))
                continue;

            // Check if the hit point is inside the wheel's volume
            Vector3 offset = currentHit.point - origin;
            Vector3 localOffset = _transform.InverseTransformVector(offset);
            float halfWidth = width * 0.5f;

            if (localOffset.x < -halfWidth || localOffset.x > halfWidth || localOffset.z > radius || localOffset.z < -radius)
                continue;

            // Check if this hit is closer
            if (currentHit.distance < minDistance)
            {
                minDistance = currentHit.distance;
                closestHit = currentHit;
            }

// 压缩
private float CalculateBumpForce(in float velocity)
{
    if (velocity < 0f) return 0f;

    float x = velocity;
    float y;
    if (x < bumpDivisionVelocity)
        y = x * slowBump;
    else
        y = bumpDivisionVelocity * slowBump + (x - bumpDivisionVelocity) * fastBump;
    return y * bumpRate;
}

// 回弹
private float CalculateReboundForce(in float velocity)
{
    if (velocity > 0f) return 0f; // We are in bump, return.

    float x = -velocity;
    float y;
    if (x < reboundDivisionVelocity)
        y = x * slowRebound;
    else
        y = reboundDivisionVelocity * slowRebound + (x - reboundDivisionVelocity) * fastRebound;
    return -y * reboundRate;
}

摩擦力

在将摩擦力之前，先提一个比较有趣的知识——外倾角。

外倾角（Camber）

顾名思义，外倾角，就是轮胎向外侧倾斜的角度。根据倾斜的角度为正、负还是零，分为：

  • 负外倾

轮胎顶部向内倾斜，呈“八”字型，常见于赛车、改装车。 因为车辆高速过弯时，车体会一定程度向外侧倾斜，此时轮胎相比静止状态，有更大的接触面积，可以提供更大的抓地力

  • 0度 两侧轮胎完全垂直于地面，常规车辆比较常见。

  • 正外倾

轮胎顶部向外倾斜，呈“V”字型，常见于重载卡车空载时的状态。 当卡车空载状态下，车桥处于自然弯曲状态，轮胎呈“V”字型向外倾斜； 当卡车重载状态下，车桥被压平，车轮成平行垂直于地面的状态，接触面变大，方便更好地承重。

综上，外倾角的大小会影响车轮与地面的基础面积，从而影响轮胎与地面接触的摩擦力。

Pacejka魔术公式（Magic Formula）

Pacejka 魔术公式（Magic Formula）是车辆动力学中描述轮胎力的圣经。虽然名为“公式”，但它其实是一个半经验模型。它不像牛顿第二定律那样，从物理基本原理推导而来，而是Hans B. Pacejka教授通过大量的轮胎实验数据，发现有一套数据公式能完美拟合几乎所有轮胎的力学特性曲线，因为拟合得太准了，却又没有完全基于物理微观结构，所以被称为“Magic Formula”。

Pacejka魔术公式中有一个很重要的概念——滑移（Slip）。

滑移（Slip）

要理解滑移，先从轮胎开始讲起。 轮胎不是刚体，它是会发生形变的。当车辆的速度发生变化，轮胎就会发生形变。

举个例子：

一辆车以10米/秒的速度向前行进，当它加速到15米/秒时，轮毂的转速会立刻增加，

靠近轮毂的轮胎部分转速贴近轮毂的转速，

而靠近地面的轮胎部分转速则依然保持在原来的速度，

如此，轮胎就会发生形变。

靠近地面的轮胎部分的速度与车辆实际的行驶速度保持一致，我们称之为“车速”；

靠近轮毂的轮胎部分的速度，我们计算为“轮胎转速 × 半径”。

所以滑移的计算公式为：

滑移率（slip）= (轮胎转速 x 半径 - 车速) / 车速

这个公式的本质，是在计算：“轮子转过的距离”与“车子实际走过的距离”之间的偏差比例。要注意，滑移（Slip）与打滑（Skid）的区分：

  • 打滑：胎面和地面发生相对位移。
  • 滑移：台面与地面保持相对静止。

滑移的“移”，“移”的是轮胎的形变，形变产生了力，推动车辆前进。

Pacejka公式

Pacekja的核心目标是描述滑移率（Slip）与摩擦力（Force）之间的关系。

Pacejka教授发现：

【轮胎类别】不论是F1赛车的热熔胎、家用轿车的四季胎，还是卡车的越野胎； 【路面条件】不论是干燥的柏油路、湿滑的水泥路，还是可能会打滑的雪地； 【受力方向】不论是纵向力（加速/刹车引起的滑移）还是横向力（转向引起的侧偏）；

它们随滑移率变化的摩擦力曲线走势完全一致，这个曲线的特征分为3个阶段：

阶段一：线性区——“抓地稳” Slip区间：0%~3% 曲线直线上升 手感：方向盘很紧，车身相应极其灵敏。你给多少输入，轮胎就给多少力。 阶段二：峰值区——“极限边缘” Slip区间：5%~15% 曲线到达最高点 手感：赛车手梦寐以求的区域。此时摩擦力最大，刹车最狠，过弯最快。但车开始有点“游离感”，因为部分轮胎橡胶开始出现滑动。 阶段三：滑动区——“失控/偏移” Slip区间：>20% 曲线过了峰值，开始下滑，然后变成一条平线。 手感：车辆彻底滑出去。此时无论怎么深踩油门或猛打方向，力都不会增加，甚至会减少（动摩擦<静摩擦上限）。这解释了：为什么刹车抱死后，反而不会马上停下来。

Pacejka教授用4个字母（B，C，D，E），3个三角函数组合出了一套数学公式，拟合了曲线的特征：

其中，变量：

-x：输入变量。对于纵向力，x是滑移率；对于横向力，x为侧偏角。 -y：输出变量。纵向摩擦力或横向摩擦力。

4个字母，是调整轮胎手感的关键：

-D（Peak Value - 峰值因子） 决定了曲线又多高。 含义：轮胎的最大抓地力。 调整：根据轮胎抓地力强弱，调整D值。 比如：普通家用车轮胎调为1.0，赛车热熔胎抓地力更强，调为1.5。

-C（Shape Factor - 形变因子） 决定了峰值附近的曲线有多“宽”。 含义：数学修正系数，通常纵向力取1.65，横向力取1.3，一般不轻易调整。

B（Stiffness Factor - 刚度因子） 决定了曲线在原点附近的斜率。 含义：轮胎的硬度。 调整：B越大，轮胎响应越灵敏，稍微打一点方向盘，力就立刻上来，比如：F1赛车的轮胎； B越小，轮胎响应越迟钝，软绵绵的，但容错率高，比如：卡车、越野车的轮胎。

-E（Curvature Factor - 曲率因子） 决定了峰值以后下降的趋势。 含义：失控后的宽容度。 调整：E较大，一旦突破极限，抓地力瞬间消失。车辆很难救回，一滑就飞。 E较小，突破极限后，抓地力稍微降低。非常适合漂移，手感顺滑。

Pacejka公式解释了两个案例：

案例一：小米汽车多事故 以较低价格，让平民开上了跑车。新手一脚油门踩到底，滑移率一下子上来，车子直接打滑。

案例二：《极限竞速：地平线》为什么用键盘玩不好？ 使用键盘玩《地平线》，驾驶法拉利F40，一按W，车辆直接原地打滑。因为键盘按下等同于油门踩死，滑移率瞬间拉满，摩擦力瞬间不足。所以玩赛车类主机游戏，推荐用线性手柄。

速度钳制 因为滑移率（Slip）的计算公式是：

滑移率 = (轮胎转速x半径-车速)/车速

如果车速为0，会导致滑移率无限大。所以在实际的逻辑计算中，需要限制车速的最小值。NWH中将车速的最小值限定在1.5~10之间：

float clampedAbsForwardSpeed = absForwardSpeed < forwardSpeedClamp ? forwardSpeedClamp : absForwardSpeed;
float invClampedAbsForwardSpeed = 1.0f / clampedAbsForwardSpeed;

这段代码有2个疑点：

为什么最小车速的计算跟帧率挂钩 为什么当前帧的时长_dt要除以0.005

  1. 为什么最小车速的计算跟帧率挂钩 我们反过来想：如果最小车速恒定为1.5，不同帧率下会发生什么？

设定一个场景：

一辆车就快停下了，当前车速为1m/s，接下来踩刹车让车速为0m/s。

情况A：高帧率（200Hz，_dt = 0.005s） 时间很短。 物理引擎算出来：“需要500N的摩擦力来刹车。” 作用时间0.005秒。 结果：车速从1m/s变为0.9m/s。很平滑，没问题。

情况B：低帧率（10Hz，_dt = 0.1s） 假设最小车速恒定为1.5m/s，算出来的Slip和摩擦力很大（比如：还是500N）。

但是！这次力作用的时间变成了0.1秒（变成了上面的20倍）。 力 × 时间 = 冲量，导致冲量相当大。 结果：巨大的刹车力作用了太久，车速不仅减为0m/s，还被反推，变成了-2m/s。 下一帧：物理引擎发现车辆在倒车，施加一个反方向的摩擦力，又用力过猛，车速变成3m/s。 最终表现：车子疯狂前后移动鬼畜。

情况C：低频率（10Hz，_dt = 0.1s）——最小车速与_dt挂钩 _dt相较于情况A扩大了20倍，于是把最小车速也扩大了20倍。 分母变大 »> 滑移率变小 »> 摩擦力也变小了（Pacejka曲线阶段一为线性区） 虽然摩擦力也变小了，但是它作用的时间为0.1秒，是情况A的20倍。 结果：小力 × 长时间 ≈ 大力 × 短时间 车辆减速为0的表现与情况A接近，不存在震荡的问题。

圆环 公式：

结构：所有质量都集中在最外圈（比如：呼啦圈、自行车轮胎）。 物理意义：因为100%的质量都在最远的地方（r处），力臂最大，所以惯性最大，最难加速。

  1. 实心圆

公式：

结构：质量均匀分布在整个圆盘上（比如：硬币、实心铁饼）。 物理意义：虽然外圈有质量，但圆心附近也有质量。圆心附近的质量最容易转动。平均下来，它的惯性只有圆环的一半。

NWH采用的是圆环公式，有如下几个考量：

汽车轮胎的质量分布更接近“圆环” 轮胎：橡胶、钢丝帘布层、胎面，这些很重的东西都在最外圈 轮毂：轮毂的“桶身”也在外圈。中间的“辐条”通常做的比较细、比较轻。 为了数值稳定性（主要原因） 惯性越大，物理状态越不容易改变，越不容易出现轮子转速一下子飙升等不稳定的情况 简化参数设计，避免通过“系数”控制惯量 如果公式是：I = k · m · r2，这个k就需要交给策划等职能去配置，会增加认知负担。 相对来说，把k预设为1是一个相对安全且保守的策略，即使因为配置者填了一个较小的质量，车子开起来也不会显得轻飘飘。

我们假设一个“大马力后驱车弹射起步”的场景，看看根据上面的逻辑会发生什么？

车况：500匹马力，1档，油门踩死。 物理现状： 轮子转动惯量 ( )：很小（轮子很轻，很容易转起来）。 引擎扭矩 ( )：巨大。 地面摩擦力极限 ( ）：也很大。 目标：轮子应该迅速从 0 加速到某个平衡点（比如空转 100 rad/s），然后稳定住。 帧率：50Hz（每帧0.02秒）

第一帧： 轮速：0 引擎：输出1000Nm扭矩 摩擦：因为轮速为0，滑移率是0，所以摩擦力，所以摩擦力为0 净扭矩：1000 - 0 = 1000Nm 第一帧-执行： wheel.angularVelocity += 1000 / I * 0.02 因为轮子惯量I很小，这1000Nm持续作用0.02秒，足以让轮子转速瞬间飙升。 结果：轮速从0直接跳到500rad/s（超级快）。 转速过头了： 实际上，轮速到了100rad/s时，摩擦力就应该介入，把轮子拉住的。因为帧率低，轮速秒涨的，轮速增长的中间过程缺少了摩擦力的作用。 第二帧： 轮速：500rad/s 引擎：还是输出1000Nm的扭矩 摩擦：Pacejka曲线检测到，“卧槽！滑移率这么大？摩擦力拉满！”，于是提供了-5000Nm的反向扭矩。 净扭矩：1000 - 5000 = -4000Nm 第二帧-执行： 这-4000Nm持续作用了0.02秒 结果：轮速从500rad/s变为-300rad/s。

循环往复，车辆弹射起步阶段，轮速在+500和-300之间剧烈跳变，车身就会出现鬼畜抖动，甚至被弹飞。

上面问题出现的核心原因在于：

帧率低，车轮转速在一帧内秒变，变化的中间过程缺少摩擦力的作用，导致变化剧烈。

对于这一问题，NWH提供了子步进的策略，把一帧拆分成20份，把扭矩也拆分成20份，分20次计算，这样每次计算车轮的转速都会受到摩擦力的作用，就不会出现车轮速度的剧变了。

  1. 未使用子步进精细化计算 纵向摩擦力，使用子步进来计算，是因为：

纵向摩擦力中，动（滚动）的对象是轮胎 轮胎的质量小，惯性就小 扭矩对轮胎的作用影响很大，导致了剧烈变化。

为了扩大使用场景，NWH加入了参数frictionCircleStrength来控制摩擦圆逻辑对横向摩擦力的影响：

摩擦圆逻辑，一定程度上也能解释生活中的一些场景：在刚下过雨的路面骑电瓶车，一般会避免急刹。
