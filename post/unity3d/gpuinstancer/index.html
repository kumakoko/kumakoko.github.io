GPU Instancer Pro 由多个称为 Manager（管理器） 的主要 MonoBehaviour 类组成。最常用的是 Prefab Manager（预制体管理器）、Detail Manager（细节管理器）和 Tree Manager（树木管理器）。这些管理器的设计以易用性为首要目标，将它们添加到场景中就像点击一个菜单项一样简单。

在本页面中，你将了解这些管理器以及 GPUI Pro 附带的一切内容——包括各种工具和组件，帮助你快速上手使用 GPUI Pro。

所有 GPU Instancer Pro 管理器的右上角都有一个问号图标。点击该图标后，管理器会在各项设置上显示说明。你随时可以点击此按钮来查看某个管理器设置的相关信息。

快速开始

Prefab Manager（预制体管理器）

使用 Prefab Manager 来渲染和管理场景中大量的预制体实例。

  • 添加 Prefab Manager：Tools -> GPU Instancer Pro -> Add Prefab Manager
  • 点击 Add 按钮。
  • 选择场景中已有大量实例、或预期会有大量实例的预制体。（参见 Instance Counts）
  • 在 Prefab Prototype Settings 中启用必要的选项。

Tree Manager（树木管理器）

使用 Tree Manager 来渲染 Unity 地形上的树木。

  • 添加 Tree Manager：Tools -> GPU Instancer Pro -> Add Tree Manager For Terrains

Detail Manager（细节管理器）

使用 Detail Manager 来渲染 Unity 地形上的细节（草、植被等）。

  • 添加 Detail Manager：Tools -> GPU Instancer Pro -> Add Detail Manager For Terrains

无 GameObject 工作流

  • 使用 RegisterRenderer API 方法创建一个新的渲染器，并保存返回的 rendererKey。
  • 使用 SetTransformBufferData API 方法，配合给定的 rendererKey 设置变换矩阵。
  • 要停止渲染，调用 DisposeRenderer API 方法。

管理器设置

通用管理器设置

以下管理器设置在每个管理器中都通用。

Dont Destroy On Load（加载时不销毁）： 启用后，加载新场景时 GPUI 管理器不会被销毁。

Default Profile（默认配置）： 新添加到管理器的原型默认使用此配置。

Revert When Disabled（禁用时还原）： 当管理器被禁用时，恢复为默认渲染。

Profile（配置）设置

与渲染相关的设置（剔除、LOD 等）存储在一个 Profile Scriptable Object 中，该配置在各原型之间共享。Profile 设置会写入持久化的 GPU 缓冲区，而不是每帧都把数据发送到 GPU。这样可以减少文件数量、简化原型的添加/移除，并优化 GPU 数据传输。

你可以点击 Profile 对象右侧的 ’+Create’ 按钮，在项目中生成一个新的 Profile Scriptable Object。或者，你也可以在 Project 窗口中右键，选择 Create -> Rendering -> GPU Instancer Pro -> Profile 来创建新的 Profile 资源。

Culling（剔除）

Is Distance Culling（启用距离剔除）： 启用距离剔除后，你可以指定最小和最大距离值。超出这些距离的对象将被剔除。

Is Frustum Culling（启用视锥剔除）： Is Frustum Culling 决定是否渲染相机视锥体外的对象。启用后，GPU Instancer 会排除视锥体外的对象不进行渲染，从而提升性能。除非有特殊原因，否则建议启用视锥剔除。

Frustum Offset（视锥偏移）： Frustum Offset 会扩大相机的视锥平面，从而影响在启用视锥剔除时渲染对象的范围。

Is Occlusion Culling（启用遮挡剔除）： Is Occlusion Culling 决定是否渲染被其他对象遮挡的对象。启用后，GPU Instancer 会跳过渲染那些位于其他对象之后、正常情况下不可见的对象。虽然遮挡剔除会增加一些额外的 GPU 操作，但在有益时建议启用。

Occlusion Offset（遮挡偏移）： Occlusion Offset 定义一个深度值（范围 0 到 1），在根据深度纹理计算被剔除对象时，差异小于该值的将被丢弃。偏移值越高，剔除越少。

Occlusion Accuracy（遮挡精度）： Occlusion Cull Accuracy 定义遮挡剔除的精度。值越高，纹理采样次数越多，剔除越精确。

1 => 5 次采样（中心点和角点）
2 => 9 次采样（增加 1/4 处的点）
3 => 17 次采样（增加 1/8 和 3/8 处的点）

Min Culling Distance（最小剔除距离）： Min. Culling Distance 定义会发生任何类型剔除的最小距离。如果该值大于 0，则与相机距离小于该值的实例不会被剔除。

Bounds Offset（包围盒偏移）： Bounds Offset 可用于增大原型的包围盒尺寸。这会影响剔除和 LOD 计算。对于使用修改顶点位置的着色器的原型尤其有用。

Calculate Instancing Bounds（计算实例化包围盒）： 启用 Calculate Instancing Bounds 后，系统会为每个原型计算包围盒，并在 CPU 上应用视锥剔除。这可以避免为不可见的实例发起不必要的 draw call。

Shadow Culling（阴影剔除）

Is Shadow Casting（启用阴影投射）： Is Shadow Casting 指定对象是否投射阴影。启用阴影投射需要额外的阴影 pass，会增加渲染操作。GPU Instancer 实现了多种技术来优化这些操作，但在不需要时禁用阴影投射可以提升性能。

Is Distance Culling（启用距离剔除）： 阴影距离剔除基于阴影投射体的位置。在阴影非常长的情况下，阴影距离剔除可能导致阴影不一致。这种情况下通常最好增大 Custom Shadow Distance（自定义阴影距离） 的值。不过如果需要，此选项允许你完全禁用阴影距离剔除。

Custom Shadow Distance（自定义阴影距离）： 当 Custom Shadow Distance 设为 0 时，GPU Instancer 将根据 Quality Settings 渲染阴影。你可以调低此设置以指定一个更小的值，从而有效地剔除远处对象的阴影。

Is Frustum Culling（启用视锥剔除）： 启用后，视锥剔除结果将应用于阴影。这会带来更好的性能，但也可能导致阴影一致性变差。

Shadow Frustum Offset（阴影视锥偏移）： Shadow Frustum Offset 会扩大相机的视锥平面，从而影响在启用视锥剔除时渲染阴影的范围。

Is Occlusion Culling（启用遮挡剔除）： 启用后，遮挡剔除结果将应用于阴影。这会带来更好的性能，但也可能导致阴影一致性变差。

Shadow Occlusion Offset（阴影遮挡偏移）： Shadow Occlusion Offset 定义一个深度值（范围 0 到 1），在根据深度纹理计算被剔除的阴影时，差异小于该值的将被丢弃。偏移值越高，阴影剔除越少。

Min Shadow Culling Distance（最小阴影剔除距离）： Min. Shadow Culling Distance 定义会发生任何类型阴影剔除的最小距离。如果该值大于 0，则与相机距离小于该值的阴影不会被剔除。

Override Shadow Layer（覆盖阴影层）： 启用 Override Shadow Layer 选项后，你可以为阴影 draw call 分配不同的层。这有助于在有多个次要光源的场景中优化光照，避免不必要的额外阴影 pass。

LOD

LOD Cross-fading（LOD 交叉淡入淡出）： LOD Cross-Fade 启用该原型各 LOD 级别之间的交叉淡入淡出混合。由于在淡入淡出期间两个 LOD 级别都会渲染，这可能对性能有轻微影响。

Animate Cross-fading（动画化交叉淡入淡出）： Animate Cross-Fading 以动画方式执行交叉淡入淡出，而不是基于距离。动画从 LOD 首次发生变化时开始。在动画期间，两个 LOD 级别都会渲染。

LOD Cross Fade Animate Speed（LOD 交叉淡入淡出动画速度）： LOD Cross Fade Animate Speed 决定不同 LOD 之间过渡的持续时间。

LOD Bias Adjustment（LOD 偏移调整）： LOD Bias Adjustment 值会影响每个原型的 LOD 级别距离。设为小于 1 的值时倾向于更少的细节；设为大于 1 的值时倾向于更多的细节。

Maximum LOD Level（最大 LOD 级别）： Maximum LOD Level 设置决定渲染时使用的最高 LOD。实际生效的 LOD 级别将取此设置与 Quality Settings 中指定的 Maximum LOD Level 之间较大者。要在整个项目范围内应用此设置，请在 Quality Settings 中调整。对于单个原型，你可以修改此 Profile 设置。

Shadow LOD Map（阴影 LOD 映射）： Shadow LOD Map 可用于调整为每个 LOD 渲染阴影时使用的细节级别。

Other（其他）

Light Probe Setting（光照探针设置）： Light Probe Setting 决定渲染系统如何使用场景中的光照探针：

Off（关闭）     —— 不使用光照探针数据。实例不会接收任何基于探针的光照。
Single（单个）  —— 所有实例共享单个环境光照探针值。以基本光照提供更好的性能。
Per Instance（逐实例）—— 为每个实例单独计算光照探针值，以性能为代价提供最精确的光照。

Per Object Motion Vectors（逐对象运动矢量）： 启用后，GPUI 会基于每个对象上一帧的变换数据计算运动矢量，但前提是 Mesh Renderer 的 Motion Vectors 设置为 ‘Per Object Motion’。如果 Motion Vectors 设为 ‘Camera Motion Only’，则无需启用此设置。

Billboard（广告牌）设置

GPU Instancer Pro 具备为预制体自动生成广告牌渲染器的能力。但请注意，广告牌系统主要是为地形树木设计的。为不使用 Unity 默认树木着色器（如 SpeedTree、TreeCreator 或 SoftOcclusion 着色器）的预制体生成广告牌可能导致意外结果。

Generate Billboard（生成广告牌）： 启用 Generate Billboard 选项后，将创建一个广告牌网格和材质，并作为最后一个 LOD 添加到原型中。

Replace LOD Culled（替换 LOD Culled 段）： 启用后，广告牌将替换 LOD Group 组件中的 Culled 段，而不是使用自定义距离值。

Billboard Distance（广告牌距离）： Billboard Distance 值类似于 LOD Group 组件上的 LOD 百分比设置。例如 0.9 的值类似于 LOD Group 组件上的 10%。

Atlas Resolution（图集分辨率）： Atlas Resolution 定义广告牌纹理的分辨率。分辨率越高，广告牌外观越好，但占用更多内存。2D 广告牌的纹理图集不是正方形；例如 “x2048” 选项会产生 2048x256 的纹理分辨率。

Frame Count（帧数）： Frame Count 定义为该广告牌从不同角度拍摄的快照总数。帧数越高，不同视角下的视角差异越精确，但由于所有帧都打包在同一个图集中，单帧分辨率会更低。

Brightness（亮度）： 你可以使用 Brightness 调整广告牌纹理的亮度。值为 0 时完全为黑色，值为 1 时更亮。

Cutoff Override（裁切覆盖）： 你可以使用 Cutoff Override 选项覆盖原始材质的 alpha 裁切值，用于广告牌纹理。如果你在该原型预制体的材质纹理中将 alpha 值用作其他数据（例如 metallic 等），通常需要此选项。

Normal Strength（法线强度）： Normal Strength 控制法线纹理效果的强度。小于 1 的值会减弱效果，大于 1 的值会增强法线纹理的效果。

Add To Billboard Assets（添加到 Billboard Assets）： 启用 Add To Billboard Assets 选项后，广告牌资源将被添加到 Runtime Settings 中的 ‘Billboard Assets’ 列表内，从而在运行时创建原型时可以发现该广告牌资源。

Statistics 选项卡

Statistics 选项卡提供 GPU Instancer 渲染信息的概览，帮助用户识别瓶颈并优化性能。

Show Visibility（显示可见性）： 启用后，GPUI 管理器将从 GPU 回读剔除结果，并显示额外信息，如顶点数和可见 LOD 数。

The Prefab Manager

通过将预制体添加到 Prefab Manager，你添加到场景中的预制体实例会自动由 GPU Instancer 渲染。它还提供运行时添加/移除/更新实例等额外功能。请注意，Prefab Manager 只接受用户创建的预制体；不接受导入 3D 模型资源时自动生成的预制体。

使用 Prefab Manager 时，最重要的是只将你拥有大量实例的预制体添加为原型。GPU Instancer 使用各种技术来提升性能，但最终它通过 GPU Instancing 来渲染其原型。因此，强烈建议阅读 Terminology（术语）和 Best Practices（最佳实践）页面，熟悉 GPU Instancing 的概念，从而充分利用 Prefab Manager 以及 GPUI 整体。

Prefab Manager 设置

Find Instances At Start（启动时查找实例）： 启用后，Prefab Manager 会在初始化时在场景中搜索 GPUIPrefab 组件。禁用后，你可以使用 Register Instances In Scene 按钮手动注册场景中的预制体实例。

Prefab Manager 原型设置

Transform Updates（变换更新）： 启用后，预制体实例的变换数据将每帧读取并上传到 GPU 缓冲区。如果预制体实例的变换数据没有变化，最好保持禁用。如果很少变化，你可以使用 GPUIPrefabManager.UpdateTransformData 方法通知 Prefab Manager 发生了变化，同时保持此设置禁用。

Auto. Add/Remove（自动添加/移除）： 启用后，GPUIPrefabAutoAddRemove 组件将被添加到预制体上。包含此组件的实例将自动添加到 Prefab Manager 或从中移除。

Optional Renderers（可选渲染器）： 通过 Optional Renderers，你可以按实例控制特定子 GameObject 渲染器的启用和禁用。

Prefab Manager 材质变体

+Create 按钮： 点击此按钮会创建一个 Material Variation Definition 资源，并将 GPUI Material Variation Instance 组件添加到预制体上。

Enable/Disable 复选框： 使用此复选框启用或禁用材质变体。

Material Variation Definition： 此字段显示 Material Variation Definition Scriptable Object。设置说明请参阅 Material Variation Definition 文档。

Remove 按钮： 点击此按钮会从预制体上移除 GPUI Material Variation Instance 组件，并可选删除 Material Variation Definition 资源。

The Detail Manager

Detail Manager 的主要目标是相对于 Unity 默认地形细节提升性能并改善视觉质量。它原生支持多个地形，最小化 draw call，并以更少的内存分配高效管理运行时变化。此外，它引入了优化功能来减少远处细节实例的数量，从而在保持视觉质量的同时提升性能。

Detail Manager 使用单通道密度纹理来渲染细节实例，这些纹理可以在运行时使用提供的 Density Modifiers 进行编辑，而不会产生 CPU 开销。用户可以在运行时动态添加和移除细节实例，从而提高地形系统的灵活性和易用性。

Detail Manager 附带的 foliage（植被）着色器为纹理类型的细节实例提供多种质量增强和自定义选项。

此外，用户可以将带有 LOD Group 组件的预制体添加到 Detail Manager 的原型中。GPUI 会将第一个 LOD 添加到地形中，以便使用地形工具进行绘制。但在渲染时，GPUI 仍将使用带有全部 LOD 级别的预制体。

Detail Manager 设置

Render In Edit Mode（编辑模式渲染）： 启用后，GPUI 管理器将在编辑模式下渲染对象。

Terrains（地形）： 此管理器当前正在渲染细节和树木实例的地形列表。

Auto. Add New Prototypes（自动添加新原型）： 启用后，当地形上存在与管理器中现有原型不匹配的原型时，将在管理器上创建新原型。

Auto. Remove Deleted Prototypes（自动移除已删除原型）： 启用后，管理器上与地形原型不匹配的原型将被自动移除。

Detail Distance（细节距离）： 决定绘制细节实例的最大距离。

Detail Update Distance（细节更新距离）： 细节实例根据相机位置更新。更新距离决定相机移动多少距离后细节实例会更新。设为 0 时，细节实例每帧都更新。

Healthy/Dry Noise Texture（健康/干枯噪声纹理）： Healthy/Dry Noise Texture 用于决定细节实例的缩放和颜色。

Detail Manager 原型设置

Mesh（网格）： 对于纹理类型的细节原型，GPUI 使用名为 ‘DefaultDetailMesh’ 的四边形网格。你可以通过为此属性分配自定义网格来更改默认四边形网格。

Materials（材质）： 对于纹理类型的细节原型，GPUI 使用带有 ‘GPUInstancerPro/Foliage’ 着色器的材质。你可以通过为此属性分配自定义材质来更改。

Material Description（材质描述）： 为了最小化纹理原型使用的材质数量，GPUI 采用 Material Property Blocks，并在不同纹理原型之间共享同一材质。‘Material Description’ 属性使用户能够通过为其着色器创建自定义材质描述，从而在自定义着色器上利用此功能。

Layer（层）： 你可以使用此下拉菜单选择纹理类型地形细节将使用的层。使用预制体的地形细节将从预制体对象获取 Layer 值。

Terrain Detail Properties（地形细节属性）： 地形细节原型设置从地形读取并在此显示，用于测试目的。对地形上的值所做的任何更改都会自动更新这些设置。

Detail 着色器属性

GPUI 使用一个自定义 foliage 着色器，该着色器使用 Standard Lighting Model 渲染纹理类型的细节属性。你也可以通过从 GPUInstancerPro/Foliage 着色器创建材质，并将该材质分配给预制体的 Mesh Renderer，从而在预制体上使用此着色器。管理器上的这些设置仅在选中纹理类型细节原型且使用默认细节材质时显示，它们可用于单独更改原型设置。

Ambient Occlusion（环境光遮蔽）： 应用于使用 foliage 着色器的对象的环境光遮蔽量。

Gradient Power（渐变强度）： GPUI 的 foliage 着色器提供了一个选项，可以使使用它的网格下部变暗。这会让植被看起来更真实。你可以用此属性设置变暗效果的量，或将滑块设为 0 完全关闭。

Wind Idle Sway（无风摆动）： 指定使用 foliage 着色器的细节原型的空闲风动画量。这是在没有风浪时发生的风动画。将滑块拉到 0 可禁用此空闲风动画。

Wind Waves On（开启风浪）： 指定使用 foliage 着色器的细节原型是否有风浪。用于计算风的法线纹理可以在材质中通过编辑 Wind Wave Normal Texture 属性来更改。

Wind Wave Size（风浪大小）： 指定使用 foliage 着色器的细节原型的风浪大小。

Wind Wave Tint（风浪染色）： 指定 Wind Wave Tint Color 对使用 foliage 着色器的细节原型风浪效果的应用程度。将滑块拉到 0 可禁用风浪着色。

Wind Wave Sway（风浪摆动）： 指定使用 foliage 着色器的细节原型由风浪施加的风动画量。这是在空闲风动画之外额外发生的风动画。将滑块拉到 0 可禁用此额外波浪动画。

Detail 密度缩减

Distance Based Density Reduction（基于距离的密度缩减）会在细节实例远离时减少其数量。它还可以增大远处对象的缩放，使它们覆盖相似的面积。

DR Start Distance（缩减起始距离）： 距离缩减从相机开始的起始距离。

DR Multiplier（缩减乘数）： DR Multiplier 值越高，移除的实例越多；值越低，移除的越少。为获得最佳性能，在不影响视觉质量的前提下应尽量设高。

DR Max Scale（最大缩放）： 远处细节实例将被缩放，以覆盖被移除实例留下的空白区域。DR Max Scale 决定最大缩放值。

DR Height Scale（高度缩放）： 设为 0 时，远处对象仅在 X 和 Z 轴上缩放。设为 1 时，Y 轴将获得与其他轴相同的缩放增量。

Detail 调整

Detail Adjustments 允许你在不修改地形数据的情况下修改细节实例的密度、缩放和位置。

Density Multiplier（密度乘数）： 通过更改 Density Adjustment 值，你可以增加或减少细节实例的密度。

Healthy/Dry Scaling（健康/干枯缩放）： Healthy/Dry Scaling 设置允许你根据 Healthy/Dry 噪声修改细节实例的缩放值。大于 0 的值会使健康实例的缩放更大；小于 0 的值会使干枯实例的缩放更大。

Noise Seed（噪声种子）： Noise Seed 调整值可用于修改细节实例随机位置和缩放值的种子。

Noise Spread Multiplier（噪声扩散乘数）： Noise Spread Multiplier 值决定用于为细节实例着色和缩放的 Healthy/Dry 噪声纹理的缩放。

高级设置

Max Instance Per Unit（每单位最大实例数）： ‘Max Instance Per Unit’ 设置基于地形上设置的 ‘Detail Resolution’ 值，决定每个索引处最多可生成的细节实例数量。

Initial Buffer Size（初始缓冲区大小）： Initial Buffer Size 用于在渲染开始时创建 GPU 缓冲区。根据计算出的实例数量，缓冲区大小会动态变化。如果初始缓冲区太小，前几帧中某些实例将不会被渲染。

Extra Buffer Percent（额外缓冲区百分比）： 在确定细节实例所需的缓冲区大小时，会进行额外分配以避免因小变化而重新分配缓冲区。此值决定分配时实际缓冲区大小中留空的百分比。

Buffer Reduction Percent（缓冲区缩减百分比）： 当已分配的缓冲区大小不足时，Detail Manager 会自动进行新分配。它还可以使用 Buffer Reduction Percent 值缩减缓冲区大小以释放内存。例如，当此值设为 0.6 时，如果 60% 的缓冲区未被使用，缓冲区将被调整大小以释放 GPU 内存。设为 0 可完全禁用缓冲区大小缩减。不建议设为非常低的值，因为频繁的内存分配可能导致性能问题。

The Tree Manager

Tree Manager 为 Unity 地形树木的实例化提供了解决方案。通过向场景添加 Tree Manager，GPUI 可以从 Unity Terrain 提取树木数据并生成必要的 GPUI 原型。此外，Tree Manager 会自动为树木原型启用广告牌，并在需要时生成广告牌。该管理器支持各种树木着色器，包括 SpeedTree、TreeCreator 以及许多自定义树木着色器。如果你想使用树木而不将其注册到 Unity 地形上，可以改用 Prefab Manager。

Tree Manager 设置

Render In Edit Mode（编辑模式渲染）： 启用后，GPUI 管理器将在编辑模式下渲染地形树木。

Terrains（地形）： 此管理器当前正在渲染细节和树木实例的地形列表。

Auto. Add New Prototypes（自动添加新原型）： 启用后，当地形上存在与管理器中现有原型不匹配的原型时，将在管理器上创建新原型。

Auto. Remove Deleted Prototypes（自动移除已删除原型）： 启用后，管理器上与地形原型不匹配的原型将被自动移除。

Tree Instance Colors（树木实例颜色）： 启用后，Tree Manager 将根据 TreeInstance 的颜色属性创建颜色变化缓冲区。合适的着色器（如 Tree Creator 着色器）可以使用此缓冲区创建颜色变化。

Tree Manager 原型设置

Apply Rotation（应用旋转）： 启用后，树木将根据 TreeInstance 的 rotation 属性进行旋转。

Apply Prefab Scale（应用预制体缩放）： 启用后，树木预制体的缩放值将应用到实例上。

Apply Height（应用高度）： 启用后，树木高度将根据 TreeInstance 的 heightScale 属性进行修改。

工具（Utilities）

GPUI Debugger 窗口

Debugger 窗口提供对 draw call 和计算着色器计算的全面洞察，辅助分析和调试。它显示用于实例化渲染的相机信息、每个相机当前渲染实例的统计数据，以及每个原型的 GPU 分配。此外，通过为每个原型选择 GPUI LOD Group Data 对象，用户可以查看 draw call 所使用的网格、材质、关键字和 LOD 设置的详细信息。

打开此窗口，请导航到：Tools -> GPU Instancer Pro -> Utilities -> Show Debugger Window

Billboard Generator 窗口

Billboard Generator 窗口是 GPUI 提供的工具，用于测试和微调系统生成广告牌的相关设置。它允许用户调整分辨率、帧数和亮度等参数，以获得广告牌渲染所需的视觉外观。有关这些设置的详细信息，请参阅 Billboard Settings 部分。

Save as Asset（保存为资源）： 此按钮将广告牌设置连同生成的纹理一起保存到一个 Scriptable Object。它允许用户在 GPUI 管理器中保留广告牌配置以供将来使用。

Save Standalone（独立保存）： 点击此按钮会创建一个网格、一个材质和一个广告牌预制体，可独立于 GPUI 管理器使用。它提供了一种将生成的广告牌作为 LOD 级别添加到其他对象或场景的方法。

Close and Return（关闭并返回）： 此按钮关闭预览场景并返回到之前的场景。

打开此窗口，请导航到：Tools -> GPU Instancer Pro -> Utilities -> Show Billboard Generator

Prefab Replacer 窗口

GPUI 包含一个 Prefab Replacer 工具，旨在通过几次点击即可将场景层级中的 GameObject 替换为预制体实例。如果你在最初创建场景时没有遵循预制体工作流，此工具特别有用。此外，它允许你轻松地将一个或多个预制体的实例替换为另一个预制体，同时保留位置、旋转和缩放等变换数据。

打开此窗口，请导航到：Tools -> GPU Instancer Pro -> Utilities -> Show Prefab Replacer

Grass Mesh Generator 窗口

GPUI 中的 Grass Mesh Generator 工具为 Detail Manager 管理的纹理类型细节原型创建自定义网格。此功能使用户能够根据特定项目需求定制草和其他纹理细节的外观。

打开此窗口，请导航到：Tools -> GPU Instancer Pro -> Utilities -> Show Grass Mesh Generator

附加组件与 Scriptable Object

GPUI Camera

你可以通过将 GPUI Camera 组件添加到每个相机来选择哪些相机用于实例化渲染。使用多个相机很简单：只需将该组件添加到每个你希望 GPUI 渲染的相机上。渲染开始时，如果没有找到带有此组件的相机，GPUI 将根据 Runtime Settings 中设置的行为自动选择一个相机。

Enable Occlusion Culling（启用遮挡剔除）： 此选项决定是否为此相机生成深度纹理，从而使用遮挡剔除功能。

HiZ Depth Texture（HiZ 深度纹理）： 此属性显示运行时用于遮挡剔除的深度纹理，有助于调试。

GPUI LOD Group Data

对于每个原型，系统会生成一个 GPUI LOD Group Data 对象，其中指定了渲染所使用的网格、材质、关键字和 LOD 过渡值。此信息对用户可访问，允许他们在运行时进行修改以用于调试和测试。

GPUI Prefab

GPUI Prefab 组件在预制体被添加到 Prefab Manager 时自动附加到预制体上。它通过维护预制体实例的实例化状态和 GPU 缓冲区信息，使 Prefab Manager 能够跟踪这些实例。

GPUI Prefab Auto Add Remove

GPUI Prefab Auto Add Remove 组件在 Prefab Manager 上启用 ‘Auto. Add/Remove’ 选项时自动附加到预制体上。它在预制体实例被添加到场景或启用时自动将其注册到 Prefab Manager，并在实例从场景移除或禁用时从 Prefab Manager 中移除。

GPUI Terrain

GPUI Terrain 组件在地形被添加到 Tree 或 Detail Manager 时自动附加到地形上。它向 GPUI 管理器提供必要的地形信息，如高度图纹理、树木实例和细节密度纹理。

Auto. Find Tree Manager（自动查找 Tree Manager）： 启用此选项后，地形将在运行时自动分配给场景中存在的 GPUI Tree Manager。

Auto. Find Detail Manager（自动查找 Detail Manager）： 启用此选项后，地形将在运行时自动分配给场景中存在的 GPUI Detail Manager。

Bake Detail Textures（烘焙细节纹理）： 此按钮将用于地形细节渲染的单通道密度纹理保存为纹理资源。它可加速 Detail Manager 初始化并减少内存分配。

Detail Material Description

为减少纹理原型所需的材质数量，GPUI 使用 Material Property Blocks，允许同一材质在不同纹理原型之间共享。‘Detail Material Description’ Scriptable Object 使用户能够通过定义着色器上哪些属性对应特定功能，在自定义着色器上利用此功能。

要创建新的 Detail Material Description，请在 Project 窗口中右键，选择：Create -> Rendering -> GPU Instancer Pro -> Detail Material Description

GPUI Event System

GPUI Event System 允许用户在相机渲染过程的不同阶段执行自定义方法。这些阶段包括：

OnPreCull： 在相机可见性计算之前执行。

OnPreRender： 在相机可见性计算之后、draw call 之前执行。

OnPostRender： 在 draw call 之后执行。

可通过以下导航将事件系统添加到场景：Tools -> GPU Instancer Pro -> Helpers -> Add Event System

Floating Origin Event（浮动原点事件）

“GPUI Event Floating Origin” 组件可以根据指定变换的移动，自动调整 GPUI Manager 管理的所有实例。请注意，这些调整仅限于存储在 GPU 内存中的矩阵数据。场景中的 GameObject 不会被修改。

Face Camera Event（面向相机事件）

“GPUI Event Face Camera” 组件可以自动调整特定原型的所有实例使其面向相机。请注意，这些调整仅限于存储在 GPU 内存中的矩阵数据。场景中的 GameObject 不会被修改。

GPUI Pro Scene View Overlay

在运行时，查看 Game 相机的剔除结果很有用，但有时你也需要在 Scene 视图中查看被 Game 相机剔除的实例。GPUI Pro Scene View Overlay 包含一个切换按钮，用于在 Culled（已剔除）和 Full（全部）渲染模式之间切换，让你在 Scene 视图中查看所有对象，包括被 Game 相机剔除的对象。

访问 Scene 视图 overlay：

  • 右键单击 Scene 选项卡，选择 Overlay Menu。
  • 从列表中选择 GPUI Pro。
  • 使用切换按钮在 Scene 相机的 Culled 和 Full 渲染模式之间切换。

GPUI Area Culler

GPUI Area Culler 支持基于碰撞体或手动定义的包围体对场景中的特定区域进行剔除。

导航到 Tools -> GPU Instancer Pro -> Utilities -> Add Area Culler 将其添加到场景。

Use Colliders（使用碰撞体）： 启用后，Area Culler 使用附加到此 GameObject 的碰撞体来应用剔除。禁用后，你可以手动指定剔除区域的 Bounds 值。

Offset（偏移）： 偏移值可用于增大或减小剔除区域的体积。

GPUI Manager Filter（管理器过滤器）： 指定剔除应应用于哪些 GPUI 管理器。留空时，剔除将影响所有 draw call。

Prototype Index Filter（原型索引过滤器）： 定义剔除将应用于指定 GPUI 管理器上的哪些原型索引。留空时，剔除将影响所有原型。

GPUI Prefab Ignore Renderers

将此组件添加到预制体的子 GameObject 上后，该 GameObject 及其子对象上的渲染器将不会被 GPUI 渲染，其 Renderer 组件也不会被 Prefab Manager 禁用。

GPUI Camera Filter

GPUI Camera Filter 组件允许将特定相机排除在 GPUI 渲染系统之外。它可用于根据相机类型、相机层或单个相机来禁用实例化渲染。

将此组件添加到场景中，然后选择你要忽略的相机类型或层，或手动将单个相机添加到忽略相机列表中。

系统设置

GPU Instancer Pro Preferences（偏好设置）

GPU Instancer Pro Preferences 包含可修改 GPUI 编辑模式下默认行为的设置。

访问偏好设置，请导航到：Edit -> Preferences -> GPU Instancer Pro

Generate Shader Variant Collection（生成着色器变体集合）： 启用后，将在 Resources 文件夹内自动生成一个 ShaderVariantCollection，其中引用 GPUI 管理器中使用的着色器。这会将 GPUI 着色器变体自动添加到你的构建中。这些着色器变体是 GPUI 在你的构建中正常工作所必需的。

Auto. Shader Conversion（自动着色器转换）： 启用后，添加到 GPUI 管理器的预制体的着色器将被自动转换以支持 GPU Instancer。

Strip DOTS Shader Variants（剥离 DOTS 着色器变体）： 从构建中排除同时包含 DOTS instancing 和 procedural instancing 关键字的着色器变体。

Strip Non Procedural Variants（剥离非过程化变体）： 启用后，对于名称中包含 ‘GPUInstancerPro’ 的着色器，构建中只包含带有 PROCEDURAL_INSTANCING_ON 关键字的变体，使其只能与间接 GPU instancing 一起使用。

Strip Motion Vector Variants（剥离运动矢量变体）： 启用后，带有 GPUI_OBJECT_MOTION_VECTOR_ON 关键字的着色器变体将从构建中排除，从而禁用此功能。

Strip Light Probe Variants（剥离光照探针变体）： 启用后，带有 GPUI_PER_INSTANCE_LIGHTPROBES_ON 关键字的着色器变体将从构建中排除，从而禁用此功能。

GPU Instancer Pro Runtime Settings（运行时设置）

GPU Instancer Pro Runtime Settings 包含可修改 GPUI 渲染系统默认行为的设置，影响所有 GPUI 管理器和原型。

要修改 Runtime Settings，请导航到：Tools -> GPU Instancer Pro -> Utilities -> Add Runtime Settings Overwrite

然后点击 GPUI Runtime Settings Overwrite 组件上的 Create 按钮来创建新的设置文件。

Occlusion Culling Condition（遮挡剔除条件）： Occlusion Culling Condition 设置可用于在整个项目范围内禁用遮挡剔除功能，避免生成深度纹理和额外的可见性计算。对于不需要遮挡剔除或遮挡剔除开销过大的项目，这可能是有益的。

Camera Selection（相机选择）： 此设置根据优先级改变相机选择行为。按优先级排序，可选项为：

  • ‘Default’（默认）=> GPUICamera 组件、MainCamera 标签
  • ‘Any’（任意）=> GPUICamera 组件、MainCamera 标签、Camera.allCameras[0]
  • ‘GPUICameraComponent’ => GPUICamera 组件

Instancing Bounds Size（实例化包围盒大小）： 定义几何体在世界空间中的包围盒。用于剔除和排序渲染的几何体。

Billboard Assets（广告牌资源）： 添加到 Billboard Assets 列表的资源在运行时创建原型时可被 GPUI 管理器发现。

GPUI Shader Bindings（着色器绑定）

Shader Bindings 资源存储原型使用 GPUI 渲染时所着色器的信息。未进行 GPUIPro 着色器设置的着色器会自动创建一个替换着色器，其信息将存储在此资源中。运行时使用此数据决定实例化渲染使用哪个着色器。

Shader Bindings 资源位于：Assets/GPUInstancerPro/Resources/GPUIShaderBindings

GPUI Shader Variant Collection（着色器变体集合）

Shader Variant Collection 资源存储原型使用 GPUI 渲染时所用的着色器变体。它确保所有必要的着色器变体都包含在你的构建中，因为 GPUI 在运行时为实例化渲染修改材质，而 Unity 的默认构建行为可能不包含所有必要变体。

Shader Variant Collection 资源位于：Assets/GPUInstancerPro/Resources/GPUIShaderVariantCollection

着色器设置指南

GPU Instancer Pro 会自动转换大多数着色器，包括使用 Amplify Shader Editor 等编辑器制作的着色器。它会跟踪更改并在需要时重新转换。但是，某些着色器（例如使用 Shader Graph 制作的）需要手动编辑。如果着色器已经兼容，GPUI 会跳过转换。下面说明如何手动编辑着色器以实现兼容。

Shader Graph 设置

要设置 Shader Graph 着色器，只需将 GPU Instancer Pro Setup 节点添加到着色器中，并将其连接到 Vertex Position 输出。

‘GPU Instancer Pro Setup’ 节点的主要功能是在着色器中加入 instancing pragma 指令并 include 必要的文件。本质上，它将输入原样复制到输出，不做任何更改。如果 Vertex Position 输出已经连接了另一个节点，你可以将该节点连接到 ‘GPU Instancer Pro Setup’ 节点的输入，然后将其输出连接到 Vertex Position。如果当前没有节点连接到 Position 输出，你可以在 Object 空间中添加一个 Position 节点，将其连接到 ‘GPU Instancer Pro Setup’ 节点的输入，然后将输出连接到 Vertex Position，如图所示。

Amplify Shader Editor 设置

要设置 Amplify Shader Editor 着色器，只需添加 GPUI Pro ASE Setup 节点。它不需要连接——其作用是 include 文件并添加所需的 pragma。

Built-in RP 着色器设置

在 Built-in Render Pipeline 中，对于所有 pass，你需要 include multi_compile_instancing 和 instancing_options procedural:setupGPUI pragma 指令。请注意，GPUInstancerSetup.hlsl 必须在 UnityCG.cginc 之后 include：

Surface Shaders（表面着色器）

...
SubShader
{
    ...
    CGPROGRAM
    #include "UnityCG.cginc"
    #include_with_pragmas "Packages/com.gurbu.gpui-pro/Runtime/Shaders/Include/GPUInstancerSetup.hlsl"
    #pragma instancing_options procedural:setupGPUI
    ...
    ENDCG
}
...

由于 surface shader 的 #pragma multi_compile_instancing 指令会自动添加到生成的代码中，你无需手动 include。但是，如果你有额外的 pass（例如 shadowcaster pass），也需要为这些 pass 添加支持（参见下面的 Vertex/fragment Shaders）。

另请注意，如果阴影显示不正确（例如阴影显示在相机位置），你可以在 surface pragma 指令中添加 addshadow 选项，让 surface shader 为你生成一个 shadow pass。这将确保 shadow pass 也为 GPUI 进行了设置。如果你没有定义 addshadow 选项，并且 surface shader 本身也没有 shadow pass，Unity 将使用定义的 fallback 着色器中的 shadow pass，而该着色器可能未为 GPUI 设置。

Vertex/fragment Shaders（顶点/片元着色器）

对于所有 pass：

...
Pass
{
    ...
    CGPROGRAM
    ...
    #include "UnityCG.cginc"
    #include_with_pragmas "Packages/com.gurbu.gpui-pro/Runtime/Shaders/Include/GPUInstancerSetup.hlsl"
    #pragma multi_compile_instancing
    #pragma instancing_options procedural:setupGPUI
    ENDCG
}
...

如果你还没有在输入结构体和顶点函数中添加 instancing 设置，也需要添加：

struct appdata_custom
{
    ...
    UNITY_VERTEX_INPUT_INSTANCE_ID
}

v2f vert (appdata_custom v)
{
    v2f o;
    UNITY_SETUP_INSTANCE_ID(v);
    ...
    return o;
}

URP 着色器设置

对于所有 pass，你需要 include multi_compile_instancing 和 instancing_options procedural:setupGPUI pragma 指令。请注意，GPUInstancerSetup.hlsl 必须在 URP include 文件之后 include：

...
Pass
{
    ...
    HLSLPROGRAM
    ...
    #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
    #include_with_pragmas "Packages/com.gurbu.gpui-pro/Runtime/Shaders/Include/GPUInstancerSetup.hlsl"
    #pragma multi_compile_instancing
    #pragma instancing_options procedural:setupGPUI
    ENDHLSL
}
...

与上面其他 vertex/fragment 着色器一样，如果你还没有在输入结构体和顶点函数中添加 instancing 设置，也需要添加。

顶点输入结构体：

struct VertexInput
{
    ...
    UNITY_VERTEX_INPUT_INSTANCE_ID
}

顶点输出结构体：

struct VertexOutput
{
    ...
    UNITY_VERTEX_INPUT_INSTANCE_ID
}

顶点函数：

VertexOutput vert (VertexInput v)
{
    VertexOutput o;
    UNITY_SETUP_INSTANCE_ID(v);
    ...
    return o;
}

片元函数：

half4 frag (VertexOutput IN)
{
    UNITY_SETUP_INSTANCE_ID(IN);
    UNITY_SETUP_STEREO_EYE_INDEX_POST_VERTEX(IN);
    ...
    return o;
}

HDRP 着色器设置

与 URP 着色器相同。对于所有 pass，你需要 include multi_compile_instancing 和 instancing_options procedural:setupGPUI pragma 指令。请注意，GPUInstancerSetup.hlsl 必须在 HDRP include 文件之后 include：

...
Pass
{
    ...
    HLSLPROGRAM
    ...
    #include "Packages/com.unity.render-pipelines.core/ShaderLibrary/Common.hlsl"
    #include "Packages/com.unity.render-pipelines.high-definition/Runtime/ShaderLibrary/ShaderVariables.hlsl"
    #include_with_pragmas "Packages/com.gurbu.gpui-pro/Runtime/Shaders/Include/GPUInstancerSetup.hlsl"
    #pragma multi_compile_instancing
    #pragma instancing_options procedural:setupGPUI
    ENDHLSL
}
...
